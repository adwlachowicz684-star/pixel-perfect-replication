# 七阶段流程：先做什么，后做什么

> **本文件只写正向步骤。** 每阶段的"不许通过的条件"见 `../audit/02-不得收工的判据.md`。

## 全景

```
S0  原版证据采集      ← 拿到能跑的原版，把表现测下来
S1  立项与基线        ← 定基线版本、定范围、定台账
S2  穷尽挖掘          ← 逐文件逐功能挖全（含 S2P/S2T/S2A/S2B/S2M 五条支线）
S3  证据与性质判定    ← 每条定性质：must-match / may-evolve / ...
S4  契约与能力包      ← 把判定落成可测契约
S5  择优设计          ← 决定"哪些整合、哪些保留、哪些重做"
S6  迁移执行          ← 按契约实现
S7  验证与验收        ← 证明完成了
```

## S0 · 原版证据采集

**做四件事：**

1. **拿到可运行的原版**，并锁定身份：构建号 · 可执行文件哈希 · 协议版本 · 热修复编号
2. **准备取证环境**：固定硬件 / 固定驱动 / 固定显示器 / 固定输入设备
3. **建取证基线**：确认原版"能跑、能测、可重复"
4. **录第一批样本**：启动、主界面、一次完整核心操作、退出

产出：`evidence/` 原始样本 + `evidence/build-identity.json`

## S1 · 立项与基线

**做四件事：**

1. 写 `ledger/project.yaml`：项目性质、目标栈、基线版本
2. 定**像素四个维度**的检查口径（视觉 / 交互 / 数据 / 行为）
3. 定**台账结构**（`assets/清单模板.md`）
4. 定**验收门槛**：像素 / 布局 / 可访问性 / 行为 四类阈值

## S2 · 穷尽挖掘

主线 `method/01-穷尽挖掘.md`，**五条支线并行**：

| 支线 | 挖什么 |
|---|---|
| `flow/S2P` | **体验参数**（数值、时序、曲线——不是功能名） |
| `flow/S2T` | 文案与全维度（含非文本：口型、BiDi、图标） |
| `flow/S2A` | 资产与资源（含导入设置、平台覆盖） |
| `flow/S2B` | BUG 与审查发现（原版的"坏味"也要记） |
| `flow/S2M` | 机器证据（能用脚本跑的都跑一遍） |

**怎么才算挖全：** 见 `../audit/01-禁令总表.md` N 域（"不能只…"）——那 64 条是历史上真实踩过的"挖了一半"清单，**挖的过程中对照看**。

## S3 · 证据与性质判定

对台账每条定**四分类**之一：

| 分类 | 含义 | 例子 |
|---|---|---|
| `must-match` | **必须等价**，偏离即 BUG | 手感、数值、碰撞、时序、关卡布局、输入响应 |
| `may-evolve` | 可演进 | 画质、特效、光照、模型精度、UI |
| `should-reinvent` | 主动用新栈特性重做 | Nanite / Lumen / GI |
| `explicit-new` | 明确新增 | 新内容、新功能 |

每条**必须带证据等级 1–8**（`references/证据等级.md`）。

## S4 · 契约与能力包

把判定落成**可测契约**：`assets/契约模板.yaml` + `assets/能力包模板.md`。

契约要能回答：**测什么、怎么测、什么值算过、差多少算不过**。

## S5 · 择优设计

三件事：

1. **整合**：原版重复实现的结构化合并（记录"合并依据"）
2. **保留**：原版值得保留的优秀设计（**别顺手"现代化"掉**）
3. **重做**：用新栈特性重做的部分（标 `should-reinvent`）

## S6 · 迁移执行

按契约实现。**每一处与原版不同的地方，当场在台账记一行**：偏离了什么、为什么、谁批的、什么时候复审。

## S7 · 验证与验收

四类阈值全测 + 视觉状态契约（`flow/S7V`）+ 门禁全跑 + 人工门禁签字。
