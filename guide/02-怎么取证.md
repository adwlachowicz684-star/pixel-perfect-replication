# 怎么取证：原版表现怎么测出来

> **取证的目的不是"知道原版有什么"，而是"拿到能证明原版是什么的证据"。**
> 后者才能拿去和复刻版逐字段比。

## 一、取证顺序（**按依赖排，不是按文件类型排**）

```
① 样本身份     构建号 · 可执行哈希 · 协议版本 · 热修复号
② 构建与依赖   编译器版本 · 依赖锁定 · 确定性构建开关
③ 输入与设备   采样率 · 轮询率 · 死区 · 力反馈设备
④ 初始状态     随机种子 · 存档 · 配置
⑤ 关键状态     逐系统状态转储
⑥ 表现层       渲染 / 音频 / 输入时序
⑦ GPU / 音频   帧捕获 · 音频总线抓取
⑧ 跨版本重复   同一样本在 30/60/120fps 各跑一遍
```

**为什么是这个顺序**（不是仪式感）：

- 没有输入时钟 → 录像**只能证明画面相似**
- 没有构建哈希 → **分不清原版补丁与旧录像**
- 没有初始状态 → 随机行为**无法复跑**

**🔑 不可并行**：同一输入流的状态日志、视频、GPU 捕获**必须同一时间原点**。

## 二、四个像素维度各测什么

| 维度 | 测什么 | 常用手段 |
|---|---|---|
| **视觉** | 像素、布局、颜色、字体、动画、状态外观 | 截图逐帧、DOM/控件树 dump、Layout Inspector |
| **交互** | 输入→响应时序、焦点、键盘/鼠标/触摸路径 | 输入注入 + 高帧录像 + 事件日志 |
| **数据** | 配置、持久化、网络协议、文件格式 | 抓包、文件 diff、注册表/配置 dump |
| **行为** | 状态机、异常路径、并发、性能曲线 | 插桩、日志、故障注入 |

## 三、取证三原则

1. **先有样本，后有结论** —— 结论从样本里读出来，不从代码里猜
2. **同一样本测三遍** —— 30 / 60 / 120fps，看是否帧率依赖
3. **原版自己当 oracle** —— 差分测试用原版输出作为期望值

## 四、常见对象的最小取证单元（**不是功能名**）

| 对象 | 最小单元 |
|---|---|
| 钓鱼 | **拉力—时间曲线** |
| 上下马 | **控制权交接帧**（旧碰撞停用 / 新碰撞启用 / 输入恢复） |
| 战斗手感 | **输入锁 → 时间锁 → 判定观察**，三步顺序不能倒 |
| 震屏 | **连续噪声 + 确定性相位**，不是随机数 |
| 待机动画 | **首次触发时间 + 变体池相位** |
| 元素连锁 | **每格元素量网格**（二进制 dump） |
| 文本 | **归一化形式 + 原字节**两套 |
| 音频事件 | **反编译工程元数据导出的有向图** |

## 五、取证产出

- `evidence/build-identity.json` —— 身份
- `evidence/<领域>/` —— 原始样本（截图、录像、dump、抓包）
- `evidence/<领域>/manifest.json` —— 清单 + 哈希
- 台账 `legacy_value` 列 —— 每条都指向一个样本

**每条台账记录必须能指回一个样本；指不回的，就是还没取证。**
