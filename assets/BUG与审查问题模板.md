# BUG / 审查问题卡模板

> 用法：挖到可疑处，**30 秒先记一张，不要当场深究**，然后继续挖。
> 分诊为"简单"的，当场补【修复方案（新版）】并修掉。

---

## 精简版（边挖边记用）

```text
B-N | 一句话描述 | 文件:行号 | 类别 B1-B5 | 严重度 P0-P3 | 状态
```

---

## 完整版（分诊与修复用）

```text
【编号】B-007
【一句话】名称校验 3 处实现不一致，新建被拒的名字能靠改名写进去
【位置】mod.rs:112 / mod.rs:308 / sys.rs:45
【类别】B3 审查发现的风险（亦属 B2，迁移侧已有）
【严重度】P1 严重（涉及数据一致性，非 [险]）
【证据等级】static-code
【证据】
  - static: mod.rs:112 内联校验（无 . / .. / 长度检查）
  - static: sys.rs:45 有 . / .. + 长度≤120 检查
  - 复现: 新建名为 ".." 的项被拒 → 改名成 ".." 成功写入

【是真 BUG 吗】真 BUG。判据：三处规则不一致必然导致绕过。
【为什么现在这么写】三处各自内联，没有统一入口（属于无意识坏味）

【灾难链】
  新建校验拒绝 ".."，改名校验不拒绝
  → 用户通过改名写入非法名字
  → 后续按名字做路径拼接时解析异常

【分诊】简单（单函数收敛，不涉并发/契约）→ 当场修
【修复方案（新版）】
  收敛为 sys::validate_name()，三处调用点统一调用：
  - 拒绝 "." / ".." / 纯点串
  - 长度 ≤ 120
  - 错误文案统一为 "名称不合法"
  ⚠️ 不改动 UI，不改动数据格式，不涉并发

【验证方式】
  - 三处调用点改为同一函数（符号计数：定义 1 引用 3）
  - 用 ".."、"a"*121 分别走新建与改名，均被拒且文案一致
  - tsc / 跨端校验无新增错误

【是行为变更吗】否 —— 修的是迁移侧回归，目标就是回到原版行为
【状态】已修 / 待修 / 决定不修 / 待确认

## 自纠偏闭环（AI 修复时必须填，防止"自报已修复"）
【attempt_budget】3                     # 尝试次数上限，超了就升级给人
【attempts】1
【根因候选】① 三处各自内联 ② 早期复制粘贴
【修改文件集合】mod.rs / sys.rs
【测试 delta】新增 2 用例（".." 与 121 字符）
【是否引入新 unknown】否
【是否新增回归】否（跨端校验无新增错误）
【人工复核结论】已复核，确为三处收敛，行为与 sys.rs 原规则一致
```

> **P0/P1 必须有关闭证明**，禁止把"agent 自报已修复"写进台账。
> 若只能微调像素/表象而不能解释行为 → **证据仍不足，不能关闭**。

## 若修的是「原版 BUG」（B1），必须补这两栏

```text
【行为变更登记】
  变更前：拖到栏内空白区时 toast("请拖到卡片上")，操作被拒
  变更后：拖到栏内空白区时执行换栏移动
  影响范围：所有跨栏拖拽场景
  批准人：<谁批准的>
  golden 标注：goldens/approved/drag-cross-drop.approved.json → intentional-change

【若决定不修】
  理由：该行为是用户当前体验的一部分，且无用户反馈要求变更
  风险：保留原行为，新版与原版一致
```

**⚠️ 不登记的 BUG 修复 = 静默改需求。**
**⚠️ 决定不修的也要写明理由**（防止以后重新挖出来当新发现）。

## 填写纪律

| 字段 | 常见偷懒 | 后果 |
|---|---|---|
| 【灾难链】 | 只写"会有问题" | 三个月后没人能判断这个改动能不能动 |
| 【是真 BUG 吗】 | 空着默认"是" | 把设计意图当 BUG 修掉（#515 类） |
| 【修复方案（新版）】 | 只写"修一下" | 简单项也拖成复杂项 |
| 【验证方式】 | 写"功能正常" | 无法确认真修好 |
| 【行为变更登记】 | 修 B1 时不填 | 静默改需求 |
| 【状态】决定不修不填理由 | 直接删 | 以后又重新挖出来当新发现 |
