# S2 · 穷尽挖掘

> **回答**：原版到底有什么？
> **立场**：不讲"什么时候可以收工"，讲"怎么保证没有遗漏"。
>
> 两套坐标系配合使用：
> - **五轮**（宏观顺序）：每轮一个主视角，结束时输出证据卡
> - **六层 × 九切角**（微观矩阵）：对每个文件逐项检查

---

## 一、五轮挖掘（宏观顺序）

每轮结束都要输出可复查的**证据卡**（`assets/证据卡模板.yaml`），不是长散文。

### 轮 1 · 清单轮：枚举一切可观察入口

枚举：可执行入口、窗口/页面、控件、菜单、快捷键、文件/注册表/配置、
网络端点、数据库表、日志、错误提示、权限调用、外部进程调用。

**不得从 README 推断；未读取的一律标记 unknown。**

```bash
# 命令 / API 清单
grep -rn 'case\s*"(\w+)"\|pub fn \w+\|@tauri::command' --include=*.rs --include=*.cs <原版src> | head -80
# 快捷键表、菜单、路由
grep -rni "KeyGesture\|shortcut\|accelerator\|MenuItem" --include=*.xaml --include=*.cs <原版src> | head -60
```

### 轮 2 · 声明轮：界面与资产承诺了什么

读 UI 声明、资源字典、schema、消息表、路由、类型与默认值。
回答"界面承诺了什么"（这是用户能看见的那部分）。

```python
# 文案（界面上有的东西必然有文案，藏不住）
re.findall(r'(Content|Text|Header|ToolTip|Watermark|Placeholder)="([^"]*[\u4e00-\u9fa5][^"]*)"', t)
# 样式资源键
re.findall(r'x:Key="(\w+)"', t)
```

**用子串双向匹配**（不是精确相等），否则漏掉一半：
```python
missing = [a for a in old_texts if not any(a in b or b in a for b in new_texts)]
```

**资产层**（视觉像素，别漏）：
```bash
find <原版> -type f \( -name "*.ico" -o -name "*.png" -o -name "*.svg" -o -name "*.ttf" \) | sort
grep -rn "Duration\|Easing\|CornerRadius\|Margin\|Padding\|#[0-9A-Fa-f]\{6\}" --include=*.xaml <原版src> | head -60
```

### 轮 3 · 运行轮：真实操作，记录可见状态 ⭐

**用原程序真实操作一遍**，记录：可见状态、文件/DB 前后变化、焦点、动画、
禁用态、提示语、可撤销性。

这一轮的证据等级最高（`runtime-verified`），
**能跑就一定要跑，不要靠读代码推断**。

### 轮 4 · 静态 / 历史轮：为什么这么写

沿调用链、事件链、数据链、线程/异步链追踪实现。

- **意图层（`//` 行内注释）是本轮最高产** —— `//` 比 `///` 值钱十倍

```bash
python3 scripts/comment_extract.py <文件>
```

- 必要时 `git blame`、查关键提交 / PR / issue 解释"为什么"
- **历史不能推翻当前可观察行为**（当前行为优先）

### 轮 5 · 反向轮：对每个字段、状态、命令构造异常

对每个字段、状态和命令构造：异常、缺失、越界、并发、权限、网络/文件失败。
寻找 try/catch、重试、回滚、降级和**隐藏边界**。

```text
边界：空集合 / 单元素 / 首尾元素 / 超长 / 超多 / 中文 / 空格 / 特殊字符 / 0 与负值
异常：中途取消 / 窗口失焦 / 进程被杀 / 磁盘满 / 文件被占用 / 权限不足 /
      鼠标捕获丢失 / 双击 / 连点 / 重入 / 并发同发 / 断网 / 超时
```

**实证收益**：拖拽 35 个机制里，5 个直接产生 bug 的全是从这一轮挖出来的
（捕获丢失、重入、坐标取半路值、源页签记录、向上以标题为基准）。

## 二、六层 × 九切角（微观矩阵）

### 六层（纵向）

| 层 | 载体 | 挖到什么 |
|---|---|---|
| L1 声明层 | 命令注册表 / API 清单 / 路由表 / 事件表 | 模块级功能 |
| L2 界面与资产层 | UI 文案、样式资源、图标/字体/颜色、动效、模板与触发器 | 交互入口 + 视觉像素 |
| L3 逻辑层 | 方法体、`///` 文档注释 | 功能说明 |
| L4 意图层 | **`//` 行内注释** | 真 bug 级细节、踩坑记录 |
| L5 实现层 | 系统调用 / 编码 / 序列化 / 第三方库用法 | "到底生不生效" |
| L6 运行与环境层 | 构建脚本、部署约定、依赖版本、权限、环境变量 | 跑不起来就全白做 |

### 九切角（横向，每个文件逐个走）

| # | 切角 | 每份文件都要问的问题 |
|---|---|---|
| A | **正向** | 这里有什么功能？清单上记了吗？ |
| B | **反向** | 当前版有而原版没有的？（对照着挖） |
| C | **边界** | 空值 / 超长 / 极端值 / 中文路径 / 路径含空格 / 单元素 / 首尾元素 会怎样？ |
| D | **异常** | 失败 / 中断 / 重入 / 断电 / 捕获丢失 / 异常退出 会怎样？ |
| E | **横向一致性** | 同名功能在不同文件行为一致吗？ |
| F | **时序** | 先后顺序、延迟、防抖、定时器、谁先谁后？ |
| G | **权限与平台** | 平台 API、权限、编码、多进程？ |
| H | **数据往返** | 读 → 改 → 写 → 再读，一致吗？会被覆盖吗？ |
| I | **可见性** | 有 UI 入口吗？有文档吗？有 config 字段吗？ |

> 切角清单详见 `../references/九切角.md`。

### 五个横向维度（跨文件整扫）

| 维度 | 为什么必须单独扫 |
|---|---|
| **数据层** | 记不住的功能一定不存在；读不出的字段迁移时被静默丢弃 |
| **并发层** | 功能测试测不出的问题 |
| **文档层** | 修复记录 = 原作者亲自记录的踩坑清单 |
| **整合层** | 决定新版该怎么组织（见 S5） |
| **时序与状态层** | "顺序错了才出事"的那一类 bug |

## 四、行级复查（挖完一轮后必做）

**精读一遍远远不够。** 复查轮要回答一个极端问题：
**这个文件的每一行，我都能解释它是干什么的吗？**

把每一行归到四类：

| 类别 | 处理 |
|---|---|
| **功能** | 已编号入账 |
| **样板** | 无需入账，但要能确认它确实是样板 |
| **死代码** | 记入清单（可能是忘接上的功能） |
| **疑问** | **必须清零**：要么查清入账，要么进 unknown 清单 |

```python
# 抽掉纯样板块后，看剩下的"实质行"是否都能对上清单条目
import re
lines = open('X.cs', encoding='utf-8', errors='replace').read().split('\n')
for i, l in enumerate(lines):
    s = l.strip()
    if not s or s.startswith('//') or s.startswith('///'): continue
    if re.match(r'^(public|private|internal)\s+\w+\s+\w+\s*\{\s*get;\s*set;\s*\}', s): continue
    if re.match(r'^(using|import)\s', s): continue
    if s in ('{', '}', '});', ');'): continue
    print(i+1, s)
```

**实证**：交互系统原本只记了 8 个条目，
行级复查 + 交互切角通读后，发现是 **35 个子机制**协同的整套系统，单轮 +83 项。

**下一步**：手工挖完后走 `S2M-机器证据.md`，用 AST 查询补正则的漏
（实证：`[^}]*` 截断导致 39 字段只抓到 33；`grep -oP "pub \w+"` 只抓到 25）。

## 七·补2：资产与资源必须整份扫一遍 ⭐

**视觉像素藏在资源里，不在逻辑里。** 功能清单上不会写图标和音效。

挖的时候顺手记（十五类见 `references/资产与资源总清单.md`）：

```
A 颜色  B 动效  C 阴影层次  D 图标  E 图片插画
F 字体  G 音效  H 光标      I 状态样式矩阵  J 尺寸布局
```

**三个必查坑**：

1. **颜色格式**：XAML `#AARRGGBB`（alpha 在前）↔ CSS `#RRGGBBAA`——**照抄变透明**
2. **ICO 是否真转**：未真正转 ICO → **改图标根本不生效**（原版 A2）
3. **任务栏图标缓存**：Windows 按固定那一刻缓存 → 需**删重建 `.lnk`**

## 七·补：体验参数必须单独过一遍 ⭐

**功能挖完了 ≠ 参数挖完了。** 功能决定"能不能用"，参数决定"用起来像不像"。

挖的时候顺手记下这些（它们**不在任何功能清单上**）：

| 类别 | 边挖边记什么 |
|---|---|
| **时序** ⭐最易丢 | tips 延迟、防抖、节流、轮询间隔、自动关闭、重试退避 |
| **阈值** ⭐最易丢 | 拖拽死区、滚动阈值、最小位移、容差、双击/长按判定 |
| 尺寸间距 | Margin / Padding / Width / Gap |
| 动画 | 时长**与缓动曲线**（不只时长） |
| 颜色 / 字体 / 层级 | 具体数值，含 hover / 禁用 / 按下态 |

**可以不照搬，但必须知道搬前是什么样** —— 原值那一栏不许空。

挖完后集中走 `S2P-体验参数提取.md` 做双侧差集（脚本会直接列出"新版里根本没有的参数"）。

**⚠️ 一条必须人看的**：XAML 的 Margin 是「左,上,右,下」，CSS 是「上 右 下 左」——
数值集合一样也不等价，**别直接抄**。

## 六、三种"看不见的功能"

| 类型 | 特征 | 实证 |
|---|---|---|
| **A. 看起来是 bug，其实是通路** | 被 `toast('请拖到...')`/`return false` 挡住的正经功能 | #101 跨栏拖到空白 = 换栏移动 |
| **B. 藏在非主干文件的独立入口** | 独立 Dialog / 小 Service，不在命令清单里 | #15 建链选名字（`LinkPickDialog`） |
| **C. 没有 UI，只在代码生效** | config 有字段、后端读了，界面无入口 | #49 目录设置整页；#591-593 创建预设三个目录 |

**类型 C 检测法**：
```
设置项无 + config 字段也无 → 正常缺口
设置项无 + config 字段有   → 类型 C（高优先级，用户只能手改 JSON）
设置项有 + config 字段无   → 硬编码，不可持久化
```

## 七、数据层专项（最容易丢东西的地方）

### 7.1 config 字段双向差集

```bash
python3 scripts/config_field_diff.py --old <原版Config.cs> --new <新版model.rs>
```

**踩过的坑**：用 `grep -oP "pub \w+"` 只抓到 25 个，**实际 39 个**
（带 `Option<...>` 的字段抓不全）。**必须按大括号配对截取。**

**语义合并检测**（比字段缺失更隐蔽）：
字段数对得上 ≠ 语义等价。实证：原版有**两层**锁定
（`locked` 账面固定 / `folderLock.items[]` 系统 ACL），
当前合并成一层 `locks` → **"仅账面固定"这一档消失**。

### 7.2 读真实数据文件 ⭐

**代码只读它认识的部分。读不出的差异，代码里永远看不见。**

```bash
python3 -c "
import json
d = json.load(open('<真实数据>/link-record.json'))
print('顶层键:', list(d.keys()))
print('首条字段:', list(d['links'][0].keys()))
"
```

**实证**：原版真实数据有 `clusters` + 每条的 `cluster` 字段，
当前 `LinkRow` 完全没有，全库 grep 零命中 →
**用户拿原版数据迁移时，`clusters` 被静默丢弃、写回时永久删除**。

读原版代码看不出、读当前代码也看不出，**只有打开真实数据文件才会暴露**。

### 7.3 文档层：修复记录 = 踩坑清单

```bash
find <原版> -name "*.md" | xargs grep -l "修复\|方案\|记录\|ERRATA\|注意事项"
```

实证：A1-A9（P0 阻断）、B1-B15（P1 严重）、C1-C17、D3-D9、V10。
对照后确认当前缺失 5 项（A2 图标未真转 ICO、B3 高 DPI、C12 退出无兜底落盘等）。

**陷阱**：使用说明可能是**旧版遗留**，描述的功能当前版本根本没有。
**必须逐条 grep 代码验证再计入**（实证：TipsPanel 描述 3 个不存在的功能，已作废并记理由）。

## 七·补：边挖边记 BUG（不要当场深究）

**挖掘和修 BUG 是同一件事的两面。**
读到一段代码觉得"这里不对"，那往往正是最重要的发现——
实证：拖拽 35 个机制里，5 个直接产生 bug 的全是这样挖出来的。

**动作顺序（关键是不要打断挖掘主线）**：

```
1. 30 秒记一张 B-N 卡（精简版即可）      → 不深究
2. 继续挖当前文件
3. 回头分诊：真 BUG？简单还是复杂？
   简单 → 当场补【修复方案（新版）】+ 立刻修 + 打勾
   复杂 → 进批次，继续挖
```

**简单项五条判据（全满足才当场修）**：
单个函数/文件内 · 不涉并发/数据格式/契约 · 有明确验证方式 · 不需要重构 · 不打断主线

**⚠️ 修原版 BUG = 有意行为变更**，必须登记（原版 BUG 也是用户体验的一部分）。

详见 `S2B-BUG与审查发现.md`、模板 `../assets/BUG与审查问题模板.md`。

| 台账没清零 | 按档位继续，**不许跳档**；优先中等文件 |

| 清单说有、实际没有 | 核实后作废条目并**记下理由**（防止以后重新挖出来当新发现） |
| 挖到 BUG 但判不出是不是真 BUG | 记 B5 进 unknown，**不许默认当 BUG 修**（#515 类） |
| BUG 需要重构才能修 | 不许当场做 → 记 I-N，跟着重写一起做 |
