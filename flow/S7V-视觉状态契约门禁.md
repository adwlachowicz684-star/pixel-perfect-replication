# S7V · 视觉状态契约门禁

> **为什么单独立一张卡**：我们原先的视觉验收是"原版与新版并排走同一流程，比截图与文案"。
> 这只能证明**一次肉眼观察**，不能证明：状态被锁定、差异可复现、批准有依据。
>
> 视觉复刻不是"看起来接近"，而是**同一用户状态、同一交互阶段、同一视口、
> 同一时间语义下的渲染契约**。

---

## 一、视觉状态 ≠ 页面截图

一个功能对应**若干视觉状态**，不是一张图：

```
空态 / 首屏 / 加载完成 / 加载中 / 错误态 / 禁用态 / hover / 按下 / 焦点 /
键盘焦点环 / 长内容 / 溢出 / 拖拽中 / 弹窗蒙层 / 右键菜单 / 暗色 /
强制颜色 / 缩减动画 / 高 DPI / 打印
```

**实证教训**：图标改了不生效、高 DPI 截图错位、动效时长不一致——
这些都不是"页面长什么样"能覆盖的。

---

## 二、闭环：状态清单 → 稳定化 → 双引擎 → 分层阈值 → 逐张审批

```
visual_state.yaml  （每个状态一张）
      ↓
scripts/visual_capture.py   装夹具、锁环境、等状态稳定、截图 → .received
      ↓
scripts/visual_diff.py      pixel（像素）+ layout（结构）双引擎 → diff + 包围盒
      ↓
scripts/visual_approve.py   只能逐张创建决策卡，**禁止 bulk approve**
      ↓
.approved 入库（附 reviewer + 偏差说明 + 性质判定）
```

**工具选型（按场景，不是互相替代）**：

| 场景 | 选择 |
|---|---|
| 统一执行器（推荐首选） | **Playwright**：锁 viewport、DPR、缩放、字体、locale/timezone、theme、reduced-motion |
| 组件隔离 | **Loki**（Storybook 视觉回归） |
| 历史报告与跨构建 | **reg-suit** |
| 多人审查 / 多浏览器 / CI | Argos、Chromatic、Happo（SaaS，注意隐私与留存治理） |
| 像素比较原语 | **pixelmatch**（抗锯齿检测、感知色差） |
| 图像分析 | Resemble.js |

**先本地 Playwright + pixelmatch，不急着接商业平台。**

---

## 三、稳定化：不稳定元素必须逐类处理，不能用大阈值糊过去 ⭐

| 不稳定源 | 处理方式 | ❌ 禁止 |
|---|---|---|
| 字体渲染 / 抗锯齿 | 固定字体版本、固定渲染环境、Docker 镜像、字体预加载、统一 hinting | 调大阈值 |
| 动画 / 轮播 / 骨架屏 | 禁用动画配置、等稳定终态、或确定性替身 | `sleep(1000)` |
| 光标 / 选择态 / 滚动条 | 隐藏或固定输入 | 遮罩掉整个容器 |
| 时间戳 / 相对时间 / 随机 ID | **固定时钟**、fixture、mock | 用大阈值吸收 |
| 头像 / 第三方 widget | fixture 或局部遮罩 | — |
| WebGL / 图表动画 / 视频封面 | 单测渲染配置与帧，**不用截图替代** | — |

**遮罩纪律**：只遮"明确不属于该视觉契约"的区域，并在证据卡写明遮蔽范围。
**如果一项功能的核心体验就是头像或倒计时，遮罩会破坏复刻目标** —— 此时必须换 fixture，不得屏蔽。

---

## 四、阈值分层（不是单一全局阈值）⭐

| 类别 | 阈值 | 理由 |
|---|---|---|
| 核心图标、像素标尺、图表轴、精确对齐项 | **0 差异** | 这些就是"像素级"的字面含义 |
| 普通组件 | 按证据定 | 需写明为什么 |
| 动画、时间戳、头像 | **遮罩 / fixture**，不给阈值 | 给阈值 = 默许漂移 |

**⚠️ pixelmatch 的 `threshold`（0-1，默认 0.1）与 `includeAA` 是库级参数，
不等于项目质量阈值。** 项目应定义**状态级阈值**，写在 `visual_state.yaml` 里。

---

## 五、审批纪律（本卡最容易出事的地方）

`.approved` 入库必须包含：

- [ ] 状态 ID 唯一
- [ ] 原端证据链接
- [ ] 目标端截图哈希
- [ ] 差异图 + 逐像素/结构报告
- [ ] **reviewer 签字**
- [ ] 与原设计的偏差说明
- [ ] 性质判定（preserve / replace / merge / remove / defer）
- [ ] 关联功能卡 ID

**只有三类可被接受**：

1. 原端有意变更（有批准的行为变更登记）
2. 目标端等价
3. 目标端择优**且有证据**

其他一律 reject，**并回写 BUG 卡**。

**禁止**：

- ❌ 自动 approve（含 AI 自动 approve）
- ❌ 自动夜间 rebase baseline
- ❌ 接受未命名整体变化
- ❌ 直接删除历史基线（至少保留一个可回溯 tag，仅供 diff 调试）

> **AI agent 只能读取差异、定位代码、提出修复、重新运行；
> 批准决策卡上签字的必须是人。**

## 六、明确不吸收的流行做法

| 流行做法 | 为什么冲突 |
|---|---|
| 视觉 diff 通过 = 像素级复刻完成 | 忽略了交互、时序、键盘、可访问性、打印、性能、系统原生控件 |
| **自动更新 baseline 让 AI 快速收敛** | 把目标从"复刻旧体验"改成"让新实现通过" |
| 单一百分比阈值统一衡量所有 UI | 图标和动画不能同一个标准 |
| 只做页面截图不做组件隔离 | 组件受父布局污染，差异无法定位 |
| 托管平台"无差异"当作跨平台证据 | 需另行规定旧平台与目标平台的比较边界 |
| 随机快照测试替代视觉契约 | 快照不稳定 = 人人都在重录 |

## 六·补2：状态清单要挂原版基线签名（S0 产出）

```yaml
original_baseline:
  baseline_id: editor__main__hover_save__zh-CN_150_dark__0001
  capture_method: printwindow      # printwindow | bitblt | render_target_bitmap | client_crop
  determinism: wait-stable         # wait-stable | non_deterministic
  ui_tree_id: uia/editor__main__hover_save.json
  mask_id: masks/settings.yaml
  allowed_deviation: 0.000
```

**⚠️ 基线签名缺失或截图环境变化 → 门禁必须拒绝"通过"。**
这不是功能通过，而是**证据失效**。

由此形成一条清晰规则：

> 像素差为零**只能**证明两个图像相近，**不能**证明语义等价；
> 但像素差显著而控件树完全一致时，也**不能**轻易归结为
> "前端无关紧要的渲染差异"。

两者要结合 `ui_tree_id` 一起判。

## 六·补：视觉状态 = 布局 + 参数，两个都要比

**只比截图不够** —— 截图能看出"位置不对"，看不出"tips 晚了 200ms"。

视觉状态契约应包含两组比对：

| 组 | 内容 | 手段 |
|---|---|---|
| **布局/外观** | 位置、尺寸、颜色、层级 | 双引擎 diff（pixel + layout） |
| **体验参数** ⭐ | 时序、阈值、动画曲线 | `param_extract.py --compare` + P-N 卡 |
| **资产资源** ⭐ | 图标、字体、音效、插画、光标 | `asset_inventory.py` + AS-N 卡 |

**实证**：新版里 `showdelay / interval / debounce / duration / dragthreshold` 全部为 0 命中——
截图上完全看不出来（静态截图里 tooltip 根本没弹），但用户体验已经变了。

**所以**：
- 涉及**时序**的状态（tips、自动关闭、防抖）→ 必须有 P-N 卡，不能只靠截图
- 涉及**阈值**的交互（拖拽死区、滚动触发）→ 必须有 P-N 卡 + 差分测试
- 截图只负责"长什么样"，参数负责"节奏与手感"

## 七、产物

| 文件 | 内容 |
|---|---|
| `visual/states/*.yaml` | 每个视觉状态一张（模板见 `../assets/视觉状态契约模板.yaml`） |
| `visual/received/*.png` | 目标端截图（**不入库**） |
| `visual/approved/*.png` | 批准基线（入库） |
| `visual/decisions/*.md` | 逐张决策卡（含 reviewer 与偏差说明） |

## 八、门禁

- [ ] 每个视觉相关功能都有状态清单（不是一张页面截图）
- [ ] 不稳定元素已按类处理（不是靠大阈值）
- [ ] 阈值按状态分层定义并写明理由
- [ ] 每张 `.approved` 都有对应决策卡与 reviewer
- [ ] 无 bulk approve 记录
- [ ] 像素差异已与结构差异交叉验证（**两者都不通过才算真差异**）
- [ ] **体验参数已比对**（涉及时序/阈值的状态必须有 P-N 卡，不能只靠截图）
- [ ] **每个状态挂了原版基线签名**（`original_baseline.baseline_id`），无签名视为证据失效
- [ ] 动效时序已比对或在容差内（`motion_check.py --compare`）

## 九、不通过怎么办

| 情况 | 处置 |
|---|---|
| 差异图看着"差不多" | **不许放行**，记成新条目（同功能缺口的处理方式） |
| 总是不稳定 | 回到稳定化：查是哪一类不稳定源，**不许靠调阈值** |
| 需要遮罩但遮的是核心体验 | 换 fixture，不许遮 |
| AI 提议自动 approve | 拒绝；这是把复刻目标改成"让测试通过" |
