# S0 · 原版证据采集

> **为什么必须单独立一张卡**：现在的工具链能证明新版"做成了什么"，
> 却**难以稳定证明原版"本来是什么"**。
>
> 对像素级复刻而言，**原版不是待描述的需求，而是唯一可信的测量基准**。
> 基准本身不可复现，后面的契约、择优、验收就全部失去共同标尺。

---

## 一、位置

```
S1 立项与基线 ──► S0 原版证据采集 ──► S2 穷尽挖掘 ──► …
```

**在 S1 之后、S2 之前。** 先把原版变成可测量对象，再谈挖掘。

## 二、两类链路：控制端 / 侵入式

| 链路 | 环境 | 用途 | 标记 |
|---|---|---|---|
| **控制端** | 独立机器或虚拟机，通过 UIA 驱动被测程序 | 常规截图、控件树、事件录制 | 默认 |
| **侵入式** | 附加调试器、注入、挂起线程、读内存、TTD | 内存、堆栈、线程级证据 | **`invasive=true`** |

**⚠️ 侵入式动作会显著改变时序、JIT、布局和异常行为** ——
必须单独标记，**不能与常规截图基线混放**，否则会把"调试器扰动后的程序"误当成原版常态。

被测端只装必要运行库与取证探针，**不装开发工具链**。

## 三、五类证据（每个状态至少这些）

| 证据 | 采集项 | 首选工具 | 置信等级 |
|---|---|---|---|
| **视觉** | 固定窗口矩形、缩放、DPI、主题、截图时刻 | PrintWindow / WPF `RenderTargetBitmap` | **A** 可复现截图 |
| **结构** | AutomationId、Name、ControlType、模式、边界矩形 | **FlaUI**、FlaUInspect | **A** 稳定标识 |
| **资源** | 图标、光标、图片、字符串、颜色、字体 | ILSpy / `pefile` / .NET 资源读取器 | **B** 反编译产物 |
| **行为** | 输入事件、响应时间、异常、日志 | FlaUI、ProcMon | **B** 依赖可触发性 |
| **运行时** | 配置路径、注册表、进程、网络、文件 | ProcMon、注册表导出 | **C** 环境与权限相关 |

**证据目录 `original_capture/` 必须只读哈希保护** —— 避免"改了证据而不自知"。

**证据身份**：`state_id = <模块>__<视图>__<状态>__<变体>__<序号>`
例：`editor__mainwindow__hover_savebutton__zh-CN_150_dark__0001`

**挂到 `unknown` 项后，未知不再是"没有查到"，而是"有 state_id 但证据等级不足"** ——
穷尽门禁从文本覆盖升级为**状态覆盖**。

## 四、原版驱动：FlaUI 主干 + pywinauto 交叉验证

```bash
python3 scripts/original_capture.py --pid <pid> --out original_capture/ --tree --shot
```

**FlaUI**（MIT，封装 Microsoft UIA，支持 WPF/WinForms/Win32）应作**主驱动**，
价值在"**控件身份 + 模式 + 等待**"，而不是坐标点击。

**pywinauto**（Python 侧 `uia` 后端）作**对照**：
- 主采集用 FlaUI，pywinauto 对同一窗口做交叉验证
- 二者不一致 → 标记 **`tree_conflict`**，**优先人工复核，不自动选边**

**WinAppDriver** 只保留为 Selenium/Appium 团队兼容层 —— 依赖 Windows 10+、开发者模式与驱动服务，对复杂 WPF 自定义控件覆盖不如直接 UIA。**没有 Appium 存量就不该为"协议熟悉"而引入。**

### 定位策略必须写成稳定优先级

```
1. AutomationProperties.AutomationId / 显式自动化标识
2. 稳定业务文本（排除动态序号、时间戳）
3. 控件类型 + 稳定祖先路径
4. 可访问名称 / 键盘助记符
5. x:Name（仅在可由 XAML/反编译确认且运行时映射可信时）
6. 坐标 ← 只能用于画框、截图、验证布局，**不得作为点击定位的唯一依据**
```

**任何 `x:Name` 定位都要附反编译/XAML 来源**；`ClassName` 只能作消歧特征，不可单独使用。

**坐标点击与"体验细节不能丢"直接冲突** —— 纯坐标脚本必然脆弱，只能作最后兜底。

### 字段清单（每次抓取至少这些）

`automation_id` / `xaml_name` 候选 / `control_type` / `localized_control_type` /
`name` / `help_text` / `access_key` / `is_enabled` / `is_offscreen` /
`is_keyboard_focusable` / `has_keyboard_focus` / `bounding_rectangle` /
`patterns` / `runtime_id` / `process_id` / `parent_id`

**三者都缺失的元素才进 `unknown`；只有图像可见而树中不可见**，
应判断是离屏 / 未实现 UIA 提供程序 / 透明覆盖层 / 自绘内容 ——
这能把"像素存在但语义缺失"转化为明确的修复项。

## 五、确定性截图：三种原语分层，不能互相冒充

| 原语 | 特点 | 用途 |
|---|---|---|
| **PrintWindow** | 窗口把自身绘制到目标 DC，最接近"窗口自述" | **视觉主基线** |
| **BitBlt** | 拷设备上下文，受遮挡、阴影、DWM 合成、透明影响 | "屏幕实际呈现"对照 |
| **WPF `RenderTargetBitmap`** | 进程内渲染指定 `Visual`，绕开遮挡，设备无关 | 模板/资源校验 |

**客户区裁剪**作布局基线。**三者都要留。**

### 必须固定的环境项（写进契约，不是留在测试员脑子里）

```
显示器编号与主屏 / 显示缩放 / DPI 感知模式 / 窗口最大化or恢复 / 边框 /
阴影 / 透明 / 多显示器布局 / 主题与配色 / 字体平滑 / 动画状态 / 光标 /
输入法候选框 / 任务栏遮挡 / 截图时刻 / 窗口激活状态
```

**对持续动画**：按固定时长、固定帧号或事件后延迟采样，
**不把任意时间点的单帧当作唯一基线**。
原版若无法关闭动画 → 记 `non_deterministic` + 设多个帧阈值，**而不是无限扩充基线**。

### 图像指标：视觉近似与技术近似分开

- 纯色、线条、图标、字体边缘 → **像素比对**更敏感
- 动画、抗锯齿、渲染差异 → **结构化指标**更稳

同时计算：pixelmatch 严格像素差 + SSIM + MSE + 最大单像素误差 + 差异面积占比 + 显著差异簇；
再用 UIA 边界矩形**分区**（标题栏/客户区/状态栏/弹出层分别比）。

**遮罩必须记录** —— 避免把真实位移悄悄抹掉。

## 六、源码不全时：反编译与资源考古（源码不全才启用）

| 工具 | 用途 |
|---|---|
| **ILSpy / ilspycmd** | .NET 主考古器（批量导出，可写进台账任务） |
| **BAML/XAML 导出** | 与 C# 反编译**并行**——只看代码会丢掉布局结构 |
| **Mono.Cecil** | 遍历 IL、类型引用、属性、特性 |
| **`pefile`** | 列出 PE 资源目录 |
| **`System.Resources.ResourceReader`** | 读 `.resources` |

**资源逐层提取并保留原始字节**，不能只保存"已理解的内容"：
PE 资源目录 → 图标/光标/位图/对话框/菜单/字符串表/版本/manifest → `.resources` → `.resx` 键级比对

- **图标光标**不只提 PNG：还要尺寸、位深、**热点**、分辨率
- **字体**：原始文件、嵌入方式、子集、**许可声明**
- **颜色**不只 RGB：来源主题、状态、透明度

**二进制差异**：.NET 优先做 **IL/元数据级 diff**，不是 PE 字节 diff
（编译选项、签名、时间戳、段对齐变化后语义可能仍一致）。
`radiff2` 只用于判断"安装包是否变化"，**不用于解释功能**。

**⚠️ 资源台账默认结论是"未确认"，不是"不存在"。**

## 七、⚠️ 法律与授权边界（必读）

> **反编译、内存读取、第三方资产复制只适用于团队合法拥有、有权分析并用于授权迁移的目标。**
> 不构成对任何第三方许可、著作权或反规避限制的放宽。

执行前由项目负责人确认：合同 / 开源许可证 / 字体 EULA / 二进制组件许可 /
数据隐私 / 调试授权。

**遇到加密、数字版权管理、许可证校验**：`ownership: self`（自有项目）时**不受此限，直接继续**；
仅 `third_party` 时停止确认 ——
不许通过内存扫描、补丁或注入绕过。

## 十、不通过怎么办

| 情况 | 处置 |
|---|---|
| 原版跑不起来 | **最高优先级阻塞** —— 没有基准就无法谈像素级；先解决可运行性 |
| 拿不到 AutomationId | 按优先级降级定位；实为权宜控件则记入 S5 择优项 |
| 动画关不掉 | 记 `non_deterministic` + 多帧阈值，**不许无限扩基线** |
| 截图总是不一致 | 回到环境固定表逐项查，**不许调阈值** |
| 源码不全 | 走反编译链（§六），但先确认**授权合法** |
| 反编译结果存疑 | 标 B 级证据（反编译产物），**不许当源码原文用** |
