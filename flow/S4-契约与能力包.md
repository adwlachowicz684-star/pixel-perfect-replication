# S4 · 契约与能力包

> **回答**：跨端会不会漂移？按什么粒度迁移？每步怎么回滚？
>
> **两个核心机制**：
> 1. **契约文件化** —— 让脚本能机械检查，而不是让模型"检查是否一致"
> 2. **能力包切分** —— 按用户可观察能力切，不按文件目录切

---

## 一、为什么需要契约层

跨端契约**天然分散在多个文件里**：

```
Rust 命令定义（mod.rs / xxx.rs）
      ↓ 必须同名
Rust 命令注册（main.rs invoke_handler）
      ↓ 必须同名同参
前端调用（api.ts）
      ↓ 字段必须对应
前端类型（types.ts）
```

| 漏改 | 运行时表现 | 误导性 |
|---|---|---|
| 没注册 | `command not found` | 低 |
| 参数名不符 | **静默传 undefined**，Rust 拿到默认值 | **高** —— 功能"时好时坏" |
| Option 与非 Option 搞反 | 前端不传 → Rust 反序列化失败 | 中 |
| DTO 少字段 | 前端读到 undefined，或**保存时被静默丢弃** | **极高** —— 数据丢失 |

**实证**：`FpxConfig` 漏 `chainActions` 字段 →
整份 config 回传时缺失，serde 走 default 得到 null，
后端判定"尚未迁移"并用内置值重置，**用户自己加的连锁动作全没了**。

## 二、四类检查（C1-C4）

| # | 检查 | 抓什么 |
|---|---|---|
| **C1** | 命令存在性 | 定义了没注册 / 注册了没定义 / 前端调用了不存在的命令 |
| **C2** | 参数名一致性 | 前端传的参数名 ≠ Rust 参数名（含命名风格映射） |
| **C3** | 必填/可选匹配 | Rust 非 `Option` 的参数，前端没传 |
| **C4** | DTO 字段一致性 | `model.rs` 字段 ≠ `types.ts` interface 字段 |

```bash
node scripts/cross-end-check.mjs --strict
```

**C2 关键**：Rust 与 TS 命名风格不同，比对前先映射。
约定 `rename_all = "snake_case"` 时前端也写 snake_case，两边按原名比最不易错。
**排除注入参数**（`app: AppHandle`、`state: State<...>` 不是前端传的），否则每个命令都误报。

**C3 注意**：Rust 侧 `Option` 但前端必传是可以的；反过来不行。**只查一个方向。**

**C4 例外配置**：
```js
STRUCT_ALIAS  = { ChainActionItem: 'ChainAction' }   // 改名过，不是错误
INTERNAL_ONLY = new Set(['LinkRecord'])              // 内部用，报提示不报错
```

### 五个必踩的坑

| 坑 | 后果 |
|---|---|
| `[^}]*` 提前截断 | `FpxConfig` 39 字段只抓到 33，漏的正是出过 bug 的 `chain_actions` |
| 对象字面量简写属性 `{ kind, path }` | 只匹配 `(\w+)\s*:` 会漏 |
| `pub async fn` 漏匹配 | 4 个 async 命令全漏，表现为"前端调了不存在的命令" |
| 命令/DTO 分散在多文件 | 必须用文件列表逐个读，`try/catch` 跳过不存在的文件 |
| 脚本"永远绿灯" | **必须故障注入验证** |

## 三、契约文件化（脚本可读）

不要只在脑子里比对，落成 YAML：

```yaml
command: document.save
source: legacy/DocCommands.cs:73
target: src/commands/save.ts:31
arguments:
  - { name: path, type: string, nullable: false, legacyEncoding: utf16-le }
  - { name: overwrite, type: boolean, default: false }
result:
  type: union
  variants: [ok, validation-error, io-error, permission-error]
sideEffects: [write-file, add-history, emit-saved-event]
idempotency: same-path-replay-must-not-create-duplicate-history
faults:
  - disk-full
  - locked-file
  - invalid-utf16
  - missing-parent-dir
  - concurrent-save
```

模板见 `../assets/契约模板.yaml`。
脚本检查：目标是否存在、名称与参数是否一一对应、DTO 字段是否丢失、
错误变体是否完整。

## 三·补：兼容性判官（PR 里的 breaking 门禁）

| 工具 | 适用 | 作用 |
|---|---|---|
| **Specmatic** | 有 OpenAPI 的目标端 HTTP | 用 OpenAPI 作契约测试，验证 provider 符合性 |
| **oasdiff** | API 变更 | 把每个变更映射为严重度/路径/行号/审查动作；**过去有效的请求现在被拒绝 = breaking** |
| **Buf** | 有 protobuf | FILE/PACKAGE/WIRE_JSON/WIRE 四级严格度 |
| **Pact** | 前后端消费者驱动 | 前端录制期望 → provider 验证 |

**纪律**：
- 不要从零编新 schema 当原端契约 —— 以原端抓包、旧接口文档、S2 机器证据共同生成**旧契约基线**
- PR 出现 breaking 必须**显式 accept/reject**，并关联迁移策略与回滚方案
- **没有 protobuf 就不要为用 Buf 引入中间格式**（可为工具改架构是本末倒置）

## 四、能力包切分（迁移粒度）⭐

**按"用户可观察能力"切，不按文件目录或文件大小切。**

| 字段 | 必填内容 |
|---|---|
| Capability ID | `CAP-<domain>-<NNN>`，贯穿挖掘、迁移、验证 |
| User-visible outcome | 用户能观察的状态变化（防止实现替代需求） |
| Legacy surface | 窗口/菜单/快捷键/API/文件格式 |
| Command/event seam | 名称、参数、结果、失败模式 |
| Data shape | DTO、单位、精度、空值、默认值 |
| Legacy evidence set | 输入、录制/日志、输出、覆盖率 |
| Modern seam | 命令注册、调用、错误处理 |
| Release gate | flag / 路由 / 双写 / 回读策略 |
| Residual risk | unknown、动态、环境、平台项 |

模板见 `../assets/能力包模板.md`。

### 迁移顺序（每步都可回滚）

```
1. 建立可执行原版与基线              （S1）
2. 建立命令 / 事件 / DTO 契约         （S4）
3. 先实现无副作用查询                 （只读，最安全）
4. 再实现带审计的变更命令
5. 最后迁移副作用 / 文件 / 平台能力
```

**禁止一次性翻译全库。** 每个提交后系统仍可部署、仍可回滚。

### 整栈迁移时"接缝"在哪

WPF → Tauri + React 这种整栈迁移，难以让两套 UI 同时渲染。
**真正的接缝是稳定的用户能力与命令边界**（文件打开、保存、导入、校验、预览、撤销），
不是"两套界面并存"。

每步可回滚手段：`feature flag` / 路由 / 双写 / 回读。
**验证未通过立即回退，不得继续"补功能"。**

**双契约窗口优于直接双写生产流量**：用 feature flag 控制读旧/读新、影子写入、结果对比、
限定租户灰度，而不是默认全量双写（工具：OpenFeature 规范、Unleash、Flagsmith、GrowthBook）。

**每个 flag 必须关联**：功能卡、契约、回滚步骤、**过期日期与删除任务**。
**不许用"实验性 flag"长期隐藏一个未验证的迁移。**

**Branch by Abstraction 比 Strangler Fig 更贴近桌面端**：
先抽象原命令/端口 → 新实现适配端口 → 移除旧适配。
Strangler 更适合 HTTP 边界，**不宜硬套到所有 IPC**。

## 五、故障注入（写完校验脚本必做）⭐

**脚本第一次跑就"全绿"时，要怀疑脚本是死的。**

| 故障 | 注入方式 | 期望报错 |
|---|---|---|
| F1 参数名写错 | `{ new_name: newName }` → `{ newName }` | `[参数名不符]` + `[必传参数缺失]` |
| F2 DTO 少字段 | 删掉 `linkedGroup: string \| null;` | `[DTO 字段缺失]` |
| F3 新增必传参数 | Rust 加 `force_rebuild: bool` | `[必传参数缺失]` |
| F4 命令未注册 | main.rs 删掉 `fpx::fpx_copy_text,` | `[注册缺失]` |

```bash
# 1. 先备份
cp api.ts /tmp/api.bak && cp types.ts /tmp/types.bak
# 2. 注入 → 跑脚本 → 确认报错 → 还原
sed -i 's/xxx/yyy/' api.ts && node scripts/cross-end-check.mjs | grep "❌"
cp /tmp/api.bak api.ts
# 3. 最后确认还原
git status --short      # 应该只剩新增的脚本文件
```

**注意**：先用 `grep -n` 看字段真实写法再删。
实证里按 `linkedGroup?: string;` 去删，实际是 `linkedGroup: string | null;`，
sed 没匹配上，差点冤枉了正确的脚本。

## 六、门禁

- [ ] `cross-end-check.mjs --strict` 全绿
- [ ] 故障注入四类全部命中
- [ ] 每个能力包有 CAP ID、可见结果、接缝、回滚策略
- [ ] 每个能力包至少一个异常路径录制
- [ ] 契约 YAML 已入库，覆盖所有跨端命令与 DTO
- [ ] CI 已接入（`--strict` 有错退出码 1，放在最前面快速失败）

## 七、不通过怎么办

| 情况 | 处置 |
|---|---|
| 校验脚本全绿但没做过故障注入 | **视为未验证**，先做故障注入 |
| 契约漂移 | 回到 S3 判断是有意变更还是回归；**有意变更必须写进台账并批准** |
| 能力包切不出来 | 说明还没找到用户可观察边界，回到 S2 补运行证据 |
| 无法回滚的改动 | 拆包或加 flag，**不允许不可回滚的迁移步骤进入 S6** |
