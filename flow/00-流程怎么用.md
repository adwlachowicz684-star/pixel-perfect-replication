# 00 · 流程怎么用

> 本文件是**操作手册**：谁在什么时候读什么、产出什么文件、门禁怎么跑。
> 理念与铁律见 `../SKILL.md`，方法论细节见 `../method/`。

---

## 一、产物流（逐级引用 ID，不靠对话记忆）

```
manifest.md             ← S1：项目事实、路径、两边体量、环境
    ↓
ledger/files.csv        ← S1：全量文件台账（S2 持续更新到清零）
ledger/features.md      ← S2：功能缺口清单（1-N，编号固定）
ledger/bugs.md          ← S2/S2B：BUG 与审查问题清单（B-N，简单项当场修）
ledger/findings.json    ← S2M：机器查询命中（file/range/rule_id/confidence）
ledger/parse-status.csv ← S2M：每个文件是否可解析（解析失败不许自动关闭 unknown）
ledger/params.md        ← S2P：体验参数清单（P-N：原值/新版值/差异理由/性质）
ledger/params-old.csv   ← S2P：原版体验参数提取结果
ledger/params-new.csv   ← S2P：新版体验参数提取结果（与 old 做差集）
ledger/assets.md        ← S2A：资产与资源清单（AS-N：图标/字体/音效/色板…）
ledger/assets-old.csv   ← S2A：原版资源清点（含孤儿/悬空/许可标记）
ledger/texts.md         ← S2T：文案清单（WD-C1-N：不许"重写得更清楚"）
ledger/dimensions.md    ← S2T：全维度清单（WD-C2…C12-N）
ledger/texts-old.csv    ← S2T：原版文案提取（与 new 做差集，识别疑似改写）
ledger/evidence/*.yaml  ← S2/S3：证据卡（每条证据可追溯到文件行号）
ledger/unknown.md       ← S2/S3：unknown 清单（阻塞项，必须清零）
ledger/nature.md        ← S3：性质判定 + 动作标签（preserve/replace/merge/remove/defer）
    ↓
contracts/*.yaml        ← S4：命令 / 事件 / DTO / 错误契约
plans/CAP-*.md          ← S4：能力包计划（含接缝、回滚、release gate）
    ↓
plans/integration.md    ← S5：整合机会表 I-N、保留清单 G-N、勿删清单
    ↓
源码 + 小批 commit      ← S6
    ↓
goldens/*.approved      ← S7：批准的行为基线
visual/states/*.yaml    ← S7V：视觉状态契约（一个状态一张，不是一页一张）
visual/received/*.png   ← S7V：目标端截图（**不入库**）
visual/approved/*       ← S7V：批准基线（入库，须有 reviewer 签字）
visual/decisions/*.md   ← S7V：逐张决策卡
reviews/*.md            ← S7：验收报告
```

**规则**：下游只能引用上游的 ID，不允许把上游内容"总结"一遍当输入。
摘要适合给人看，**不适合作为下一阶段的唯一输入**。

---

## 二、阶段卡结构（每个阶段都按这五段读）

| 段 | 含义 |
|---|---|
| **输入** | 上一阶段必须已经存在的文件 |
| **动作** | 具体做什么（分层 × 切角 × 逐文件） |
| **产物** | 落到哪个文件、什么格式 |
| **门禁** | 可脚本化或可人工核验的通过条件 |
| **不通过怎么办** | 阻塞时的处置，**不允许绕过** |

## 四、脚本清单

| 脚本 | 作用 | 关键陷阱 |
|---|---|---|
| `ledger.py` | 全量入账 / 未读 diff / 按档位列出 / 清零率统计 | 必须按档位走完，不许只按行数倒序 |
| `coverage_gate.py` | 统计发现项 / 已验证项 / unknown，unknown>0 退出码 1 | 阻塞收工的唯一硬指标 |
| `renumber_check.py` | 编号重复与缺号自检 | 索引里要写 `\| 123 \|` 而非 `#123` |
| `brace_check.py` | 括号平衡（含 Rust lifetime 陷阱） | `'a` 不是 char 字面量 |
| `comment_extract.py` | 提取 `//` 行内注释并标注所属方法 | `//` 比 `///` 值钱十倍 |
| `config_field_diff.py` | 大括号配对截结构体 + 命名归一化 + 双向差集 | grep 单行会漏掉带泛型的字段 |
| `cross-end-check.mjs` | 命令存在性 / 参数名 / 必填可选 / DTO 四类检查 | `[^}]*` 会提前截断 |
| `bug_triage.py` | BUG 分诊统计与门禁：P0/P1 未处置阻塞、B5 存疑阻塞、简单项未修警告、B1 未登记行为变更警告 | B5 未确认等同 unknown |
| `tree_sitter_parse.py` | 全量源码可解析性扫描（S2M L1）；无 tree-sitter 时降级粗判并标 low | 解析失败不许自动关闭 unknown |
| `ast_query.py` | AST 精确查询（S2M L2）；ast-grep 缺失时**如实降级**并标 low，绝不静默跳过 | ⚠️ `which sg` 会命中 Unix 的 set-group 命令，已做身份校验 |
| `visual_check.py` | 视觉状态契约校验（S7V）：必锁项、遮罩 reason、阈值 reason、语义等待、审批签字、bulk approve 检测 | 只校验契约，**不做截图** |
| `param_extract.py` | 体验参数提取 + 双侧差集（S2P）：时序/阈值/尺寸/动画/颜色/字体/层级 | ⚠️ XAML「左上右下」vs CSS「上右下左」，顺序不能照抄 |
| `asset_inventory.py` | 资产清点（S2A）：资源清单 + **孤儿资源** + **悬空引用** + 许可待确认列表 | 孤儿**不许默认当残留**（动态路径 grep 不到） |
| `text_extract.py` | 文案提取 + 差集（S2T）：XAML 属性 / 提示调用 / CJK 字面量，识别**疑似改写** | 用序列相似度而非字符集合（同义词替换集合法会漏） |
| `original_capture.py` | 原版取证（S0）：控件树 + 三原语截图 + 环境契约；环境未固定**阻塞采集** | 非 Windows 时如实降级为"待人工采集"，不假装成功 |
| `license_gate.py` | 许可四态门禁（L 类）：允许/受限/证据不足/不适用；后两者**阻断交付** | 字体需逐项确认嵌入/再分发/子集/Web 托管 |

| `feature_matrix.py` | 功能对照表：五类处置校验 + 与台账双向对账 | 「需讨论」缺四栏阻断；`✅/❌`却标完成是危险组合 |
| `env_lock.py` | 环境锁 15 项（渲染敏感 7 项）；**不一致直接 FAIL** | `unknown` ≠ 已锁定；弱版本不要求 bit-for-bit |

## 五、最小可行启动（第一次接入一个新项目）

```bash
# 1. 建工作区
# 0. 【最先做】原版证据采集 —— 原版是唯一可信的测量基准，不是待描述的需求
python3 scripts/original_capture.py --init work/original_capture/
#    填 MANIFEST.json 的全部环境字段（不填就采集会被阻塞）
python3 scripts/original_capture.py --env                  # 看环境契约与定位优先级
python3 scripts/original_capture.py --pid <pid> --out work/original_capture/ --tree --shot
mkdir -p work/{ledger,contracts,goldens,plans,reviews}

# 2. 建立双向基线 + 全量台账
find <原版src> -type f | sort > work/ledger/all.txt
python3 scripts/ledger.py --init --src <原版src> --ledger work/ledger/files.csv

# 3. 跑一次门禁，看初始覆盖率（此时 unknown 应等于发现项）
python3 scripts/coverage_gate.py work/ledger/unknown.md work/ledger/features.md
# → 必然不通过。这是正确的起点，不是失败。

# 4. 挖的同时建 BUG 清单（挖到可疑处先记卡，别当场深究）
python3 scripts/bug_triage.py work/ledger/bugs.md

# 5. 机器证据（正则容易漏，用 AST 补）
python3 scripts/ast_query.py --check                                  # 先确认工具是真 ast-grep
python3 scripts/tree_sitter_parse.py --src <原版src> --ext .cs        # 机器能不能读懂
python3 scripts/ast_query.py --rules rules/sg --src <src> --out work/ledger/findings.json

# 6. 资产与资源清点（图标/字体/音效/色板 —— 像素藏在资源里，不在逻辑里）
python3 scripts/asset_inventory.py --src <原版资源> --code <原版代码> --out work/ledger/assets-old.csv --gate
python3 scripts/asset_inventory.py --src <原版资源> --code <原版代码> --out work/ledger/assets-old.csv --list-license

# 7. 文案差集（不许"重写得更清楚" —— 用户肌肉记忆认的是原句）
python3 scripts/text_extract.py --src <原版> --out work/ledger/texts-old.csv
python3 scripts/text_extract.py --src <新版> --out work/ledger/texts-new.csv
python3 scripts/text_extract.py --compare --old work/ledger/texts-old.csv \
                                           --new work/ledger/texts-new.csv --gate

# 8. 体验参数双侧差集（tips 延迟/间距/动画/阈值 —— 不记录就会丢失）
python3 scripts/param_extract.py --src <原版src> --out work/ledger/params-old.csv
python3 scripts/param_extract.py --src <新版src> --out work/ledger/params-new.csv
python3 scripts/param_extract.py --compare --old work/ledger/params-old.csv \
                                            --new work/ledger/params-new.csv --gate

# 9. 视觉状态契约（一个状态一张，不是一页一张）
python3 scripts/visual_check.py --init --states work/visual/states --feature "#1" --name <功能>.<状态>
python3 scripts/visual_check.py --states work/visual/states --approved work/visual/approved --gate

# 每次提交都跑一次全部门禁（结果写进版本库）
python3 scripts/run_all_gates.py --work work/ --strict
python3 scripts/run_all_gates.py --list          # 只看清单不执行

# 11. 按 flow/S1 → **S0** → S2 → S2M → S2A → S2P → S2T → S2B → S3 → S4 → S5 → S6 → S7(+S7V) 推进，每阶段重跑门禁
```

## 六、常见跑偏与纠正

| 跑偏 | 表现 | 纠正 |
|---|---|---|
| 跳过 S1 直接挖 | 挖到一半发现原版跑不起来，很多行为只能猜 | 回到 S1，先把原版跑起来 |
| 只按行数倒序选文件 | 大文件看完就说挖完了 | `ledger.py --by-band` 逐档清零（中等文件最肥） |
| 把 README/使用说明当事实 | 照着不存在的旧功能做了一遍 | 逐条 grep 代码验证，不通过的作废并记理由 |
| 边迁移边清理 | 历史行为静默消失 | 先锁行为（golden），再按批准接缝改写 |
| 模型自述"已对齐" | 没有 golden diff 与契约检查支撑 | 一律以门禁脚本输出为准 |
| 并行多 agent 各写各的 | 同一文件互相覆盖 | 按能力包/文件路径加锁，一次只有一个实现者 |
| 挖到 BUG 当场深究 | 台账推进停滞，主线断了 | **先记卡 30 秒，继续挖**；简单项回头补方案并修 |
| 把设计意图当 BUG 修 | 体验被"优化"掉（#515 类） | 先判性质；判不出 → B5 进 unknown，不许默认当 BUG 修 |
| 修原版 BUG 不登记 | 静默改需求，golden 对不上 | B1 类必须写【行为变更登记】并走 golden 批准 |
| 借修 BUG 顺手重构 | 同时面对"功能缺失"和"重构回归" | 简单项只改 BUG；需重构的记 I-N，跟着重写一起做 |
| 信工具的"通过" | 自动 approve / 单一阈值让门禁悄悄失效 | **工具只产生证据，不批准变更**；阈值按状态分层，决策卡必须人签 |
| 工具没装却显示成功 | 永远 0 命中的假绿灯 | 脚本做了身份校验（`which sg` 会命中 Unix 的 set-group 命令）；不可用必须如实报告 |
| 用全局阈值衡量所有 UI | 图标和动画同一个标准 | 阈值写在状态清单里，且必须写 `threshold_reason` |
| 不稳定就调大阈值 | 视觉漂移被默许 | 逐类处理（时钟/字体/动画/DPR），不许靠阈值糊 |
| 热度模型判定"不用迁" | 低星旧模块被跳过 | CodeScene 等只决定**挖掘顺序**，不决定完整性 |
| 只挖功能不挖参数 | 功能全对但手感全变，用户"说不出哪里不对" | 走 `S2P`，`param_extract.py --compare` 直接列出丢了哪些 |
| Margin 数值照抄 | XAML「左上右下」抄成 CSS「上右下左」，四向错位 | 脚本会提示"顺序约定不同"，但仍需人工换算 |
| 参数差异理由写"优化" | 说不清为什么改，三个月后没人敢动 | 说不清就按原值，或进 unknown |
| tips/防抖类参数没记 | 静态截图根本看不出来，但体验已变 | 时序与阈值类**必须有 P-N 卡**，不能只靠截图 |
| 只挖功能不挖资源 | 图标/字体/音效整类丢失 | 走 `S2A`，十五类逐类打勾，`asset_inventory.py` 扫文件 |
| 颜色值照抄 | XAML `#AARRGGBB` 抄成 CSS → **变透明** | 逐个换算，不能复制粘贴 |
| 图标文件在就算完成 | 未真正转 ICO → **改图标根本不生效**（原版 A2） | 必须实测"改了是否真的生效" |
| 孤儿资源默认当残留 | 动态拼接路径 grep 不到，实为在用 | **先迁着**并标"待确认"，不许默认不迁 |
| 字体/音效许可没查 | 仅 `third_party` 有影响 | `--list-license` 逐条列出；**`self` 时不阻断** |
| 文案"重写得更清楚" | 用户肌肉记忆认原句，换了措辞=换了入口 | `text_extract.py` 识别疑似改写；要么补回要么登记 |
| 只测正常路径 | 崩溃恢复、部分失败、焦点陷阱全漏 | 走 `S2T` 六个必须实测（含**强杀进程**、**拔鼠标**） |
| 旧数据"跑通了"就放行 | 字段被静默丢弃，数据永久丢失 | 逐字段比对（实证 `clusters` 字段就这么丢的） |
| 跳过原版取证直接挖新版 | 基准不可复现，后面全部失去共同标尺 | **先做 S0** —— 原版不是需求，是测量基准 |
| 用坐标点击驱动原版 | WPF 视觉树多装饰层，坐标必然脆弱 | 按稳定优先级定位，坐标只能画框/截图 |
| 只截一张全屏当基线 | 受遮挡/DWM/透明影响，无法定位差异 | 三原语都要：PrintWindow/BitBlt/RenderTargetBitmap |
| 截图环境不固定 | 像素门禁把环境噪声误判为功能回退 | 环境契约 11 项全填才能采集（脚本会阻塞） |
| 反编译结果当源码 | 是 B 级证据，会丢布局与注释 | 标 B 级；**先确认授权合法** |
| 拿不到证据就标"已解决" | 用新版默认实践掩盖真实缺口 | 缺口如实写进报告，不许补成"已解决" |
