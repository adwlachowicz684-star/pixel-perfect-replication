# S1 · 立项与基线

> **回答**：两边体量多少？原版能跑起来吗？基线怎么冻结？
> **为什么必须先做**：挖到一半才发现原版跑不起来，大量行为只能靠猜——
> 而 assumption 级证据**不得成为迁移决定**（见 `../references/证据等级.md`）。

---

## 一、输入

- 原版工程路径、新版工程路径
- 原版运行环境说明（OS、运行时版本、依赖、必需的外部程序）

## 二、动作

### 1. 建立双向基线

```bash
find <原版src> -type f | wc -l
find <原版src> -type f \( -name "*.cs" -o -name "*.xaml" \) | xargs wc -l | sort -rn | head -60
# 新版同样统计，记下体量比
```

```bash
# 行数分布（判断工作量与盲区档位）
find <原版src> -type f \( -name "*.cs" -o -name "*.xaml" \) | xargs wc -l \
  | awk '{ if ($1>500) a++; else if ($1>150) b++; else if ($1>60) c++; else if ($1>0) d++ }
         END { print "大>500:", a, "中上150-500:", b, "中等60-150:", c, "小<=60:", d }'
```

### 2. 让原版真的跑起来 ⭐

**这是 S1 的核心交付，不能跳过。** 只有能跑，才有 runtime 级证据。

| 检查项 | 做法 |
|---|---|
| 能否构建 | 完整走一遍构建流程，记录耗时与坑 |
| 能否启动 | 启动一次，确认无阻断级报错 |
| 数据目录在哪 | 找到真实数据文件位置（后面 S2 要用） |
| 有没有日志 | 打开日志，确认能看到关键操作 |
| 外部依赖 | 依赖的第三方程序 / 服务 / 权限 |
| 多入口 | **重点**：是否有独立进程入口（见下方实证） |

**实证教训**：原版注释写"所有写入者都在同一进程内"，
查入口代码才发现 `--mcp` 是同一 exe 的**独立进程实例**。
**不要信注释里的架构假设，去查入口代码。**

```bash
# 查所有入口（以 Rust main 为例）
grep -n "std::env::args\|::args()\|--" <原版src>/main.rs | head -40
```

### 3. 建全量文件台账

```bash
python3 scripts/ledger.py --init --src <原版src> --ledger ledger/files.csv
python3 scripts/ledger.py --unread --src <原版src> --ledger ledger/files.csv
```

台账字段：`路径 | 行数 | 档位 | 粗读 | 精读 | 复查 | 产出项数 | 疑问行 | 状态`
状态机：`未读 → 粗读 → 精读 → 复查 → 清零`，**只有「清零」算完成**。

### 4. 冻结 golden 环境（为 S7 准备）⭐

**迁移前先锁定现状**，否则后面无法判定"变了没有"。

```
goldens/
├── env.md              原版版本、OS、分辨率/DPI、locale、时区、依赖版本
├── inputs/             可复现的输入样本（真实数据文件，脱敏后入库）
├── raw/                原版实际输出（原始录制，不做任何规范化）
└── approved/           规范化 + 人工批准后的基线（.approved 入库）
```

**三类基线都要建**：

| 基线 | 内容 |
|---|---|
| **输入契约基线** | 命令名、参数顺序/可选性、单位、编码、空值、默认值、幂等键 |
| **可见行为基线** | 相同输入下原版的实际输出、文件字节、DB 行、日志、错误提示、UI 状态 |
| **业务不变量基线** | 总数守恒、状态机合法迁移、权限隔离、乱序/重复消息安全 |

**规范化规则**：时间、UUID、PID、内存地址、路径、随机数、locale 必须 scrub。
**`.received` 不入库，`.approved` 入库；golden 只能由运行结果生成，不允许手编。**

### 5. 写 manifest

```markdown
# manifest
- 原版：<路径> / <版本> / <构建命令> / <启动命令>
- 新版：<路径> / <技术栈> / <构建命令> / <校验命令>
- 体量比：原版 N 文件 M 行 / 新版 X 文件 Y 行
- 真实数据位置：<路径>
- 多进程入口：<有/无>，证据：<main.rs:行号>
- 门禁命令：<逐条列出，可直接复制运行>
```

## 三、产物

| 文件 | 内容 |
|---|---|
| `manifest.md` | 项目事实、路径、命令、环境 |
| `ledger/files.csv` | 全量文件台账（初始全为「未读」） |
| `goldens/env.md` | golden 环境说明 |
| `goldens/raw/`、`goldens/approved/` | 初始行为基线 |

## 四、门禁

- [ ] 原版能构建、能启动、能操作（**不能跑就直接阻塞**）
- [ ] 台账已建，条目数 = 原版文件数
- [ ] 多进程入口已确认（有/无都有证据）
- [ ] golden 环境已记录，至少 1 条真实输入样本入库
- [ ] manifest 里的门禁命令可直接复制运行

## 五、不通过怎么办

| 情况 | 处置 |
|---|---|
| 原版跑不起来 | **不要靠读代码猜行为**。先修环境；实在跑不起来，把所有无法 runtime 验证的项标为 `unknown` 并写明"环境受限"，这些项在 S7 会一直阻塞 |
| 找不到真实数据文件 | 从代码里 grep 数据路径常量，或启动一次让程序生成默认数据 |
| 依赖缺失 | 记录缺失项与影响范围，进 unknown 清单 |
