# S7 · 验证与验收

> **回答**：真的对齐了吗？
> **核心立场**：**测试通过 ≠ 等价。** 测试可能漏路径，golden 可能被手改，断言可能被削弱。
> 需 golden 比对、契约检查、故障注入、mutation 与像素比对交叉验证。

---

## 一、四类 oracle（不能互相替代）

| 类型 | 回答什么问题 | 手段 |
|---|---|---|
| **输入契约** | 命令名、参数顺序/可选性、单位、编码、空值、默认值、幂等键 | schema + property test |
| **可见行为** | 相同输入下原版/新版的实际输出、文件字节、DB 行、日志、错误提示、UI 状态 | golden 比对 |
| **业务不变量** | 总数守恒、状态机合法迁移、权限隔离、乱序/重复消息安全 | property / fuzz |
| **视觉状态契约** ⭐ | 同一用户状态下渲染是否一致 | 状态化截图 + 像素/结构双引擎（见 `S7V`） |

### 等价性三层（证明"测试不是装饰"）

| 层 | 回答的问题 | 工具 |
|---|---|---|
| **差分 oracle** | 新旧在同一输入下是否一致（**不让新实现自己证明自己**） | 自研 harness（模板见 `../assets/等价性三层模板.yaml`） |
| **属性不变量** | 任意合法输入下不变量是否成立 | fast-check / proptest / Hypothesis / schemathesis |
| **mutation 审计** | 小错误是否会让等价性证据失败 | StrykerJS / mutmut / cargo-mutants |

**差分 oracle 的四类结果**：语义相同（可关闭）/ 允许择优不同（可关闭，须有 S5 证据）/
未覆盖（补输入，**不许关闭**）/ **冲突（必须进 S5 重判）**。

原端已不能运行时，可用旧录制、日志、DB 快照、视频帧形成证据链，
但**必须标为历史证据，不能伪装成实时 oracle**。

**mutation 纪律**：不把工具默认分数直接设成 G 门禁；
关键功能包内"等价性突变存活数 = 0"；
**mutation 覆盖 100% 不代表视觉等价**，必须与视觉状态契约并用。

## 二、Golden 规范

```
goldens/
├── raw/          原版实际输出（不做任何规范化）
├── received/     新版输出（不入库）
└── approved/     规范化 + 人工批准后的基线（入库）
```

**硬规则**：

| 规则 | 理由 |
|---|---|
| **`.received` 不入库，`.approved` 入库** | 防止未审查的输出混进基线 |
| **golden 只能由运行结果生成，不允许手编** | 手编的 golden 等于没有验证 |
| **任何 diff 必须被解释为"有意行为变化"或"回归"** | 不能默默放行 |
| **golden 变化必须有批准人、原因、影响范围** | 可追溯 |
| **禁止 bulk re-record** | 批量重录 = 把回归全部抹平 |

**规范化（scrub）**：时间、UUID、PID、内存地址、路径、随机数、locale 必须规范化。
没有可冻结输出时，改用结构化字段比较。

### 这套规范直接抵御 AI 的三种典型偏差

1. 把历史 bug 悄悄"修复"
2. 删除阻碍通过的旧测试
3. 把职责扩到请求之外

## 三、Mutation 验证（测试是不是真的能发现问题）

**覆盖率不等于有效性。** 主动破坏实现，确认测试会失败：

```bash
# 例：故意改错一个边界判断，跑测试，必须红
sed -i 's/if (depth < 0)/if (false)/' src/x.rs && npm test   # 期望：失败
```

测试仍然绿 = 测试是死的，补用例。

## 四、像素比对（本 Skill 特有）

**功能对了 ≠ 体验对了。** 逐维度比对：

| 维度 | 比对项 |
|---|---|
| 视觉 | 间距/尺寸/颜色/图标/圆角/阴影/动效曲线、**各状态样式矩阵（含 focus-visible）**、音效/光标 |
| 文案 | **全部 UI 文案与错误提示逐条比对**，不许"重写得更清楚" |
| 可访问性 | 键盘走完全流程、无焦点陷阱、对比度、缩放 |
| 交互 | 手势每个阶段、阈值与死区、让位与回弹、自动滚动、异常残留是否清理 |
| 数据 | 字段集、默认值、序列化格式与命名、编码（BOM）、迁移兼容 |
| 行为 | **文案措辞原文**、错误提示、时序与防抖、失败/中断后的状态、退出兜底 |

**实操**：原版与新版并排操作同一流程，逐步比对截图与文案。
**不比对就宣称"对齐了"是不允许的。**

## 六、CI 硬门禁

```yaml
- name: 跨端契约一致性检查
  run: node scripts/cross-end-check.mjs --strict
- name: 覆盖率与 unknown 门禁
  run: python3 scripts/coverage_gate.py ledger/unknown.md ledger/features.md
- name: BUG 与审查问题门禁
  run: python3 scripts/bug_triage.py ledger/bugs.md --gate
```

**放在最前面**（只依赖 node/python，几十毫秒出结果，快速失败）。

**以下均为硬阻塞**：

- 契约缺失或漂移
- unknown 未关闭
- **P0/P1 BUG 未处置、B5 存疑未确认**
- golden 无批准 diff
- 测试被 skip/only
- 覆盖率下降
- 故障注入失败

**门禁结果写入版本库**（`ledger/gate-report.md`），不作为会话内临时结论。

## 八、不通过怎么办

| 情况 | 处置 |
|---|---|
| golden 出现 diff | 判定"有意变更"或"回归"。有意变更须批准并记录影响范围；回归则回退该能力包 |
| mutation 后测试仍绿 | 测试无效，补用例再验 |
| unknown 环境受限无法清零 | **如实说明**：写明受限原因与所需条件，不得包装成"已完成" |
| 像素比对有差异 | 记成新条目进清单，**不许用"差不多"放行** |
| 门禁脚本全绿但没做过故障注入 | 视为未验证，回到 S4 |
| P0/P1 BUG 未处置 | 硬阻塞：简单项当场补方案修掉；复杂项进批次但收工前必须修完 |
| 修了 B1 却没登记行为变更 | 补登记 + golden 标 `intentional-change`；否则视为静默改需求 |
| 视觉总是不稳定 | 回到稳定化：查是哪类不稳定源（时钟/字体/动画/DPR），**不许调大阈值** |
| 差分 oracle 出现"冲突" | 进 S5 重新判定性质，**不许关闭** |
| mutation 存活 | 说明该功能卡只有截图/fixture，没真正锁定行为 → 补等价性测试 |
| 体验参数缺失（新版根本没有） | 落 P-N 标"缺失" → 视同功能缺口，**必须补**（时序类优先） |
| 参数差异理由说不清 | **按原值**；不许填"优化"，也不许用"差不多"放行 |
| 有悬空引用 | 硬错误，运行时必然取不到资源 → 先修 |
| 字体/音效许可查不到 | `third_party` 时升级确认；**`self` 时直接放行** |
| 任务栏图标改了不生效 | 不是代码问题；删重建 `.lnk`，写进部署脚本 |
| 丢了错误提示文案 | **视同功能缺口** —— 用户遇到了但不知道发生了什么 |
| 文案被"重写得更清楚" | 要么补回原文，要么登记有意变更，**不许默认保留新版措辞** |
| 旧数据字段疑似丢弃 | **最高优先级**：数据永久丢失，必须逐字段比对 |
| 崩溃恢复/焦点陷阱没测 | 补实测（强杀进程 / 拔鼠标）；环境不具备就如实记 unknown |
| 原版跑不起来 | **最高优先级阻塞** —— 没有基准就无法谈像素级；先解决可运行性 |
| 许可证据拿不到 | `third_party` 时升级确认；**`self` 时不影响交付** |
| 动效时序超差 | 判定有意变更还是漂移；**不许调容差让它过** |
