# 门禁清单：怎么读，以及读的时候防什么

## 一、规模与真实构成

| 项 | 数量 | 真实含义 |
|---|---|---|
| 声明门禁 | **232** | 编号 1–232 连续无重复 |
| 自动（调脚本） | 102 | **其中绝大多数是台账校验器** |
| 人工待签字 | 130 | 自动全绿**也不等于完成** |
| 脚本总数 | 108 | **81 个是纯 CSV 表校验**（75%） |
| 登记工具 | 263 | **实际可用 3 个**（ffmpeg / graphviz / tesseract） |
| 标"来源不确定" | 20 | 诚实标注，**但需集中清理** |

## 二、怎么跑

```bash
python3 scripts/run_all_gates.py --work <工作区>          # 跑全部
python3 scripts/run_all_gates.py --work <工作区> --strict # 缺输入也算阻断
python3 scripts/run_all_gates.py --list                    # 只列清单
```

**✅ 已验证**：空工作区退出码 = **1**（阻断），`--strict` 也是 1——**CI 不会误判通过**。

## 三、🔴 读结果时防三种误判

**1. 别把 SKIP 当 PASS。**
空工作区实测：`PASS 0 / SKIP 107 / FAIL 2`。
输出会把人工提示项逐条打印，**视觉上像"通过了一大半"**。
> **结尾必须自己数：通过 N / 跳过 N / 失败 N。**

**2. 别把"缺失 260 个工具"当能力缺口。**
263 个登记项里只有 3 个是 CLI，其余是参考仓库与商业 SDK，
**本来就不可能被探测到**。
> 真正要问的是：**你要用的那个工具，装了吗？**

**3. 别把台账校验当自动发现。**
81 个脚本只查"你填没填"，**不会自动发现任何差异**。
> **发现仍然完全依赖人工。**

## 四、必做的混沌验证

**故意改坏一处，看门禁是否报出来。**

> 🔴 **没被抓到的改坏 = 这个门禁是假的。**
> 82 个门禁可能全是假的——验证的是"坏构建能否被检出"。

## 五、硬门禁语义（已验证未静默）

- `required` 缺失 → 进 unknown 并**硬阻断**
- `optional` 缺失 → 标 skipped 并提示
- 偏离缺 owner / 到期日 → **硬阻断**
- 台账缺 `legacy_value` / `tolerance` → **硬阻断**
- 标"不等"却影响碰撞/伤害/可达区域/经济/存档/分支 → **硬阻断**

## 六、三个数字的真实含义（再提醒一次）

> - **263 个工具** → 3 个可直接调用，其余是参考清单
> - **232 个门禁** → 102 个自动（多数是表格校验），130 个人工待签字
> - **108 个脚本** → 81 个校验人工填写的台账，27 个接触真实产物
>
> 🔴 **最该防的不是数字虚高，而是据此产生"机器已经查过了"的错觉。**
