## 二、我们原本就有、无需重复（调研确认其价值）

六层信息、九切角、逐文件台账、行级复查、四像素、性质判定六类、
命令—注册—调用—DTO 四类检查、故障注入。
**调研结论是：这些已经比多数 community skill 更细，不替换，只转成可验收字段。**

## 三、明确不吸收（与我们理念冲突）

| 流行做法 | 为什么不吸收 |
|---|---|
| **先做 MVP，再补功能** | 像素级复刻的目标是穷尽现有行为，MVP 会把未知项变成待办黑洞 |
| **先清理再迁移** | 没有 golden 与契约的清理会让历史行为静默消失；应"先锁行为，再按批准接缝改写" |
| **够用就行 / 结果合理即可** | 复刻的标准是原版实际行为，不是模型认为合理的样子 |
| **产出衰减就收工 / 让模型决定何时完成** | 收工由覆盖率、unknown、契约、golden、故障注入与人工批准共同决定 |
| **测试通过即等价** | 测试可能漏路径、golden 可能被手改、断言可能被削弱 |
| **一个万能 CLAUDE.md** | 规则过长会失效、跨文件复制会漂移、冲突指令会被任意选择 |
| **多 agent 天然更准** | 无边界并行只会复制错误；只有隔离 + 结构化产物 + 锁 + 独立审查才提高可靠性 |
| **awesome 列表条目天然可信** | 只是发现入口；引入任何 skill 前必须读真实仓库与脚本，并小样本验证 |

## 四、调研局限（如实记录）

- 多数 community skill 缺少独立效果评估，"仓库真实存在、内容与页面一致"即视为可引用证据；
  聚合站/市场宣传仅作线索，不作结论依据。
- 部分候选仓库未能取得完整原始 SKILL.md 正文，仅作为结构弱证据。
- 未对不可公开访问的原版程序做实测，迁移细节的验证仍依赖本项目自身实证。

## 五·第二轮：工具层调研（GitHub 开源仓库）

第二轮调研聚焦**具体工具**，结论是：原则体系已完整，薄弱的是把原则变成机器可执行的证据。

### 5.4 考古权重（只决定顺序）

CodeScene / Code Maat / hercules / git-of-theseus → 决定**挖掘顺序**，
**只进 `考古权重`，不进 `completeness`**：
> 旧功能不存在就是不存在，任何热度模型都救不回来；低热度旧模块不得自动判定"无需迁移"。

### 5.5 第二轮明确不吸收

| 流行做法 | 理由 |
|---|---|
| **自动 approve baseline**（含 AI 自动 approve） | 把复刻目标改成"让新实现通过" |
| **单一全局阈值衡量所有 UI** | 图标和动画不能同一个标准 |
| **随机快照测试替代视觉契约** | 不稳定 = 人人都在重录 = 门禁失效 |
| **端到端通过即迁移完成** | 不覆盖视觉状态、边界、时序、可访问性 |
| 为用某工具引入中间格式（如强上 protobuf） | 为工具改架构，本末倒置 |
| OpenRewrite（本例） | 面向 JVM；仅在目标端为 Java/JVM 时借鉴其 recipe 思想 |

### 5.5·补：体验参数（用户提出，本次重点补充）

**用户洞察**：tips 多久弹、按钮间距多少、动画多长——
**可以不照搬，但必须知道搬前是什么样**。不记录就会丢失，都影响体验。

这不是从某个仓库抄来的，而是复刻实践里最容易塌的一块：

XAML 属性、`Timer.Interval`、CSS 声明里。**功能全对而参数全丢，

### 5.5·补2：资产与资源（用户提出：样式/美术/颜色/动效/阴影/音效归类）

**用户洞察**：样式、美术、颜色、动效、阴影、音效、美术资源——
"还有我没有想到的都记录一下，整体归类"。

归成 **A–O 十五类**（见 `references/资产与资源总清单.md`），
其中**用户多半没想到但一定会踩的**是这几类：

| 类 | 为什么容易没想到 | 踩了会怎样 |
|---|---|---|
| **I 状态样式矩阵** | 习惯按控件记样式，不按「控件×状态」记 | 某个状态下长得不对，测试也测不到 |
| **focus-visible** | 用鼠标测根本触发不到 | 键盘用户完全没法用 |
| **B 退场动画 / 中断行为** | 只关注"怎么出现" | "消失得很突兀" |
| **L 许可合规** | 不是技术问题 | 仅 `third_party` 需确认（字体商用授权最常见）；**自有项目跳过** |
| **M 系统整合资源** | 不在代码里，在注册表/快捷方式里 | 改了不生效，还以为是代码 bug |
| **G 音效** | 桌面程序有，迁 Web 常直接不迁 | 用户觉得"少了点什么" |
| **N RTL 布局** | 中文场景用不上 | 支持多语言后整份样式要镜像（含阴影方向） |

**三个必查坑**：
1. 颜色格式 XAML `#AARRGGBB` ↔ CSS `#RRGGBBAA` —— **照抄变透明**
2. ICO 是否真转 —— 未真正转 ICO，**改图标根本不生效**（原版 A2）
3. 任务栏图标缓存 —— Windows 按固定那一刻缓存，需**删重建 `.lnk`**

| 补充 | 落到哪 |
|---|---|
| 铁律 2·补2「资产与资源」+ 十五类索引 | `SKILL.md` |
| `S2A-资产与资源清点.md` | `flow/` |
| `references/资产与资源总清单.md`（A–O 逐项表） | `references/` |
| `assets/资产与资源清单模板.md`（AS-N + 许可表） | `assets/` |

和 1 处悬空引用（`App.xaml` 引用了不存在的 `missing.png`）——

文案、空态错误态、可访问性、性能、系统整合、输入设备、状态持久化、

|---|---|

| `S2T-文案与全维度.md` | `flow/` |
| `references/体验维度总清单.md`（C1–C12 逐项表） | `references/` |

**C1 文案是最常被直接重写的一类**：不看原文案，"重写得更清楚"——
**但用户肌肉记忆认的是原句，换了措辞等于换了入口。**

**六个多半没想到但一定会踩**：
防闪烁延迟（没它就一直闪）/ 部分失败（10 个成功 8 个怎么显示）/
焦点陷阱（**用鼠标测不出来**）/ 崩溃恢复（正常退出测不出）/
**字段静默丢弃**（实证 `clusters`，数据永久丢失）/ 多显示器不同 DPI。

**脚本实证**：样例工程正确识别出 2 组**疑似改写**
（「保存成功」→「操作成功」、「确定」→「确认」）和 5 条丢失文案。
⚠️ 用**序列相似度而非字符集合**——短中文串同义词替换
（确定→确认）字符几乎不重叠，集合法只有 0.33 会漏掉。

### 5.6 实证：工具身份陷阱 ⭐

`shutil.which("sg")` 会命中 **Unix 的 `sg`（set group ID）命令** ——
它可执行，但没有 `scan` 子命令，会让查询**永远 0 命中却显示"成功"**。
这是"假绿灯"的典型形态，`scripts/ast_query.py` 已用 `--version` 特征 + 子命令双重校验。
**教训：只检查"命令存在"是不够的，必须验证工具身份。**

### 5.7 实证：体验参数提取的四个陷阱（均已修进脚本）

| 陷阱 | 后果 | 修法 |
|---|---|---|
| `\bThreshold\b` 抓不到 `dragThreshold` | **驼峰命名的参数全漏** | 匹配含关键词的完整标识符 `\w*keyword\w*` + 忽略大小写 |
| `FontSize` 与 `fontSize` 当两个参数 | 差集全是噪音，真差异看不见 | 键归一化（小写去分隔符） |
| `TimeSpan.FromMilliseconds(180)` 被当秒 | **180 变 180000ms** | 先判 `millisecond`，再判 `second` |
| `Margin="8,4,8,4"` 被逗号截断 | 四元组只拿到 `8` | 优先取引号内整段 |

**另有一条脚本处理不了、必须人看的**：
**XAML 是「左,上,右,下」，CSS 是「上 右 下 左」** ——
数值集合相同不代表等价，脚本会提示"顺序约定不同"，但**别直接抄**。

## 六·第三轮：补最大失衡 —— 原版侧取证

第三轮的核心发现不是"还缺哪个工具"，而是**结构性失衡**：

> **工具链能证明新版"做成了什么"，却难以稳定证明原版"本来是什么"。**
> 视觉有 Playwright/pixelmatch/Loki/reg-suit，代码有 tree-sitter/ast-grep/comby，
> 等价性有 insta/fast-check/Stryker —— **几乎全是针对新版一侧的**。
> 对"如何从原版 WPF 旧程序里捕获行为与视觉"几乎没有工具化手段。

### 6.1 新增 S0 原版证据采集（最高优先级）

| 件套 | 手段 | 落到哪 |
|---|---|---|
| **稳定身份** | **FlaUI** 主驱动 + pywinauto 交叉验证，不一致标 `tree_conflict` | `flow/S0`、`references/原版取证.md` |
| **确定性图像** | PrintWindow（视觉主基线）/ BitBlt（屏幕对照）/ WPF `RenderTargetBitmap`（资源校验）**三原语都要** | 同上 |
| **资源字节** | ILSpy / ilspycmd / `pefile` / .NET 资源读取器（**源码不全才启用**） | 同上 |
| **行为时序** | UIA 事件录制 + 响应时间 | 同上 |

**证据身份** `state_id = <模块>__<视图>__<状态>__<变体>__<序号>` ——
挂到 `unknown` 后，**未知从"没有查到"变成"有 state_id 但证据等级不足"**，
穷尽门禁从文本覆盖升级为**状态覆盖**。

**三条硬规则**：
1. 坐标点击与"体验细节不能丢"直接冲突 → 只能最后兜底
2. 截图环境不固定 → 像素门禁把**环境噪声误判为功能回退**
3. 侵入式证据（调试器/内存/注入/TTD）标 `invasive=true`，**不混入常规基线**

### 6.2 关键认知：反编译不是源码

`ILSpy` / `ilspycmd` 是 .NET 主考古器，但**反编译产物是 B 级证据**，
会丢注释、丢局部命名、丢布局意图。
**BAML/XAML 导出必须与 C# 反编译并行** —— 只看代码会丢掉整个布局结构。

**二进制差异做 IL/元数据级，不做 PE 字节级** ——
编译选项、签名、时间戳变化后语义可能仍一致。
`radiff2` 只判断"安装包是否变化"，**不用于解释功能**。

### 6.3 许可从"待确认"升级为四态门禁

| 状态 | 放行 |
|---|---|
| `confirmed_allowed` | ✅ |
| `confirmed_restricted` | ❌ 阻断 |
| `unknown_evidence` | ❌ 阻断 |
| `not_applicable` | ✅（限自研且审批） |

**不许用功能完成替代许可完成** ——
允许用更优设计替代实现，**不允许用侵权替代原版字体**。

工具：ScanCode Toolkit、Syft/Grype（SBOM）、cargo-deny、licensee、REUSE、ClearlyDefined。
**每个只覆盖自身生态**，必须同时生成 `bom.original.spdx` 与 `bom.tauri-react.spdx` 做差集。

**字体是像素级复刻最容易忽略的红线** ——
同一家族不同字重/厂商/渠道规则可能完全不同，
需逐项确认：个人/商用/嵌入/再分发/修改/Web 托管/子集化。

### 6.4 三处"必须如实说明做不到"

| 事 | 现状 |
|---|---|
| **新旧无障碍树自动语义 diff** | **没有成熟一站式方案** —— 必须自建归一化器，不许宣称存在现成方案 |
| **UI 动效回归** | 无成熟统一项目；FFmpeg/OpenCV 只能测"何时变、何时停、哪些区域动"，**不能识别缓动曲线** |
| **RTL 视觉正确性** | rtlcss/postcss-rtl 自动镜像**不能证明视觉正确**，仍需逐状态截图 |

**这是本次调研最重要的态度**：宁可说"做不到、需自建"，
也不把 FFmpeg 抽帧包装成"动效语义理解"。

### 6.5 第三轮明确不吸收

| 做法 | 理由 |
|---|---|
| **纯坐标点击做原版自动化** | 与"体验细节不能丢"直接冲突 |
| **录屏回放当回归证据** | 分不清环境噪声与真实差异 |
| **图形相似搜索替代控件树 diff** | 掩盖控件缺失（长得像 ≠ 功能在） |
| **"智能理解界面"的自动工具** | 无可审计元素映射，不进门禁 |
| 商业工具作管线唯一依赖 | 可辅助调查，但破坏可复现性 |
| de4dot 等反混淆 | **自有项目可自由使用**；仅第三方目标才是风险信号 |
| 拿不到证据就标"已解决" | 缺口应写进报告，不许用新版默认实践补 |

### 6.6 ⚠️ 法律边界（必读）

> 反编译、内存读取、第三方资产复制**只适用于团队合法拥有、有权分析
> 并用于授权迁移的目标**，不构成对任何第三方许可、著作权或反规避限制的放宽。

遇加密 / DRM / 许可证校验 → `ownership: self`（自有项目）**不受此限**；仅 `third_party` 时停止确认。

**另**：Sysinternals 系列（ProcMon / ProcDump）本次未抓到可引用的一手官方页面，
报告中已标"来源不确定"，**不写精确功能声称**。Snoop WPF 同理。

## 六·第四轮：从结构证据到可解释差异

第四轮的核心判断：

> **最大缺口不是"再找一个视觉回归工具"，
> 而是缺一条从结构证据到可解释差异的闭环。**
> A（树对齐）、B（录屏质量）、C（差异归因）三者分开用，
> 只能回答"哪里不一样"，不能回答"对应哪个原版节点、差了几像素、为何产生"。

### 6.7 树对齐：新栈无障碍树 ≠ 原版 UIA 树

**没找到可靠、维护中的"UIA ↔ DOM 语义对齐"专用开源项目** ——
**这个空白本身就是必须自建的能力**，不许宣称存在现成方案。

WPF 暴露 AutomationId / ControlType / BoundingRectangle / IsOffscreen；
React 无障碍树偏语义角色与 ARIA 状态。
自定义控件、装饰元素、虚拟化列表、弹出层常出现 **1:N、N:1、多对多**。

**四级对齐（不许跳级）**：
L1 锚点匹配（稳定键 O(n)）→ L2 **NetworkX VF2++** →
L3 **GumTree**（同构子树 → 共享后代细化 → 编辑脚本，含 move/rename）→
L4 **APTED** / Zhang-Shasha（**仅未匹配连通块**）。

**APTED 是兜底不是默认**；超预算（200 节点 / 8 层 / 500 ops）一律降级为区域匹配，
**不许为覆盖率好看输出假的精确映射**。

**匹配键不能只依赖 role**：
`control_type × automation_id × name × runtime_id 哈希 × 几何中心 × 宽高 × 深度 × 文本 × 图像哈希`。

**归一化不做则两棵树永远对不上**：忽略装饰容器、合并重复容器、
几何软匹配、虚拟化按可见顺序恢复、role 回退允许多候选。

> **装饰层消失但语义结构保留 → 不应判为失败**（换掉权宜之计是对的）。

### 6.8 差异归因：十类根因 + 多证据投票

十类：平移 / 缩放 / 颜色 / 文本字体 / 缺失 / 多余 / 时序 / 渲染 /
**结构变化** / 未定。

- `structural` → 触发**契约回归**，不只是视觉回归
- `unknown` → **阻止自动收工**

**每簇算 12 项特征**（bbox / 面积 / 质心 / Hu 矩 / 颜色直方图 / 局部 SSIM /
边缘差 / OCR / 节点映射 / 动画相位 / 鼠标区 / 时钟区）再做投票，
**不把任何单一分类器（含 OpenCV）当真理**。

**odiff 的抗锯齿忽略是候选分类，不是默认豁免** ——
必须把"边缘变化"拆成：无法消除的渲染环境差 vs 真实的圆角/渐变/阴影变化。
**这是本 Skill 与普通视觉回归产品最关键的分界。**

**报告要同时呈现证据与反对证据**，最终门禁用"证据充分性"而非差异像素数。

### 6.9 录屏：VMAF 回答"多像"，录屏回答"何时发生"

OBS Studio（录原版）+ **Netflix/VMAF**（感知质量，含 VIF/ADM/Motion/SSIM/
MS-SSIM/CIEDE2000）+ OpenCV `QualitySSIM`（逐通道质量图）+ odiff（抗锯齿/区域/YIQ）。

**视频基线必须记录机器环境指纹**（OS / GPU / 电源模式 / ICC / 字体版本 /
编码器 / 时基…），**不能跨机器合并** —— Playwright 官方明确主机 OS、版本、
设置、硬件、电源模式、无头模式均会改变渲染。

**❌ GIF 不作测量源**（色深与帧损失污染指标）；
**❌ 不让 AI 直接看视频口述结论**（应先转帧集 + 质量序列 + 候选簇）。

### 6.10 环境锁定：字体与色彩必须进门禁

**FreeType 的 hinting、gamma、stem darkening、LCD 滤镜都会改变字形** ——
字体差异是"合法外观变化"，必须进门禁而非事后忽略。
`font_lock.yml` 锁：字体 SHA256 / 版本 / hinting / LCD / DPI / 亚像素策略。

**色彩锁 ICC**（Little CMS，MIT）：未嵌入 profile 的截图状态必须是
`color_profile_unknown`，**不得冒充无损证据**。

### 6.11 其他吸收

| 方向 | 工具 |
|---|---|
| 私有格式考古 | **Kaitai Struct**（`.ksy` 生成多语言 parser）+ protoscope + blackboxprotobuf + ImHex；验收要 **round-trip 字节相等** |
| 克隆检测 | SourcererCC / Deckard / jscpd；**目标是发现历史分叉，不是单纯删重复** |
| 死代码 | Vulture（Python）/ Knip（TS）；**只产生候选，不能自动删反射调用** |
| 影响分析 | jQAssistant 图模型思路；**输出可追溯查询，不是风险分数黑箱** |
| 技能生态 | `anthropics/skills` 的分层与 frontmatter；**不搬运泛风格规则** |
| 时间旅行 | QEMU / PANDA 只用于难复现缺陷；**不混成一个"确定性"概念** |

**实施顺序 A→C→B→D→E→F/G→H/I** ——
先做树对齐与差异归因，录屏才有意义；再锁字体色彩避免大量假回归。
**顺序倒置最容易落入"工具很多、差异仍无法收工"。**

### 6.12 第四轮明确不吸收

| 做法 | 理由 |
|---|---|
| "像素不一致就失败" | 太粗：误杀亚像素文本、动画相位、合法字体替换 |
| "像素一致就通过" | 也不足：结构已变只是凑巧相似时会放过 |
| tree-sitter diff 当 UI 等价性 | 文本结构相似 ≠ 运行时控件树等价 |
| Myers/Unified 行级 diff | 对重排、移动、属性顺序变化大量噪声 |
| 编辑距离阈值设全局常数 | 1px 位移与表单层级错误权重应不同 |
| 只保留分类名删原始截图 | 后续无法复核 |
| "功能等价即完成" | 与"体验细节不能丢"冲突；手感不同应判**部分完成** |
| 全局代码风格规则 | 易改 `var`→`const`、改 Win32 时序，**却遗漏原版边界** |

## 六·第五轮：让原版自己当 oracle，并挖出它没写下来的规则

第五轮判断：前四轮都在补"怎么看得更清楚"，
本轮补的是**"怎么知道哪些是规则"**和**"怎么让原版自己当 oracle"**。

### 6.14 不变量挖掘（本轮最高价值单项）

> **S2 穷尽挖掘的本质瓶颈不是"没读完代码"，而是"读完了但不知道哪些是规则"。**

**Daikon**（`plse-cs-uw/daikon`，5.8.24）+ **Celeriac .NET 前端**，
支持 `x.field > abs(y)`、`y = 2*x+3`、`array a is sorted` 等模板——
正是复刻现场需要的那类隐含约束。

**两阶段闭环**：
1. 原版插桩 → **FlaUI 驱动覆盖所有业务操作** → 候选不变量清单
   = **S2 穷尽挖掘的"机器先验"**
2. 同一模板编译成 S7 断言 → 新版校验内部状态语义（S7V 只管像素）

**⚠️ 最关键边界：Daikon 输出的是"在已观测执行上成立"的候选，不是证明。**
**必须以驱动覆盖率作置信度分母**，不足则降级人工，**不得直接进 G 门禁**。
> **这是本轮最容易误用的点：把统计规律当规格。**

配套：**LearnLib**（主动式自动机学习，以原版为黑盒 SUL）→
`state_model_diff` 三列，其中**"同状态不同转移守卫"最危险** ——
功能在但**触发条件变了**。

### 6.15 差分测试：不需要人写 oracle

> **原版的行为就是现成的 oracle。**
> "原版接受 / 新版拒绝同一输入" = 一条语义回归，
> **这类 bug 不产生崩溃，纯视觉测试与纯单测都抓不到。**

NEZHA（δ-diversity）/ difftest（成对输出比对）。

**⚠️ 用"行为向量距离"选种，不是代码覆盖率** ——
覆盖率引导会让新版"多跑"而忽视"结果不同"。
seed corpus 应来自网络录制，不是随机生成。

**四类 oracle**：真回归（S2B 直报）· 权宜之计消除（须附 S4 契约变更说明）·
非确定（进 S7V）· **外部契约变更（触发 S0 重采，不许改 oracle）**。

**与属性测试正交**：属性测试人写 oracle（S5 后加固），
差分测试用另一实现当 oracle —— **复刻场景优先差分测试**。

**⚠️ 未命中率不得把 0 当目标** —— 可能是原版死路径或新版少实现。

### 6.16 网络与 I/O 录制回放

> **原版不是"黑箱截图机"，而是网络客户端 + 文件/注册表读写者。**

mitmproxy（录制 + 故障注入）+ WireMock（回放）+ **Detours**（MIT，
挂 `CreateFile*`/`RegOpenKey*`，产出 `syscall_trace.jsonl`/`fs_ops.csv`/`reg_ops.csv`）。

`har_diff` 四列（新请求/漏请求/响应差异/并发拓扑）
**能在 UI 还没画出来时先判死行为等价性** —— 比像素差更早、更硬。

**回放时任何未录制请求直接 FAIL，不是 passthrough** ——
"换成更好方案"只针对实现，**不针对外部契约**。

### 6.17 环境锁（前四轮忽略得最彻底的一条）

原版渲染依赖 .NET 运行时、字体、GPU 驱动、DPI 感知、系统主题、
**电源模式** —— 这些以前**都不在取证清单里**。

`environment.lock` 15 项（渲染敏感 7 项），**不一致直接 FAIL，不降级**。
**`unknown` 不是"已锁定"。**

⚠️ **弱版本**：Tauri 目标无法 bit-for-bit（MSVC/Rust 未承诺），
故要求"输入集哈希一致 + 环境声明一致"。**这一点必须写死避免后续误用。**

### 6.18 ❌ 目标函数冲突（本轮重点辨析）

> **"流行但冲突"的共性：目标函数不同。**

| 工具 | 它的目标函数 | 冲突点 |
|---|---|---|
| **Healenium** | 测试**通过率** | 自愈定位器**绕过**定位稳定要求；ML 替换不可审计 |
| **iFixFlakies** | 补丁通过率 | 修的是 oracle 而非实现，S3 失去依据 |
| NonDex / DeFlaker | 容错 / 跳过 | 与"不轻易收工"相悖 |
| fMBT / NModel | — | 已归档 / 死分支，**供应风险** |

**本 Skill 的目标函数是"差异暴露率"。**

三个反例：
1. Healenium 自愈 → 门禁"通过"但**新版 DOM 已偏离原版**，S2 成果被悄悄作废
2. iFixFlakies → **修复的是 oracle 而非实现**
3. 异常指纹合并 → S2B 清单**少报**，S6 质量被系统性低估

**可吸收的只有方法论**：把 flaky 分类合并进 `coverage_gate`，
识别后**强制重跑直至收敛**，把"收敛次数"作质量指标 —— **而不是"修复"它**。

**新增原则**：任何外部工具进门禁前，**必须重写其目标函数以匹配"差异暴露率"**。
> **工具不冲突，用法冲突。**

### 6.19 其他吸收

- **MBT**：GraphWalker（含 Rust 版）+ ModBat；产出**状态覆盖矩阵**，
  与像素快照分开存（快照是证据，矩阵是 coverage）
- **design token**：**DTCG 2025.10 首个稳定版**；`token_diff` 比
  "设计稿声称值 vs 运行时实际值"，是判断"原版有没有违反自己设计稿"的**唯一客观依据**
- **遥测**：OpenTelemetry；`telemetry_diff` 查"仅原版存在的 span"= **新版丢埋点**

### 6.20 ⚠️ 来源不确定（本轮一律不吸收）

`TsudaKageyu/minhook`（仓库未确认）· `WinAPIOverride`（仅 SourceForge 发布页）·
`rohitab/apimonitor`（无开源仓库）· `Shaker` / `FlakyBot`（无确认仓库）·
`Hoverfly/hoverfly-io`（活跃仓库状态未确认）· UI clone benchmark（是 LLM 评测）·

## 六·第六轮：语义证据层（不只看最终值）

第六轮判断：**问题不在工具数量**（已有 26 个脚本），而在**证据粒度**。

> 现有脚本比较的是"**最终值**"，不足以回答：
> **中间调度是否等价、异常路径是否等价、协议格式是否等价。**

正确做法：把不可直接像素比较的语义，转成**可比较的序列化金标准**
（文本：glyph/cluster/break/bidi；并发：actor/logical time/state；
故障：precondition/fault/recovery/postcondition）。

### 6.21 文本：只锁 hinting 是不够的

WPF 的 DirectWrite/Uniscribe/ICU/Win32 locale 与浏览器 CSS 文本栈
**不共享同一语义**。只锁 FreeType hinting，仍可能在**连字、字簇、
双向重排、换行点、排序键、日期格式**上与原版不同。

**HarfBuzz**（A 区第一优先）作字形事实源。两个独立合同**不许混**：
**L1 字形簇合同**（glyph/cluster/advance，`hb-shape`）
vs **L2 最终像素合同**（fallback/hinting/subpixel/DPI）。
> **只在 Chromium 截图，不能判断差异来自排版、字体选择还是合成。**

**ICU4X + Raqm** 把"看起来一样"拆成规范化、断行、排序、Bidi 四张证据表。

**实测抓到两类截图看不出的坑**：
`café` 组合/预组合序列差异（NFC 相等但原字节不同，**影响排序与匹配**）、
`ＡＢＣ` 全角/半角（NFKC 相等但 NFC 不同，**显示可能相同但比较不同**）。

**权威层分工不许两边都算**：排序/索引由 Rust 固定 data 版本，
展示由前端按 locale，渲染由 Chromium/HarfBuzz。

⚠️ **不要把 `unicode-range` 当真正的子集化** —— 只控下载，不删字形。

### 6.22 并发：没有"两版等价验证器"

**搜索范围内没有找到能直接证明两版并发完全等价的现成工具** ——
**不许宣称存在**。

TSan（需近全量插桩）/ DRD+Helgrind（仅 Linux，不能用于 WPF）/
Loom+shuttle（受控调度，**不能证明正确性**）/
tokio-console（发现"活着但不前进"：self-wake、lost-waker、never-yielded）/
rr --chaos（Linux，不能直接分析生产 WPF）。

**可复刻的并发不变量应进 S3，不是只写进测试注释**：
单 command 不被两 actor 同时处理 · 事件不丢不重 ·
取消后不更新废弃窗口状态 · 任务链终态三选一 · 并发导入不破坏单写者 ·
关闭后无 use-after-close。

**四条门禁**：阻塞预算 / 锁跨度（**持锁禁 await**）/ 取消一致性 / 调度可回放 seed。

### 6.23 故障：26 类，不止网络

现有 `cross-end-check` 只覆盖 F1-F4（参数层），**原版在异常下的行为一条都没采集**。

> **"没有崩溃" ≠ "韧性等价"** —— 两条不同的门禁。
> 原版可能也错了，但新版应与原版**在同一前置条件下表现一致**。

**每类六栏齐全** + **`old_behavior` 必须已采集**
（**不许凭空生成新版韧性**，脚本硬阻断留 TODO 的项）。

工具分工**互不替代**：Toxiproxy 管传输层（latency/down/timeout/slicer…）、
libfiu 管 POSIX 层（`LD_PRELOAD` + errno + 运行时启停）、
**Chaos Mesh 仅实验室**（K8s 原生，不进桌面主链）、
mitmproxy/WireMock 管内容层。

### 6.24 安装与更新：桌面复刻最大的盲区之一

Tauri 默认 MSI **不能自动复刻原版所有安装语义**（快捷方式参数、
文件关联、URL 协议、服务、每用户/每机器作用域……）。

> **平滑升级的核心不是"能下载新包"，而是残留数据迁移矩阵。**

13 处残留位置每处定 owner（只读快照/迁移/兼容/双写/废弃）。
**没有 owner 的数据在升级时一定会被漏掉。**

**Velopack 比 Omaha 更适合**复刻 Windows 桌面应用（Omaha 是重量级 C++/COM，
无硬约束不自建）；WiX 作**安装契约源码**而非临时打包脚本。
⚠️ 开始菜单 shortcut 需 **Shortcut + RemoveFolder + KeyPath** 齐全，否则**卸载残留**。

### 6.25 崩溃

Breakpad / Crashpad 捕获，**rust-minidump** 本地分析。

**⚠️ 不应以"调用栈相同"作门禁** —— 跨语言没有相同函数。
应比较归一化后的：崩溃签名 · 崩溃阶段 · 用户输入 · 业务状态 · 恢复动作。

**Sentry 是聚合告警平台，不是像素级差异验收源**；可作上报渠道。

### 6.26 其他

**图像管线**：resvg（确定性位图）/ librsvg / sharp（**有操作顺序依赖**，
不能替代构建期基准）/ oxipng+pngquant+svgo。
**不得把"看起来差不多"的压缩产物直接发布**。

**剪贴板/拖放/OLE**：必须按**格式集合**验收，不是"文本粘贴成功"。
Tauri clipboard-manager 只公开文本/图像/HTML，**CF_DIB、CF_HDROP、OLE、
延迟渲染、私有格式不能直接复刻**。单实例用 `single-instance` 插件补 WPF 语义。

**性能**：samply / FlameGraph；**火焰图只能解释热点，不能证明"体验一样"**。
**搜索**：复刻 tokenizer/score/tiebreak/延迟预算，不只抄最终候选。

### 6.27 ❌ 第六轮明确不吸收

| 做法 | 理由 |
|---|---|
| **用 Chromium 截图等同文本等价** | 不暴露 glyph/cluster/Bidi 根因 |
| **"没有崩溃"等同韧性等价** | 两条不同门禁 |
| **"概率通过"的随机并发测试** | 与穷尽理念冲突；只能作发现器 |
| **"能粘贴文本"等同剪贴板复刻** | 忽略 CF_HTML/CF_DIB/OLE/私有格式 |
| Sentry 作唯一崩溃源 | 聚合优先，不保证单用户证据完整 |
| 自动 font subset / unicode-range | 漏字符、漏 OT feature |
| Chaos Mesh 覆盖 Windows 桌面 | K8s 假设与单机桌面不符 |
| Skia / Pango 进默认运行时 | WebView 已封装渲染 / GTK 依赖重 |

## 七、六轮调研共同新增的硬机制（这是我们原来的缺口）

调研最直接的收获是：**把已有的判断转成可复算的覆盖率、门禁与跨阶段契约。**

1. **unknown 清单 + 硬门禁**（`scripts/coverage_gate.py`）：unknown > 0 一律阻塞
2. **证据等级**：assumption 不得成为迁移决定
3. **golden 三层基线 + 人工批准**：抵御"AI 悄悄修掉历史 bug / 削弱断言"
4. **能力包与回滚边界**：禁止一次性翻译全库
5. **mutation 验证**：确认测试真能发现破坏
6. **动作标签**：性质判定必须落成 preserve/replace/merge/remove/defer
7. **门禁结果写进版本库**：不做会话内口头结论
