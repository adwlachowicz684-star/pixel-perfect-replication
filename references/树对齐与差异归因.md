# 树对齐 / 差异归因 / 环境锁定

> **核心结论**：最大缺口不是"再找一个视觉回归工具"，
> 而是缺一条从**结构证据到可解释差异**的闭环。
>
> **像素差只是症状，不能作为穷尽验收的终态证据。**

---

## 一、树对齐（原版 UIA ↔ 新版可访问性树）★★★

**⚠️ 核心认知**：新栈可访问性树**不是**原版 UIA 树的天然同构物。

| | WPF/UIA | React/可访问性树 |
|---|---|---|
| 暴露什么 | AutomationId、ControlType、Name、BoundingRectangle、IsEnabled、IsOffscreen | 语义角色、文本、焦点顺序、ARIA 状态 |
| 常见错位 | 自定义控件、装饰元素、虚拟化列表、弹出层 → **1:N、N:1、多对多** | |

**本报告未找到可靠、维护中的"UIA ↔ DOM 语义对齐"专用开源项目** ——
**这一空白本身就是应自建的能力**，不许宣称存在现成方案。

### 四级对齐（从稳到贵，不许跳级）

| 级 | 算法 | 适用 |
|---|---|---|
| **L1** | 稳定键锚点匹配 O(n) | automation_id / runtime_id / name |
| **L2** | **NetworkX VF2++**（`networkx`） | 有唯一同构候选时求精确映射 |
| **L3** | **GumTree**（`GumTreeDiff/gumtree`）思路 | 自上而下找同构子树 → 自下而上用共享后代细化 → 生成编辑脚本（含 **move / rename**） |
| **L4** | **APTED**（`DatabaseGroup/apted`）/ Zhang-Shasha（`zss`） | **仅未匹配连通块**，且受预算约束 |

**APTED 是"无法靠规则匹配时的精确兜底"，不是默认全树算法。**
超预算一律降级为连通域/区域匹配 —— **不许为了覆盖率好看输出假的精确映射**。

**复杂度预算**：`max_subtree_nodes 200 / max_subtree_height 8 / max_ted_ops 500`

### 候选匹配向量（**不能只依赖 role**）

```
control_type × automation_id × name × runtime_id 哈希 ×
几何中心 × 宽高 × 父子深度 × 文本内容 × 图像哈希
```

先稳定匹配锚点，再用树编辑距离处理剩余节点。

### 归一化规则（不做归一化，两棵树永远对不上）

1. **忽略装饰容器** —— Border / Decorator / AdornerLayer / React fragment 折叠
2. **合并重复容器** —— StackPanel / Grid / `<div>` 包装层按父子链折叠
3. **几何软匹配** —— 包围盒用容差比较，不要求像素级相等
4. **虚拟化恢复** —— 同 ID 节点按**可见顺序**恢复，不按 DOM 顺序
5. **role 回退** —— `ListViewItem` → `role=row` / 列表项 / 虚拟滚动组合，**允许多候选**

### 结构化 diff 辅助

| 工具 | 用途 |
|---|---|
| `Shoobx/xmldiff` | XAML / 导出树的 XML diff + patch |
| `benjamine/jsondiffpatch` | 状态快照、配置快照的 deep diff（数组需 `objectHash`） |
| `paulfitz/daff` | 表结构 diff：属性集、资源清单、状态转移表 |

### ❌ 冲突做法

- 把 **tree-sitter diff 当 UI 等价性证据** —— 文本结构相似 ≠ 运行时控件树等价
- 只用 **Myers/Unified 行级 diff** —— 对重排、移动、属性顺序变化产生大量噪声
- **固定角色映射** —— 必须允许多候选 + 人工裁决
- **编辑距离阈值设成全局常数** —— 按钮栏移动 1px 与整个表单层级错误权重应不同

> **关键分界**：装饰层消失但语义结构保留 → **不应判为失败**（换掉权宜之计是对的）。

## 二、差异归因 ★★★

**十类根因**（每个差异簇输出唯一主因 + 候选 + 支持/冲突证据）：

| 根因 | 判定信号 | 门禁动作 |
|---|---|---|
| `translation` | 形状/面积/直方图相近，质心位移 | 位移超出**体验参数阈值**才失败 |
| `resize` | 宽高比与内容不变，轮廓相似度下降 | 检查布局约束、DPI、flex 比例 |
| `color` | 几何稳定但通道/色差变化 | 固定 ICC 与色彩空间 |
| `text` | 包围盒稳定，OCR 或字形哈希变化 | 检查字体、hinting、locale、截断 |
| `missing` | 新版背景 vs 原版前景 | 与 **UIA/DOM 节点消失证据互证** |
| `extra` | 新版新增连通域 | 检查 focus ring、tooltip、调试层 |
| `animation` | 多帧状态均合法，单一时刻有差异 | 帧序列须在合法状态集合内 |
| `rendering` | 抗锯齿、亚像素、LCD 边缘高频变化 | 抗锯齿免疫或局部容忍 —— **但不是自动豁免** |
| `structural` | 节点映射改变（move/rename/insert/delete） | 触发**契约回归**，不只是视觉回归 |
| `unknown` | 各证据互相矛盾 | **阻止自动收工**，进人工 S2/S3 |

### 多证据投票输入（每个簇都算）

`bbox` / `area` / `centroid` / `Hu 矩` / `颜色直方图` /
`局部 SSIM` / `边缘差` / `OCR 文本` / `节点映射` / `动画相位` /
`鼠标区域` / `时钟区域`

**归因必须依赖几何特征与多证据投票，不把任何单一分类器当真理。**

例：包围盒一致 + OCR 相同 + 仅边缘高频 → 更像抗锯齿；
包围盒与文字都不同 → 更像布局或内容变化。

### 可视化报告要同时呈现证据和反对证据

每处差异应包含：原版帧 / 新版帧 / SSIM 质量图 / 连通簇编号 / bbox /
候选根因 / 支持证据 / **冲突证据** / 对应树节点 ID / 契约条目 / 裁定状态。

**最终门禁采用"证据充分性"而非差异像素数** ——
证据冲突则强制人工复核。

### odiff 的抗锯齿忽略 = 候选分类，不是默认豁免

像素级复刻的目标是**保留原版外观**，所以必须把"边缘变化"拆成两类：
无法消除的渲染环境差（入 `known_environmental_diff`）
vs 真实宽度/圆角/渐变/阴影变化（仍进契约回归）。

**这个区别是本 Skill 与普通视觉回归产品最关键的分界。**

## 三、录屏与逐帧质量 ★★★

| 工具 | 用途 |
|---|---|
| **OBS Studio**（`obsproject/obs-studio`，GPLv2+） | 固定场景、分辨率、编码器后录原版交互 |
| **Netflix/VMAF** | 感知质量：VIF、ADM、Motion、PSNR、SSIM、MS-SSIM、CIEDE2000 |
| **OpenCV `QualitySSIM`** | 逐通道 0-1 质量值与质量图 → 局部热力图 |
| **odiff** | 抗锯齿识别、区域忽略、尺寸不一致、YIQ 阈值 |

**视频质量评分回答"看起来多像"，录屏回答"行为何时发生"——二者必须合并。**

正确流水线：同分辨率/帧率/时间基/音频时钟/无鼠标输入录制 →
FFmpeg 按显示时间戳对齐 → 逐帧生成工作帧 → 裁剪与黑帧检测 →
算 VMAF/SSIM → 低分帧送入像素与树诊断。

### 视频基线必须记录机器环境指纹（不能只存 .mp4）

```
OS 与版本 / GPU / CPU / 缩放 / DPI / 字体版本 / 显示器 ICC / 电源模式 /
OBS 场景与编码器 / 帧率 / 时基 / 时区 / 鼠标可见性 / 音频设备 /
录制起止时间 / 键盘宏版本
```

Playwright 官方明确：主机 OS、版本、设置、硬件、电源模式、无头模式
**均会改变渲染**，不同平台甚至需要不同基线。**视频基线不能跨机器合并。**

### ❌ 冲突做法

- **GIF 当高精度测量源** —— 色深与帧损失污染指标，只适合展示
- **只靠逐帧像素相等** —— 压缩、时间抖动、亚像素文本会大量误报
- **让 AI 直接看视频口述结论** —— 应先转成带时间戳的帧集、质量序列、候选簇再聚合

## 四、环境锁定：字体与色彩 ★★

**字体差异是"合法外观变化"，必须进门禁而不是事后忽略。**

FreeType 的 slight hinting、gamma correction、stem darkening、
归一化彩色平衡 LCD 滤镜**均会改变**低字号字形粗细、对齐与彩色边纹。

`font_lock.yml` 应锁：字体文件清单 + SHA256 / 版本 / hinting mode /
LCD geometry 与 filter / DPI / 灰度与亚像素策略 / 文本渲染缩放。

**原版 Windows 字体无法复制到目标渲染环境时** →
把"字体复刻"列为**独立资产任务**，明确允许替换但**必须保留度量**；
**不得用全局模糊掩过字形改变**。

**色彩管理要锁 ICC 与转换意图，不能只设"RGB"**：
Little CMS（`mm2/Little-CMS`，MIT）支持 ICC v2/v4 与快速转换。
原版截图、设计稿、视频帧、新版截图统一记录 profile；
未嵌入 profile 的状态必须是 **`color_profile_unknown`**，**不得冒充无损证据**。

**确定性截图应固定"时间—动画—输入—硬件"四轴**：
禁用动画或停在离散 phase / 隐藏光标 / 冻结时间、随机源、locale /
关闭通知、输入法候选框、自动更新提示 / 固定视口、DPR、滚动位置 /
CI 与本地基线分离。

### ❌ 冲突做法

- **把所有差异区设为 ignore region** —— 直接破坏像素级复刻
- 浮点字体缩放、自动选择最佳字体、主题继承系统颜色、依赖运行时动画当前帧

> **以"锁定基线"为默认，以"允许替换"为明确决策的契约项。**

## 五、私有格式考古 ★★

**应形成"探测 → 假设 → KS 规格 → 双向 round-trip"链。**

| 工具 | 用途 |
|---|---|
| **`kaitai-io/kaitai_struct`** ⭐ | 声明式 `.ksy` DSL，可生成 C++/C#/Go/Java/JS/Python/Rust parser；含 compiler、IDE、visualizer、样本库 |
| `protocolbuffers/protoscope` | schema-free protobuf 线格式汇编/反汇编，支持 round-trip |
| `nccgroup/blackboxprotobuf` | 无 `.proto` 解码、启发式类型猜测、重编码 |
| `CollectiveOSS/binwalk` | 内嵌结构扫描 |
| `imhex-editor/ImHex` | 图形化 hex 模式匹配，人工结构验证 |

**验收口径**：解析成功 · 字段数稳定 · 关键字段值可解释 ·
**round-trip 与原字节相等**（或在明确故意变更处差异可解释）。

**无 schema protobuf/MessagePack/CBOR 必须先做格式指纹再谈语义**；
证据不足时标 **`schema_inferred`**，**禁止据此声称完整复刻协议**。

### ❌ 冲突做法

用 LLM 直接猜整个二进制格式并生成写入器；
只因能解析一个样本就宣称格式稳定；
删除未知尾部字段或校验字段而不记录。

## 六、克隆检测与死代码 ★★

**目标应是"发现历史分叉"，不是单纯删重复代码。**

| 工具 | 用途 |
|---|---|
| `Mondego/SourcererCC` | token-based，block/file/project 粒度 |
| `skyhover/Deckard` | tree-based，聚类 |
| `kucherenko/jscpd` | 多语言快速预扫描 |
| `jendrikseipp/vulture` | Python 死代码（不可达代码与参数置信度 100%） |
| `webpro-nl/knip` | JS/TS 未使用文件、依赖、导出、成员、重复导出 |

**Type-1/2/3 克隆要分层，不能让单一哈希决定合并**：
jscpd 发现近似文本 → 树/令牌方法确认结构相似 → 变量名归一化、
调用图、运行时证据判断是否真正重复。

**只有"相同行为、不同栈、无外部副作用差异"才进 S5 合并**；
"历史权宜实现、副作用不同、时间/线程行为不同"应保留旧实现或先写失败测试。

**死代码检测只产生候选，不能自动删 C# 反射与动态调用** ——
反射、字符串导入、插件入口、资源 key 仍需白名单。
候选须记 `confidence` / `entry_points` / `reflection_evidence` / `test_coverage`。

## 七、规则与技能生态 ★

**应借鉴"任务型技能 + 强证据约束"，不搬运泛风格规则。**

| 仓库 | 状态 | 借鉴 |
|---|---|---|
| `anthropics/skills` | 官方 | SKILL 模板、触发条件、reference/scripts/assets 分层 |
| `ComposioHQ/awesome-claude-skills` | 可核实 | 动作包 + 集成的目录组织 |
| `PatrickJS/awesome-cursorrules` | 可核实 | 规则文件分层、文件类型触发 |
| `google/oss-fuzz` 的 agent-skills | 官方博客可核实 | 先扫基线 → 扩覆盖 → 审查输出 → 不自动提交 |
| `mm0/resultakak/code-archaeology` | **来源不确定** | 仅作检索线索，不纳入依赖 |
| `luanluan1/code-archaeology-skill` | **来源不确定** | 不吸收 |

**技能分四层**：L0 CHARTER 与不可变原则 / L1 阶段门禁 /
L2 领域技能 / L3 项目覆盖层（只覆盖项目事实，不重复 L0/L1）。

每条技能强制 frontmatter：`name` / `triggers` / `inputs` / `outputs` /
`gates` / `tools` / `confidence_requirements` / `failure_policy`。
**禁止"保持代码简洁"这类无门禁规则。**

**规则冲突由证据类型仲裁**，固定顺序：
**原版可执行证据 > 反编译/机器证据 > git/设计/issue 历史 > 语义推理**。

### ❌ 冲突做法

默认规则库会鼓励"用 React 最佳实践重写旧代码"，与"逐功能穷尽"冲突；
全局代码风格规则容易把 `var` 转 `const`、把 Win32 时序改成现代异步，
**却遗漏原版边界**。规则若无证据字段、门禁和失效日期，就只是审美偏好。

## 八、变更影响分析 ★

**没有成熟、跨 WPF-C#/Tauri-Rust/React-TS 的统一影响分析器。**

可借鉴 `jQAssistant/jQAssistant`（扫描源码/字节码/XML/JSON/YAML 导入 Neo4j，
以 concepts、constraints、reports 分析架构）建立跨栈 **evidence graph**。

**边类型**：`implements` / `replaces` / `reads_asset` / `dispatches` /
`renders` / `validates_against`。

变更后查询：哪些原版行为节点失去实现 / 哪些契约测试覆盖已变代码 /
哪些截图区域应重测 / 哪些证据仍引用旧方法。

**输出必须是可追溯查询，不是"影响分数越高越危险"的黑箱。**

## 九、时间旅行 ★

**分层，不要混成一个"确定性"概念：**

| 场景 | 手段 |
|---|---|
| 原版难复现缺陷（计时器/动画/竞态/迁移 bug） | QEMU record/replay、PANDA、S2E |
| 新版业务迁移 | event-sourcing 与快照重放 |
| 截图验收 | 重放可观察的视频/帧序列 |

**完整系统级重放开销大、平台限制多，不应成为日常验收基础设施。**
只在难复现缺陷时做 `replay_capsule`（快照 + 输入 log + 软件版本 + 重放步骤）。

## 十、实施顺序

**A → C → B → D → E → F/G → H/I**

先做**树对齐**和**差异归因**，录屏才有意义；
再固化**字体与色彩**，避免大量假回归；
随后 **Kaitai** 解决资产格式，克隆检测识别合并机会；
最后补规则分层与影响分析。

**顺序倒置最容易落入"工具很多、差异仍无法收工"的状态。**

---

## 十一、与理念冲突的流行默认（写进门禁，不是忽略）

1. **"像素不一致就失败"太粗** —— 会误杀亚像素文本、动画相位、合法字体替换
2. **"像素一致就通过"也不足** —— 整棵结构已变只是凑巧相似时会放过
3. **抗锯齿免疫/区域忽略/模糊基线**只能降噪声，**不能成为豁免**
4. **"功能等价即完成"与"体验细节不能丢"冲突** ——
   结构等价但手感不同应判为**部分完成**
5. **只保留分类名而删除原始截图** → 后续无法复核；
   **只保留截图而不解释** → 无法完成穷尽验收
