# 原版取证参考（驱动 / 截图 / 反编译）

> **核心结论**：工具链最大的失衡不是"新版 Web 侧做得不够"，
> 而是**原版 WPF 行为证据几乎只能靠人工观察**。
> 应把取证前移为独立阶段（S0），而不是继续堆新版测试工具。

---

## 一、原版驱动：FlaUI 主干 + pywinauto 交叉验证

| 工具 | 许可/身份 | 定位 |
|---|---|---|
| **FlaUI**（`FlaUI/FlaUI`） | MIT，.NET UIA 库，支持 WPF / WinForms / Win32 / Store Apps | **主驱动**（`UIA2`/`UIA3` 双提供者） |
| **FlaUInspect**（`FlaUI/FlaUInspect`） | 基于 FlaUI 的实时 UIA 检查器 | 人工**元素探针**，**不进门禁** |
| **pywinauto** | Python GUI 自动化，`win32` / `uia` 双后端 | **交叉验证**；易接入现有 Python 台账 |
| **WinAppDriver**（`microsoft/WinAppDriver`） | WebDriver 协议入口 | **仅** Selenium/Appium 团队兼容层 |
| **Accessibility Insights for Windows**（`microsoft/AccessibilityInsights-Windows`） | Windows 无障碍检查 | 焦点顺序、事件模式采样 |
| **Snoop / WPF Inspector** | WPF 可视化树检查 | ⚠️ **来源不确定**，仅人工调查候选，不进门禁 |

**FlaUI 的价值在"控件身份 + 模式 + 等待"，不是坐标点击。**
WPF 布局由视觉树和逻辑树共同决定，同一业务控件可能含多个装饰层、模板子元素、
不可见节点——**纯坐标点击必然脆弱**。

**双实现策略**：主采集用 FlaUI，pywinauto 对同一窗口交叉验证；
不一致 → 标记 **`tree_conflict`**，**优先人工复核，不自动选边**。

**WinAppDriver 不该为"协议熟悉"而引入** —— 依赖 Windows 10+、开发者模式、驱动服务，
且对复杂 WPF 自定义控件覆盖不如直接 UIA。无 Appium 存量就不用。

### 定位策略稳定优先级（写死，别临时发挥）

```
1. AutomationProperties.AutomationId / 显式自动化标识
2. 稳定业务文本（排除动态序号、时间戳）
3. 控件类型 + 稳定祖先路径
4. 可访问名称 / 键盘助记符
5. x:Name（须附反编译或 XAML 来源）
6. ClassName  ← 只能消歧，不可单独使用
7. 坐标       ← 只能画框、截图、验证布局
```

**⚠️ 坐标点击与"体验细节不能丢"直接冲突** —— 只能作最后兜底。

### 每次抓取至少这些字段

`automation_id` / `xaml_name` / `control_type` / `localized_control_type` /
`name` / `help_text` / `access_key` / `is_enabled` / `is_offscreen` /
`is_keyboard_focusable` / `has_keyboard_focus` / `bounding_rectangle` /
`patterns` / `runtime_id` / `process_id` / `parent_id`

**三者都缺失的元素才进 `unknown`；只有图像可见而树中不可见** →
判断是离屏 / 未实现 UIA 提供程序 / 透明覆盖层 / 自绘内容。

## 二、确定性截图：三种原语分层，不能互相冒充

| 原语 | 特点 | 用途 |
|---|---|---|
| **PrintWindow** | 窗口自绘到目标 DC，最接近"窗口自述" | **视觉主基线** |
| **BitBlt** | 拷设备上下文，受遮挡/阴影/DWM 合成/透明/分层窗口影响 | 屏幕实际呈现对照 |
| **WPF `RenderTargetBitmap`** | 进程内渲染指定 `Visual`，绕开遮挡，设备无关 | 模板 / 资源校验 |
| 客户区裁剪 | — | **布局基线** |

**单一"全屏截图"无法形成基线** —— 三者都要留。

### 必须固定的环境项（写进契约，不是留在脑子里）

```
显示器编号与主屏 / 显示缩放 / DPI 感知模式 / 窗口最大化or恢复 / 边框 /
阴影 / 透明 / 多显示器布局 / 主题与配色 / 字体平滑 / 动画状态 / 光标 /
输入法候选框 / 任务栏遮挡 / 截图时刻 / 窗口激活状态
```

**对持续动画**：固定时长 / 固定帧号 / 事件后延迟采样，
**不把任意时间点单帧当唯一基线**。
原版关不掉动画 → 记 `non_deterministic` + 多帧阈值，**不是无限扩充基线**。

### 图像指标：视觉近似 vs 技术近似分开

- 纯色、线条、图标、字体边缘 → **像素比对**更敏感
- 动画、抗锯齿、渲染差异 → **结构化指标**更稳

同时算：pixelmatch 严格像素差 + SSIM + MSE + 最大单像素误差 +
差异面积占比 + 显著差异簇；再用 UIA 边界矩形**分区**
（标题栏 / 客户区 / 状态栏 / 弹出层分别比）。

**遮罩必须记录** —— 否则会把真实位移悄悄抹掉。

**ShareX / ScreenToGif** 可作人工采集，但**自动化接口、稳态控制、版本化输出
不是其设计目标** → 只取原语，统一进自研重命名/元数据/哈希/台账流程，**不进门禁**。

## 三、源码不全时：反编译与资源考古

| 工具 | 用途 |
|---|---|
| **ILSpy**（`icsharpcode/ILSpy`） | .NET 主考古器：浏览程序集、反编译 C#/VB、PDB 映射 |
| **ilspycmd**（`icsharpcode/ilspycmd`） | 命令行批量导出，**适合写进台账任务** |
| **BAML/XAML 导出** | 与 C# 反编译**并行**——只看代码会丢掉布局结构 |
| **Mono.Cecil**（`jbevain/cecil`） | 遍历 IL、类型引用、属性、特性 |
| **`pefile`**（`erocarrera/pefile`） | 解析 PE 资源目录 |
| **`System.Resources.ResourceReader`** | 读 `.resources` |

**dnSpy** 有历史价值，但维护状态须以官方仓库当前发布为准 ——
**不应把历史版本能力写成现成保证**。

### 资源逐层提取并保留原始字节（不能只存"已理解的内容"）

```
PE 资源目录 → 图标/光标/位图/对话框/菜单/字符串表/版本/manifest
            → .resources → .resx 键级比对
```

- **图标光标**不只提 PNG：还要尺寸、位深、**热点**、分辨率
- **字体**：原始文件、嵌入方式、子集、**许可声明**
- **颜色**不只 RGB：来源主题、状态、透明度

**资源台账默认结论是"未确认"，不是"不存在"。**

### 二进制差异：.NET 优先 IL/元数据级，不是 PE 字节级

同一功能在编译选项、签名、时间戳、段对齐或资源顺序变化后**语义可能仍一致**。
用 ILSpy 输出规范化后的类型/方法文本，或 Mono.Cecil 遍历 IL 再做语义化 diff。

`radiff2`（radare2）只用于判断"**安装包是否变化**"，**不用于解释功能**。

## 四、⚠️ 法律与授权边界（必读）

> **反编译、内存读取、第三方资产复制只适用于团队合法拥有、有权分析
> 并用于授权迁移的目标。**
> 不构成对任何第三方许可、著作权或反规避限制的放宽。

执行前由项目负责人确认：合同 / 开源许可证 / 字体 EULA /
二进制组件许可 / 数据隐私 / 调试授权。

**遇到加密、数字版权管理、许可证校验**：`ownership: self`（自有项目）时**不受此限**；仅 `third_party` 时停止确认 ——
不许通过内存扫描、补丁或注入绕过。

**运行时取证工具**（ProcMon / ProcDump / WinDbg TTD）：
⚠️ Sysinternals 系列**本次未抓取到可引用的一手官方页面**，
仅列为需离线授权使用的运行时取证工具，**不写精确功能声称**。

## 五、明确不吸收 / 不作为主路径

| 做法 | 理由 |
|---|---|
| **纯坐标点击器** | 与"体验细节不能丢"直接冲突，只能最后兜底 |
| **录屏回放当回归** | 无法区分环境噪声与真实差异，只能作人工证据 |
| **图形相似搜索替代控件树 diff** | 容易掩盖控件缺失 |
| **"智能理解界面"的自动工具** | 无可审计元素映射 → 不进门禁 |
| 商业工具（Beyond Compare / JustDecompile / Reflector / dotPeek） | 可辅助调查，但**不应成为可复现管线的唯一依赖** |
| de4dot 等反混淆工具 | **自有项目可自由使用**；仅第三方目标时才是风险信号 |
