# 不变量挖掘 / 差分测试 / 环境锁（第五轮）

> **本轮判断**：前四轮都在补"怎么看得更清楚"，
> 第五轮补的是**"怎么知道哪些是规则"**和**"怎么让原版自己当 oracle"**。

---

## 一、不变量挖掘 ★★★（本轮最高价值单项）

> **S2 穷尽挖掘的本质瓶颈不是"没读完代码"，而是"读完了但不知道哪些是规则"。**

原版里大量约束是**隐式**的：字段范围、字段间线性关系、集合排序、
容器包含、状态不变量。人工做这件事会漏，
**而漏掉的恰好是决定"新版能不能换方案"的那些**。

### Daikon（`plse-cs-uw/daikon`）★

当前 5.8.24；支持 C/C++/C#/F#/Visual Basic 等。
**.NET 需独立前端 Celeriac**（`codespecs/daikon-dot-net-front-end`）。

**支持的模板正是复刻现场需要的**：
`x.field > abs(y)` · `y = 2*x+3` · `array a is sorted` ·
`lst.next.prev = lst` · 集合包含与排序

### 两阶段闭环（不是"跑一遍看报告"）

| 阶段 | 做法 | 产出 |
|---|---|---|
| **一 · 原版轨迹** | 为原版每个 Model 类插 Celeriac 前端 → **FlaUI 驱动覆盖所有业务操作** → `.dtrace` | 候选不变量清单 = **S2 穷尽挖掘的"机器先验"**（告诉你"这里有条规则，去源码里找成因"） |
| **二 · 新版 oracle** | 同一份模板编译成 S7 断言 → 新版进程采集值序列并校验 | S7V 管像素，**这个 oracle 管"内部状态语义"** |

### ⚠️ 最关键边界：Daikon 输出的是候选，不是证明

**Daikon 输出的是"在已观测执行上成立"的候选，不是证明。**

**必须要求 FlaUI 驱动的覆盖率报告作为不变量置信度的分母**：
覆盖率低于阈值的模板**自动降级为 S2 人工复核项，不得直接进 G 门禁**。

> **这是本轮最容易误用的点：把统计规律当规格。**

### `invariant_table` 表头（模板字段）

```
模板类型 | 程序点 | 变量表达式 | 成立样本数 | 总样本数 | 置信度 |
对应源码位置 | 反例路径 | G 门禁判定
```

**最后两列决定能否进门禁**：
无反例路径的候选**只作 S2 线索**；有反例但置信度低的进 S2B BUG。

### 状态机学习

| 仓库 | 用途 |
|---|---|
| `learnlib/learnlib`（Apache-2.0） | 主动式自动机学习：L*/L#/TTT、Mealy/Moore/DFA/NFA；**以原版为黑盒 SUL 主动查询** |
| `cypherpunk/statelearner`（原 `jderuiter/statelearner`） | 更贴近协议/桌面会话场景 |
| `artho/modbat` | 用推出来的状态模型做模型化测试生成 |

产出 `original_state_model.dot` → **S4 契约 + S5 择优比较"两版状态空间是否同构"**。

### `state_model_diff` 三列输出

1. **仅原版可达状态** → 新版缺功能或不可达路径
2. **仅新版可达状态** → 新版引入原版没有的状态，需 S3 裁决
3. **同状态不同转移守卫** ← **最危险**：功能在但**触发条件变了**

## 二、差分测试 ★★★（原版自己当 oracle）

> **差分测试不需要人先写 oracle——原版的行为就是现成的 oracle。**

"原版接受 / 新版拒绝同一输入"或反之 = 一条语义回归。
**这类 bug 不产生崩溃，纯视觉测试与纯单测都抓不到。**

### 与属性测试正交（不是替代）

| | 属性测试（fast-check/proptest） | 差分测试 |
|---|---|---|
| oracle | 人写属性 | **另一实现** |
| 适用 | S5 择优**后**的新实现加固 | 复刻过程中的行为等价性 |

**复刻场景优先差分测试**。

### 三个粒度

| 仓库 | 粒度 |
|---|---|
| **`nezha-dt/nezha`** | 通用语义差异，δ-diversity 引导；已发现 778 类差异 |
| `nalediym/difftest` | 同输入跑两程序，比对 stdout/exit/stderr，逐行 diff |
| `compsec-snu/difuzz-rtl` | 仅当目标含 RTL/CPU 模拟时 |

### ⚠️ δ-diversity：用行为距离选种，不是代码覆盖率

```
每次变异后用「原版与新版行为向量距离」选下一代，
**而不是代码覆盖率** —— 覆盖率引导会让新版"多跑"而忽视"结果不同"。
```

**seed corpus 应来自网络录制（har_diff 结果），不是随机生成。**

### 四类 oracle 判定（S3 的实际输入）

| 类 | 判定 | 处置 |
|---|---|---|
| `real_regression` | 原版成功新版失败（或反之） | **S2B BUG 直报** |
| `workaround_removed` | 原版因旧框架限制的容错路径，新版按正确语义拒绝 | S5 择优正当理由，**必须附 S4 契约变更说明** |
| `nondeterministic` | 浮点/字体/渲染/时序 | 进 S7V 而非 S3；允许容差但**不许无理由豁免** |
| `external_contract` | 录制集过期 | **触发 S0 重采**，不是改 oracle |

**不许改 oracle 让它通过。**

### ⚠️ 未命中率不得把 0 当目标

未命中意味着两条之一：**原版有条死代码路径**（S2B BUG 候选），
或**新版少实现了一条功能**。

## 三、网络与 I/O 录制回放 ★★★

> **原版不是"黑箱截图机"，而是对外的网络客户端 + 本地文件/注册表读写者。**

缺了这部分，S5 择优后"换更好方案"就没有依据——**必须先知道原版到底做了什么**。

| 层 | 工具 | 用途 |
|---|---|---|
| 网络录制 | **`mitmproxy/mitmproxy`** | HTTP/1/2/WS 拦截、保存对话、重放、Python addon（可故障注入） |
| 网络回放 | **`wiremock/wiremock`** | 录制请求响应为 JSON stub，S6 作为新版唯一对外通道 |
| 单测层 | `pigoz/msw-vcr` | cassette 录制回放，替代手工 mock |
| 系统调用 | **`microsoft/Detours`**（MIT）⭐ | 挂 `CreateFile*` / `RegOpenKey*` / `SHGetFolderPath` 等，输出带参数+返回值的调用序 |

### 三类输出

| 文件 | 内容 | 喂给谁 |
|---|---|---|
| `call_seq.jsonl` | `{ts, tid, dll, api, args, ret, err}` | S2M 机器证据的**系统调用层** |
| `fs_ops.csv` | 写过的每个文件：`path, op, bytes, sha256` | S2A 资产清单（补"配置文件默认内容未知"） |
| `reg_ops.csv` | `root\sub\value, type, data, written_at` | S2P 体验参数（识别"首次运行写入的默认值"） |

### `har_diff` 四列

`new_request`（原版发过新版没发）· `missed_response`（新版多取的接口）·
`body_delta`（同 URL 响应结构差异）· `timing_delta`（请求并发拓扑）

**这个输出能在 UI 还没画出来时先判死行为等价性** —— 比像素差更早、更硬。

### 回放的确定性：任何未录制请求直接 FAIL，不是 passthrough

这与 S5 择优相容：**"换成更好方案"只针对实现，不针对外部契约。**

## 四、环境锁 ★★（前四轮忽略得最彻底的一条）

> **S0 证据必须可复现，否则 S2 的所有结论都无法复核。**

原版 WPF 的渲染结果依赖 .NET 运行时、字体、GPU 驱动、DPI 感知模式、系统主题——
**这些以前都不在取证清单里。**

`environment.lock` 必锁 15 项，其中**渲染敏感 7 项**（🔴）：
GPU 驱动 · 显示器 EDID · 显示缩放 · DPI 感知 · 系统主题 · 系统字体 · **电源模式**

### ⚠️ 弱版本声明（必须写死，避免后续误用）

> 可复现构建的"bit-for-bit 相同"**与 Tauri 目标不符**
> （MSVC 与 Rust 工具链均未承诺 bit-for-bit）。
> 本 Skill 采用**弱版本：输入集哈希一致 + 环境声明一致**。

**门禁行为：不一致直接 FAIL，不降级、不警告。**
环境不一致时通过的任何视觉比对都不可信。

**`unknown` 不是"已锁定"** —— 门禁会把它当不一致。

工具参考：reproducible-builds、Nix/Guix（`guix time-machine` 是唯一真能回到任意历史环境的机制）、in-toto、SLSA。

## 六、design token ★★

**DTCG 2025.10 是本轮最实的外部规范利好** ——
不是"从截图生成布局"，而是把颜色、字号、间距、动效曲线
变成跨工具可交换的**单一事实源**，直接对应 S2P 与 S2A 的设计意图层。

| 工具 | 用途 |
|---|---|
| `design-tokens/community-group`（DTCG 2025.10 稳定版） | 规范；支持 theming、Display P3/Oklch、继承与别名 |
| `amzn/style-dictionary` | token 构建系统，多平台输出 |
| Figma REST `/v1/files/:file_key/variables/local` | 拉取变量 |

**`token_diff`**：DTCG 声称值 vs **运行时实际值**（注册表默认值、像素取色）—
这是判断"原版有没有违反自己的设计稿"的**唯一客观依据**。

⚠️ Figma 的 `subscribed_id` 每次发布都变，**必须用 `id` 做主键**，
否则锁定文件会因"每次同步都 diff"而失效。

## 七、❌ 明确不吸收：目标函数冲突（本轮重点辨析）

> **"流行但冲突"的共性是：目标函数不同。**

| 工具 | 它的目标函数 | 为什么冲突 |
|---|---|---|
| `healenium/healenium` | 测试**通过率** | 自愈定位器**绕过** G 门禁的"定位稳定"要求；ML 替换结果不可审计、不可回放 |
| `TestingResearchIllinois/iFixFlakies` | 补丁通过率 | 自动修测试 = 改 oracle 而非实现，S3 失去依据 |
| `TestingResearchIllinois/NonDex` | 实现容错度 | 让测试"更宽松"，与 S7V 冲突 |
| `gmu-swe/deflaker` | 跳过可疑测试 | 与"不轻易收工"相悖 |
| `intel/fMBT` / `juhan/NModel` | — | 已归档 / 死分支，供应风险 |

**本 Skill 的目标函数是"差异暴露率"** ——
要求测试在发现差异时**失败**，且失败必须可归因到具体字段、状态、像素。

### 三个可直接写进门禁的反例

1. 用 Healenium 自愈 → G 门禁"通过"但**新版 DOM 已偏离原版**，S2 成果被悄悄作废
2. 用 iFixFlakies 自动修测试 → 门禁"通过"但**修复的是 oracle 而非实现**
3. 用 Sentry 指纹合并异常 → S2B BUG 清单**少报**，S6 质量被系统性低估

### 可吸收的只有方法论

把 iDFlakies 的"顺序依赖/非顺序依赖"分类与 DeFlaker 的"变更覆盖分析"
**合并进 `coverage_gate`**，产出 `flakiness_report.md`。
门禁行为改为：识别到 flaky 后**强制重跑直至收敛**，
把"收敛次数"作为 S6 执行质量指标 —— **而不是"修复"它**。

### 新增原则（S1 立项章）

> **任何外部工具进入门禁前，必须重写其目标函数以匹配"差异暴露率"，
> 否则只作参考不进门禁。**

**工具不冲突，用法冲突。**
