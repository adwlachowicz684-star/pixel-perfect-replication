# 体验参数挖掘（不记录就会丢失的那些）

> **立场**：tips 多久弹出来、按钮间距多少、动画多长、拖拽阈值几像素——
> **可以不照搬，但必须知道搬前是什么样。**
>
> 这些参数**不会出现在任何功能清单上**，也不会写进 README。
> 它们散落在 XAML 属性、CSS 声明、`Timer.Interval`、代码常量里。
> **不提取 = 迁移时静默丢失 = 用户说"感觉变了但说不出哪里变了"。**

---

## 一、七类体验参数

| 类别 | 典型参数 | 影响 |
|---|---|---|
| **尺寸间距** | Margin / Padding / Width / Height / Gap / Spacing | 视觉密度、手感 |
| **时序** | tips 延迟、防抖 400ms、轮询间隔、自动关闭、冷却 | **节奏感**（最易丢） |
| **动画** | Duration / Easing / KeyTime / 过渡曲线 | 顺滑度 |
| **阈值** | 拖拽死区、滚动阈值、最小位移、容差 | **操作手感**（最易丢） |
| **颜色透明度** | Background / Opacity / Brush / 主题色 | 视觉一致性 |
| **字体** | FontSize / FontFamily / LineHeight / LetterSpacing | 信息密度 |
| **层级 / 圆角描边** | ZIndex / CornerRadius / BorderThickness | 层次与风格 |

**还有一类不在源码里**：系统级默认值（Windows 默认按钮高度、滚动条宽度、
系统字体度量、任务栏高度）—— 这些靠**运行原版实测**，见第五节。

---

## 二、提取手法

### 手法 1：脚本自动提取（首选）

```bash
python3 scripts/param_extract.py --src <原版src> --out work/ledger/params-old.csv
python3 scripts/param_extract.py --src <新版src> --out work/ledger/params-new.csv
python3 scripts/param_extract.py --compare --old params-old.csv --new params-new.csv --gate
```

脚本支持 XAML / C# / CSS / TS-TSX / Rust / JSON，输出 CSV 与三类差集：

| 差集 | 含义 |
|---|---|
| 原版有、新版无 | **会丢失的体验**（硬阻塞，必须落 P-N 卡） |
| 值不同 | 有意变更 or 漂移，必须判定 |
| 新版多出 | 记入反向清单（勿删） |

### 手法 2：关键词全库扫（脚本扫不到的手工补）

```bash
grep -rn "Margin\|Padding\|CornerRadius\|BorderThickness" --include=*.xaml .
grep -rn "Interval\|Duration\|Delay\|debounce\|Throttle\|防抖\|延迟\|轮询" --include=*.cs .
grep -rn "Threshold\|DeadZone\|死区\|阈值\|epsilon\|Tolerance" --include=*.cs .
grep -rn "transition\|animation\|cubic-bezier" --include=*.css .
```

### 手法 3：系统资源与样式表（XAML 的"样式资源键"）

```python
re.findall(r'x:Key="(\w+)"', t)     # 样式资源键，再往上回溯 <!-- 注释 -->
```

**⚠️ 静态资源引用**（`{StaticResource xxx}`）脚本提取不出来（值在别处定义），
必须顺着资源键找到真实定义——**这类往往是一整个主题的参数集**。

## 三、三个实证陷阱（脚本已处理，手工挖时也要注意）

| 陷阱 | 后果 | 处理 |
|---|---|---|
| `\bThreshold\b` 抓不到 `dragThreshold` | 驼峰命名的参数**全部漏掉** | 匹配**包含关键词的完整标识符**（`\w*keyword\w*` + 忽略大小写） |
| `FontSize`(XAML) 与 `fontSize`(TSX) 当两个参数 | 差集全是噪音，真差异看不见 | **键归一化**：小写去分隔符 |
| `TimeSpan.FromMilliseconds(180)` 被当成秒 | **180 变 180000ms** | 先判 `millisecond`，再判 `second` |
| `Margin="8,4,8,4"` 被逗号截断成 `8` | 四元组只拿到第一个数 | 优先取**引号内整段** |

**还有一个脚本处理不了、必须人看的**：

> **XAML 是「左,上,右,下」，CSS 是「上 右 下 左」。**
> 数值集合相同不代表等价——脚本会提示"顺序约定可能不同"，但**别直接抄**。

## 四、每个参数落一张 P-N 卡

**模板见 `../assets/体验参数清单模板.md`。** 四栏必须全填：

```
原值 / 新版值 / 差异理由 / 性质
```

**性质五选一**（决定要不要照搬）:

| 性质 | 含义 | 处置 |
|---|---|---|
| **等比迁移** | px → px，语义不变（如圆角 4 → 4） | 照搬 |
| **需缩放** | 受 DPI / 字体度量 / 设备像素比影响（如 13px 在高 DPI 屏） | 换算后记下公式 |
| **平台惯例** | Windows 惯例 ≠ Web 惯例（如默认按钮高 28 vs 32） | 记录差异，按新平台惯例定 |
| **技术权宜** | 当年受限于技术（如手动累加高度） | ⭐ 换成更好的方案 |
| **有意变更** | 明确要改（有批准） | 登记 + golden 标注 |

## 五、源码里没有的：运行原版实测

有些参数**代码里根本没有**，只有跑起来才看得到：

| 参数 | 怎么测 |
|---|---|
| tips 实际弹出延迟 | 录屏数帧 / 打点计时 |
| 动画真实时长 | 录屏按帧数 × 帧率 |
| 滚动条宽度、系统字体度量 | 原版运行实测 + 截图量像素 |
| 默认控件尺寸（未显式设 Width 的） | 截图量像素 |
| 双击判定间隔、长按判定 | 手动试 + 计时 |

**这类参数的证据等级标 `runtime-measured`**，写进证据卡并附测量方法。

## 六、常见遗漏清单（逐项自检）

- [ ] tips / tooltip 的 **ShowDelay / HideDelay / 自动关闭时长**
- [ ] 各类**防抖与节流**（输入防抖、滚动节流、连锁发送防抖）
- [ ] **拖拽死区**与落点容差（不是"支持拖拽"一句话）
- [ ] **自动滚动**触发边界与速度
- [ ] 双击 / 长按 / 三击的**时间阈值**
- [ ] 轮询间隔、超时、重试次数与退避
- [ ] 动画时长与**缓动曲线**（不只是时长）
- [ ] 未显式设置的**系统默认值**（靠实测）
- [ ] 主题色 / 透明度 / 禁用态 / hover 态的**具体数值**
- [ ] 快捷键的**判定窗口**（如连按间隔）

> **一句话**：功能决定"能不能用"，参数决定"用起来像不像"。
> 功能全对但参数全丢，用户的感受就是"说不出哪里不对"。
