# 证据等级

> **规则**：等级决定这条能不能成为迁移依据。**assumption 不得成为迁移决定。**

---

## 一、七级

```
runtime-verified   > dynamic-trace > static-code > resource/declaration
                   > documentation > commit-history > assumption
```

| 等级 | 怎么来的 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **runtime-verified** | 真跑原版观察到的 | 直接作为 golden，最高权威 | — |
| **dynamic-trace** | 日志 / 抓包 / 文件前后变化 / 断点 | 作迁移依据 | — |
| **static-code** | 读代码推断 | 需与运行证据交叉 | 单独不足以判定"真的生效" |
| **resource/declaration** | UI 声明、schema、资源文件 | 证明"承诺了什么" | 不能证明"实际做了什么" |
| **documentation** | README、使用说明 | 作为线索 | **可能是旧版遗留，必须验证** |
| **commit-history** | git blame / PR / issue | 解释"为什么" | **不能推翻当前可观察行为** |
| **assumption** | 猜的 | ❌ 什么都不能决定 | 一律进 unknown |

---

## 二、三条硬规则

1. **每个非平凡条目至少要有 `static-code` 级证据。**
2. **只有 `documentation` 级证据的条目，必须先补运行或静态证据。**
3. **`assumption` 级条目一律进 unknown 清单**，S7 门禁（G3）会阻塞。

---

## 三、"真的生效吗"（static-code 最常见的盲区）

读代码能推断意图，但**不能证明真的生效**。这几类必须升级到运行证据：

| 场景 | 为什么静态证据不够 |
|---|---|
| 图标写入 | 编码错了可能根本不生效（UTF-16LE vs UTF-8） |
| 系统通知 | 没有 `SHChangeNotify`，改了不刷新 |
| 边界处理 | 代码写了分支，但输入可能根本走不到 |
| 第三方库行为 | 库的行为可能与文档不符（如 Markdig `ColumnIndex` 恒 -1） |
| 并发时序 | 静态看不出来，必须压测或日志佐证 |

---

## 四、常见误判

| 误判 | 纠正 |
|---|---|
| 把 README 当事实 | 实证：TipsPanel 描述 3 个根本不存在的功能（旧版遗留） |
| 把 commit 历史当现状 | 历史解释"为什么"，**当前行为优先** |
| 把注释当架构事实 | 实证：注释说"所有写入者都在同一进程内"，实际 `--mcp` 是独立进程 |
| 把"代码里有这段逻辑"当生效 | 必须问"到底生不生效"（编码、通知、边界） |
| 猜一个"应该就是这样" | 一律算 assumption，进 unknown |

## 五、证据卡的写法

```yaml
id: EVD-LOGIN-021
subject: 登录失败时用户名保留
layer: 界面资产 / 逻辑 / 行为
evidence:
  - type: runtime-observation
    source: legacy-app@build123
    trace: sessions/login-failure.json
    excerpt: "输入 user=u、pwd=wrong 后，密码清空，用户名保留"
  - type: static
    location: src/LoginViewModel.cs:88-102
    excerpt: "PasswordBox.Clear(); UsernameBox.Focus();"
status: verified
nature:
  code: original-intent
  reason: 减少重复输入，提升可访问性
migration:
  target: NewLoginForm.username
  preserve: true
  deviation_allowed: false
```

模板见 `../assets/证据卡模板.yaml`。
