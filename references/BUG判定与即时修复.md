# BUG 判定与即时修复

> **用途**：挖到可疑处时，判断"要不要当场修"的速查表。
> 详细流程见 `../flow/S2B-BUG与审查发现.md`。

---

## 一、三问定类别

| 问 | 答案 | 类别 |
|---|---|---|
| 这个行为在原版里就有问题吗？ | 是 | **B1 原版 BUG**（修了 = 行为变更） |
| 是迁移侧自己的问题/回归吗？ | 是 | **B2 当前版 BUG**（直接修） |
| 现在能跑，但会不会出事？ | 会 | **B3 审查发现的风险** |
| 是执行阶段新引入的？ | 是 | **B4 迁移引入**（立即修） |
| 看着像 BUG，但不确定 | — | **B5 存疑**（先确认，**不许默认当 BUG 修**） |

---

## 二、是真 BUG 吗（先过这一层）

```
去掉/改掉它，体验或正确性会受损吗？
  会   → 设计意图，不是 BUG（转入功能清单，preserve）
  不会 → 真 BUG，按下面分诊
  判不了 → B5，进 unknown
```

### 看着像 BUG、其实是设计的常见情形

| 看着像 BUG | 实际原因 |
|---|---|
| 拖到空白区 `toast` 拒绝 | **其实是通路**：跨栏拖到空白 = 换栏移动 |
| 只加 `+s` 不加 `+h` | 加 `+h` 会让文件夹被隐藏 |
| 双端滚动 33ms 防抖 | 防振荡，删了就两端来回微调 |
| 退出前强制落盘 | 异常退出兜底 |
| 官方 API 失败后直写 | 环境兜底（保证极端情况仍能写） |
| 读不出来还继续跑 | ⚠️ 这条**不是**设计，是 bug（应中止而不是用默认值） |

## 三、当场修还是进批次

### 当场修（五条全满足）

| # | 条件 | 反例 |
|---|---|---|
| 1 | 单个函数 / 单个文件内 | 需要改 3 个调用点 → 不算 |
| 2 | 不涉并发模型、数据格式、跨端契约 | 涉及事务边界 → 不算 |
| 3 | 有明确可执行的验证方式 | 只能"手动试试" → 不算 |
| 4 | 不需要重构 | 需要先抽统一入口 → 不算 |
| 5 | 不打断当前文件的深挖主线 | 要切走半小时 → 不算 |

**当场修的动作**：直接在卡片【修复方案（新版）】里写出**新版怎么写**，
改完验证、打勾、回到挖掘。

### 进批次（任一命中）

跨多模块 · 涉锁/事务/编码/跨平台 · 需重构 · 需 golden 批准的行为变更 · 需补证据才能验证

---

## 四、⚠️ 修原版 BUG = 有意行为变更

**原版的 BUG 也是用户当前体验的一部分。**
复刻目标是"用户原先的体验一点不丢"——修 BUG 意味着新版与原版不一致。

所以修 **B1** 必须：

1. 卡片里写【行为变更登记】：变更前 / 变更后 / 影响范围 / 批准人
2. golden 对应项标注 `intentional-change`
3. 若决定**不修**（保持与原版一致），也要写明理由，防止以后重新挖出来当新发现

**不登记的 BUG 修复 = 静默改需求。**

## 五、简单 BUG 的修复方案怎么写（模板）

```text
【修复方案（新版）】
  收敛为 sys::validate_name()，三处调用点统一调用：
  - 拒绝 "." / ".." / 纯点串
  - 长度 ≤ 120
  - 错误文案统一为 "名称不合法"
  ⚠️ 不改动 UI，不改动数据格式，不涉并发

【验证方式】
  - 符号计数：定义 1、引用 3
  - 用 ".."、"a"*121 分别走新建与改名，均被拒且文案一致
  - 跨端校验无新增错误
```

**写方案的三条纪律**：

1. **写"新版怎么写"，不是"修一下"** —— 落到具体函数与调用点
2. **边界行为要对齐** —— 换实现方式时最容易丢的，就是丑实现里藏着的边界处理
3. **不许借修 BUG 顺手重构** —— 需重构的记 I-N，跟着重写一起做

## 六、审查发现（B3）的四个高发区

| 区 | 必问 |
|---|---|
| **并发** | 几个进程会写这份数据？读-改-写在同一临界区吗？锁可重入吗？异常会放锁吗？ |
| **数据** | 读不出来会静默用默认值吗？是唯一副本吗？写入前有拦截吗？ |
| **跨平台** | 路径含空格？编码按 BOM 判定？会吃掉别人写的内容？属性操作有副作用？ |
| **整合** | 这段逻辑别处写过吗？三份相似实现 = 迟早漂移 |

**实证三个"审查才发现"的问题**（都不是功能没实现，是实现了但会出事）：

| 问题 | 怎么发现的 |
|---|---|
| `&String` vs `&Path` | diff 双方而非只看无冲突（硬编译错误） |
| 名称校验三份不一致 | 找整合机会时扫出来（真 bug：`..` 能写进去） |
| `save_records` 在事务外 | 括号匹配定位闭包范围（竞态落点） |

## 七、严重度

| 级 | 含义 | 门禁 |
|---|---|---|
| **P0 阻断** | 数据丢失 / 崩溃 / 功能不可用 | 硬阻塞 |
| **P1 严重** | 竞态、静默覆盖、异常路径出错 | 硬阻塞 |
| **P2 一般** | 边界处理、文案、体验不一致 | 应修，不阻塞 |
| **P3 轻微** | 命名、冗余、可读性 | 记入即可 |

`[险]` 标记：涉及数据不可逆损失的额外打标，与 P0/P1 一起优先。
