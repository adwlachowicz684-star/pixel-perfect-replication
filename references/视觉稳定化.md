# 视觉稳定化（不稳定元素逐类处理表）

> **核心立场**：不稳定元素必须**逐类处理，不能用高阈值统一糊过去**。
> 调大阈值 = 默许漂移 = 把"像素级"悄悄改成"大致像"。

---

## 一、七类不稳定源与处理方式

| # | 不稳定源 | 正确处理 | ❌ 禁止 |
|---|---|---|---|
| 1 | **字体渲染 / 抗锯齿** | 固定字体版本、固定渲染环境（Docker 镜像）、字体预加载、统一 hinting | 调大阈值 |
| 2 | **动画 / 轮播 / 骨架屏 / indeterminate progress** | 禁用动画配置、等稳定终态、或确定性替身 | `sleep(1000)` 后截图 |
| 3 | **光标 / 文本选择态 / 滚动条** | 隐藏光标、清除选择、固定滚动条样式 | 遮罩整个容器 |
| 4 | **时间戳 / 相对时间 / 随机 ID / UUID** | **固定时钟**（clock fixture）、固定随机种子、mock | 用大阈值吸收 |
| 5 | **头像 / 第三方 widget / CDN 图片** | fixture 数据或局部遮罩 | — |
| 6 | **WebGL / 图表动画 / 视频封面** | 单测渲染配置与帧，**不用截图替代** | — |
| 7 | **异步加载的数字 / 骨架屏残留** | 语义断言等待目标状态（如 `aria-busy=false`），不等固定时间 | 固定等待 |
| 8 | **字体未加载完（FOUT / FOIT）** | 字体预加载 + 等字体 ready 再截图 | 截图时字体还是回退字体 |
| 9 | **图标 / 图片异步加载** | 等资源加载完成（`decode()` 或资源级语义断言） | 截图时还是占位图 |
| 10 | **音效 / 动画触发的视觉反馈** | 用状态夹具直接置到该状态，不依赖播放 | 等音效播完再截 |

## 二、必锁的环境项（写进统一 fixture）

```
viewport          宽高
deviceScaleFactor 设备像素比（高 DPI 必须显式设）
zoom              缩放
font              字体名称@版本，预加载
font_ready        等字体加载完成再截图（防 FOUT/FOIT）
assets_ready      图标/图片等资源加载完成再截图
locale            语言
timezone          时区
theme             明暗
reduced_motion    reduce / no-preference
clock             固定时钟（如 2026-09-17T09:00:00+08:00）
seed              随机种子
```

**⚠️ 高 DPI 是实证踩过的坑**：未处理会导致截图/取色**错位**——
这不是"差异"，是 diff 出来的假结果，必须先锁 DPR 再比对。

---

## 三、遮罩纪律 ⭐

**只遮"明确不属于该视觉契约"的区域**，并在证据卡写明遮蔽范围。

**反例（绝对禁止）**：一项功能的核心体验就是头像或倒计时，
却把它遮掉来让 diff 变绿 —— **遮罩破坏了复刻目标本身**。
此时应换 fixture（固定头像图、固定时钟），而不是屏蔽。

**遮罩清单要能自证**：每个遮罩项写清"为什么这个区域不属于本状态的视觉契约"。

---

## 四、等待策略：语义断言 > 固定等待

```
❌ page.waitForTimeout(1000)
✅ await expect(locator).toHaveAttribute('aria-expanded', 'true')
✅ 等 animate 进入稳定终态
✅ 用确定性替身替换 indeterminate 动画
```

**理由**：固定等待在 CI 慢机器上会偶发失败，
然后有人就会去调阈值——**阈值一旦被为了"让它过"而调大，视觉门禁就死了**。

---

## 五、阈值的分层定义（不是单一全局值）

| 类别 | 阈值 | 说明 |
|---|---|---|
| 核心图标、像素标尺、图表轴、精确对齐项 | **0** | "像素级"的字面含义 |
| 普通组件 | 按证据定 | 必须在状态清单里写明理由 |
| 动画、时间戳、头像 | **遮罩/fixture，不给阈值** | 给阈值 = 默许漂移 |

**⚠️ 库级参数 ≠ 项目阈值**：pixelmatch 的 `threshold`（0-1，默认 0.1）
和 `includeAA`（是否忽略抗锯齿像素）是库的调节旋钮，
**项目应定义状态级阈值并写在 `visual_state.yaml` 的 `comparison.threshold`**。

---

## 五·补：截图比不出来的那些（体验参数）⭐

**静态截图看不出"tips 晚了 200ms""拖拽死区小了 2px"。**
实测样例里，新版对 `showdelay / interval / debounce / dragthreshold` 全部 0 命中——
截图上 tooltip 根本没弹，看起来一切正常，但手感已经变了。

所以涉及时序与阈值的状态，**必须有 P-N 卡，不能只靠截图**：

| 截图负责 | 参数负责 |
|---|---|
| 长什么样（布局、颜色、层级） | 节奏与手感（时序、阈值、动画曲线） |

比对手段：`param_extract.py --compare --old ... --new ... --gate`

## 六、自检清单（每个视觉状态跑之前过一遍）

- [ ] 时钟固定了吗？随机种子固定了吗？
- [ ] 字体版本锁了吗？DPR 显设了吗？
- [ ] 动画禁用了或等到终态了吗？
- [ ] 光标与选择态清除了吗？
- [ ] 每个遮罩项都写了"为什么不属于本契约"吗？
- [ ] 等待是语义断言而不是固定时间吗？
- [ ] 阈值是按状态定的还是抄的全局值？
- [ ] **字体预加载并等 ready 了吗？**（否则截到回退字体）
- [ ] **图标/图片等资源加载完成了吗？**（否则截到占位图）
- [ ] **涉及时序/阈值的状态，有没有对应 P-N 卡？**（截图比不出来）
- [ ] **涉及音效/动画反馈的状态，是用夹具置位还是等播放？**（应是前者）
- [ ] 体验参数双侧差集跑过了吗？（`param_extract.py --compare --gate`）
