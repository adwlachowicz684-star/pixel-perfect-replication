# 运行时取证、二进制覆盖与 AI 边界（第八轮）

> **本轮最大缺口不是静态分析，而是两件事**：
> ① **不改写原版即可取得可重放的行为证据**；
> ② **用证据反证新实现是否遗漏、改坏或过度迁移**。

---

## 一、六层反证链（不是按项目名平铺工具）

```
1 原版身份     → 哈希、文件元数据、清单、调试信息、资源版本、DAT 校验
2 可观测运行   → Frida、DynamoRIO、Pin、Qiling、Unicorn、.NET/Linux 诊断
3 静态覆盖     → 二进制 diff、函数匹配、反编译器、符号执行、污点分析
4 行为等价     → 差分测试、记录回放、黄金轨迹、属性测试、性能门禁
5 环境兼容层   → Wine/DXVK/vkd3d、DOSBox-Staging、Dolphin、PCSX2、RPCS3、Wasm
6 人机协同理解 → 代码打包、导航、反编译假设、代理辅助（**默认全是待验证假设**）
```

> 缺少运行时取证，所谓"逐文件复刻"会**退化为反编译器可读化之后的二次开发**。
> 缺少二进制 diff，就无法回答"**原版究竟有多少个行为单元、哪些已被覆盖、
> 哪些只是名字相似**"。

## 二、A 类：运行时取证层（默认开启，不是偶发调试）

### 2.1 原版行为基元 —— 最小工作单元

> **最小工作单元不是"一个功能点"，而是行为基元。**

```
输入 / 触发条件 / 内部状态 / 可观察副作用 /
输出 / 时序 / 异常路径 / **对其他状态的副作用**（最容易漏）
```

### 2.2 工具分工（**Detours 降为 Windows 旁路**）

| 工具 | 定位 | 何时用 |
|---|---|---|
| **Frida** | **默认主入口**：跨平台黑盒注入、钩任意函数、热改脚本 | Win/macOS/Linux/Android/iOS/FreeBSD/QNX |
| **Qiling** | **完整执行环境**：可执行加载、动态链接、系统调用、IO、异常钩子 | 答"给定环境和文件系统时这个原子程序返回什么" |
| **Unicorn** | **只模拟 CPU** | 把已恢复状态放入单元测试，验**单个算法片段** |
| DynamoRIO / Pin | 指令/基本块/缓存/内存追踪 | Frida 不能稳定附加时的后手，**非通用替代** |
| Detours | Windows **持久化二进制桩** | 仅此场景，不再是取证核心 |
| dotnet-counters/trace/dump/gcdump | .NET 宿主运行时 | ⚠️ 原版 **.NET Framework** 不能假设 .NET Core 工具全适用 |
| bpftrace / LTTng / SystemTap / perf | Linux 追踪 | Windows 应映射为 **ETW/WPR**，**不许宣称 eBPF 可观察 Windows** |

**推荐组合**：**Qiling 取证 → Unicorn 冻结 → 属性测试反证**

### 2.3 ⚠️ 三条硬纪律

1. **Hook 数据 ≠ 语义事实**
2. **Frida 脚本不得修改游戏状态并声称观察到原版** —— 只读观察、参数快照、受控桩注入**必须分开**
3. **采样失败以"失败计数 + 未覆盖基元清单"收口** ——
   **不能以"脚本运行成功"替代功能覆盖**（移动端/DRM/反调试场景尤其容易踩）

每个探针必须绑定：**原版构建、进程位数、模块基址、符号来源**。
地址不含基址 = 换个机器就对不上。

```bash
python3 scripts/runtime_forensics.py --primitives
python3 scripts/runtime_forensics.py --init ledger/runtime_forensics.csv
python3 scripts/runtime_forensics.py --check ledger/runtime_forensics.csv --gate
```

> 模拟结果只能证明"**在该模型和桩下**"的行为，
> **不能**证明物理硬件上的像素或音频完全一致。
> 风险：外部状态、浮点精度、线程竞争、系统时间、未建模系统调用。

## 三、B 类：二进制覆盖 —— 从"能反编译"到"函数集合已穷尽覆盖"

### 3.1 工具（**都有附加约束，不许宣传成零成本**）

| 工具 | 许可 | 约束 |
|---|---|---|
| **google/bindiff** | Apache-2.0 | ⚠️ 要求 **IDA 9.0+** —— **不能宣传成无商业依赖** |
| **joxeankoret/diaphora** | **AGPL-3.0** | ⚠️ 要求 **IDA 7.4+**（支持 6.8–9.4）；AGPL 需法务确认 |
| **clearbluejar/ghidriff** | 按仓库确认 | ✅ **降低 IDA 依赖的关键候选**（基于 Ghidra，可 CI 化） |
| avast/retdec | MIT | 第二套伪代码**交叉验证**，不取代 Ghidra/IDA |
| angr / Triton / KLEE / Manticore / BAP | BSD-2 / Apache-2 | 符号执行与污点 |

### 3.2 三条硬纪律

1. **禁止把自动映射直接写入规范** —— 必须保留
   `match_type / confidence / similarity / algorithm / manual_review`
2. **三个工具结论冲突时不得自动择多** —— 要补插桩样本、类型恢复、调用约定或调试信息
3. **二进制匹配答"函数是否仍是同一份逻辑"，不答"渲染结果是否一致"**

> 变量名、注释、控制流相似都可能是编译器、混淆、内联或重构的产物。
> 只有与真实输入输出、错误路径、性能轨迹、视觉输出结合，才接近像素级覆盖。
> → 二进制 diff **产出待验假设**，不能成为"已完成迁移"的证据。

### 3.3 关键判读

| 项 | 含义 |
|---|---|
| **unmatched_primary** | 原版有、新版无 → **即漏做**（最危险） |
| unmatched_secondary | 新版多出 → 需说明是增强还是多余，**不许默认无害** |
| low_confidence | 必须进**人工队列**，不得自动采信 |

```bash
python3 scripts/binary_coverage.py --tools
python3 scripts/binary_coverage.py --check ledger/binary_coverage.csv --gate
# 🔴 原版有、新版无 1 条（行 [1]）→ 即漏做
```

### 3.4 符号执行：只能证明有限语义

> **不许宣称证明任意输入上全同。**

「等价」必须写成**可证伪命题**：约束输入长度、元素范围、稳定性、内存所有权、
异常与写回；RNG 则约束种子、计数器、字节序、浮点精度与舍入。

求解超时与未建模外部调用须进 `assumptions` / `limitations`。
**不能把 SMT 的 sat/unsat 直接转成"视觉完全一致"**。
图形管线、浮点渲染、并发、网络 → 宜用受控差分测试与记录回放。

## 四、C 类：AI 只有"提出假设"的权限

### 4.1 七道强制门（缺一不可）

| 门 | 要求 |
|---|---|
| 1 原版侧 | AI 不得访问未经许可的私有代码/原始素材；取证须在**隔离环境**产生 |
| 2 任务侧 | 只描述**可观察行为**与证据约束，**不许让 AI 猜原版实现** |
| 3 生成侧 | 必须区分「反编译器事实 / 运行观测 / 推断 / 未知」，逐函数给引用地址或文件行；**禁止生成未引用的 API、数值、资源路径、表项、魔法常数** |
| 4 编译侧 | 必须过目标平台/架构/优化级别/依赖锁版本的 CI；**失败日志不得被 AI 重新解释为"接近正确"** |
| 5 测试侧 | 确定性 / 差分 / 属性 / 回放 / 视觉 / 音频 / **帧时间分布**交叉验证 |
| 6 复核侧 | 状态机、渲染、物理、音频、RNG、存档、计时、网络、错误处理**由人复核**；高风险差异即使测试通过也要二次审查 |
| 7 收工侧 | 只有门禁全绿且未覆盖项为零或经批准才可收工；**AI 的"完成"声明无效** |

```bash
python3 scripts/context_pack.py --gates
python3 scripts/context_pack.py --scan <目录> --gate        # 密钥扫描
python3 scripts/context_pack.py --pack src --out m.json --budget 200000
python3 scripts/context_pack.py --review-check changes.json --gate
```

### 4.2 反编译器 MCP 只开放最小只读工具面

**允许**：列函数、读反汇编/伪代码、查交叉引用、读注释、导出已命名工件
**禁止**：改名、打补丁、保存项目、执行脚本、远程下载、调用外部 LLM 插件

> MCP 的作用是把反编译器变成**证据检索器**，不是让模型成为开发者。

上下文过长会导致模型遗漏细节 → 先**结构化检索**，再向小窗口提交**单函数证据**。

> ⚠️ 若搜索索引、反编译器与运行样本给出**三种不同解释**，
> 应把**冲突本身**保存为待验证据，**而不是让模型在对话中"最终裁定"**。

### 4.3 上下文打包必带 manifest

任何被打包目录都必须生成 `context-manifest.json`：
包含文件数、排除规则、令牌估计、**git 状态**、**密钥扫描结果**、提示模板版本。

候选工具：repomix、gitingest、code2prompt、yek、files-to-prompt（均需封装）

> ⚠️ 扫描基于正则，**不能保证找出全部敏感信息** —— 仍需人工复核。
> **禁止把密钥投喂给模型。**

### 4.4 AI 迁移代理只能生成候选 diff

`aider` / `OpenHands` / `SWE-agent` / `plandex` —— **不得拥有收工资格**。
它们倾向生成**看起来完整、可编译、可解释**的代码，
**而不是证明与原版一致** —— 容易把同名 API、流行库用法、训练先验当原版行为。

输出必须附加：提议者身份、上下文包哈希、目标文件、变更集、编译日志、
测试日志、反编译器证据、**人工签名**。

## 五、D 类：遗留代码检索（从文本匹配到可复现证据检索）

| 用途 | 工具 |
|---|---|
| 大规模正则/字面量搜索 | **Zoekt**、Livegrep（Hound 为轻量备用，活跃度较低） |
| 交叉引用 | OpenGrok（CDDL-1.0） |
| 符号表 | **Universal Ctags**（GPL-2.0） |
| 语义索引协议 | **SCIP** / stack-graphs |

**每次搜索都应生成可重放查询**：查询表达式、仓库 commit、路径过滤、语言、
命中前后文、结果数、查询时间。**不要只保留 LLM 读到的摘要。**

> 搜索命中不是理解 —— 必须再展开定义、调用点、覆写、实现、资源引用和测试。

⚠️ C/C++ 宏与模板、C# partial 类、动态加载、反射调用**可能漏报** →
**运行时插桩发现的符号应回灌搜索，静态搜索命中的符号也应回灌运行时验证**。

## 六、E 类：ABI / API 兼容性

`libabigail`（Apache-2.0 w/ LLVM exception）· `abi-compliance-checker`（LGPL-2.1+）
· `abi-dumper` · `cargo-semver-checks` · `revapi`（Java）

> **ABI 检查只在"对外接口是首要资产"时才成为收工门禁。**

对自包含 WPF 或游戏可执行文件（导出符号极少、无公开 SDK），
**ABI 门的价值低于二进制覆盖、运行轨迹和视觉/帧时间门**。

若复刻产物是供第三方调用的库/插件 API/原生组件/跨语言边界 → 必须建 baseline。
⚠️ **C++ ABI 比较只能验证接口，不能验证语义。**

## 七、F 类：帧时间与性能（**不能只比均值**）

`Tracy`（BSD-3，游戏首选）· `Remotery`（Apache-2）·
`Optick` / `easy_profiler`（MIT，活跃度较低，不作唯一门禁）·
`criterion.rs` · `asv` · `hyperfine` · Bencher / CodSpeed（CI 趋势，涉服务边界）

> **只测平均帧率会把"偶尔卡顿"平均掉。**

门禁至少保存：**p50 / p95 / p99**、帧间隔直方图、GC/磁盘/着色器编译事件、
调用栈、失败样本、可重放录像，并把硬件与驱动写进 `environment.json`。

**新实现与原版不应直接比较原始毫秒数**（硬件/驱动/渲染 API/调度不可控），
应比**相对帧时间分布、卡顿频率、资源加载阶段和受控场景**。

> 若新栈只有"平均更快"但 **p99 更差或卡顿更多**，**不能判定体验更好**。

## 八、G/H/I 类：让"不可启动的原版"变成"可观测的原版"

### 8.1 兼容层

| 目标 | 工具 |
|---|---|
| Windows / 旧 DirectX | **Wine**（LGPL-2.1）、**DXVK**（zlib/libpng）、vkd3d-proton、MoltenVK、Zink |
| DOS | DOSBox-Staging（GPL-2.0） |
| 主机平台 | Dolphin、PCSX2、RPCS3 |
| 可重入逻辑/解码器 | Emscripten、wasmtime、wabt |

每个模拟器环境必须生成 `emulator-evidence.json`：
原版构建、镜像/ROM 校验、**BIOS/固件合法性**、版本、视频/音频后端、
时钟/速度设置、控制器映射、随机种子、录屏与日志路径。

> 兼容层只能作为"**可获得运行样本**"的工具，
> **不能自动成为像素或音频真值**。

### 8.2 构建身份是取证链第一道闸门

`original-build.yaml`：来源合法性说明、发行平台、区域/版本、文件哈希、体积、
时间戳、数字签名/清单、PDB/调试信息、资源版本、DAT 名称与校验和。

No-Intro（DAT-o-MATIC）与 redump 提供 DAT 与校验规范 ——
⚠️ **不应被包装成 GitHub 开源仓库**；商业 ROM/ISO 的获取须遵守适用许可。

### 8.3 转译器只解决"机械承载"

`c2rust` / `c2go` / `cxgo` 产物通常保留指针、unsafe、生命周期和不可读结构。
转译后**必须**经反编译解释、静态清理、单元测试、差分测试和人工重构。

> **不得因为编译通过就替代原版规范。**

## 十、❌ 本轮新增冲突项

| 做法 | 为什么冲突 |
|---|---|
| **AI 宣布"已完成/已修复"** | 与"S2 不许轻易收工"直接冲突；AI 无收工资格 |
| 把失败日志重新解释为"接近正确" | 编译失败就是失败 |
| 让 AI 猜原版实现 | 会产生看起来合理但与原版不同的行为 |
| 生成未引用的 API / 数值 / 魔法常数 | 无法回溯，等同编造 |
| 把自动二进制映射直接写入规范 | 跳过了人工复核 |
| 三工具冲突时自动择多 | 多数不代表正确，须补证据 |
| 宣称符号执行证明了全程序等价 | 只能证明有限语义 |
| 只比平均帧率 | 把卡顿平均掉了 |
| 用模拟器结果冒充原版硬件行为 | 精度与时序可能不同 |
| 转译通过即认为迁移完成 | 机械承载 ≠ 行为正确 |
| 把 BinDiff/Diaphora 当零成本开源 | 依赖 IDA；Diaphora 还是 AGPL |
| 打包时不扫密钥 | 泄露风险，且会污染模型上下文 |
