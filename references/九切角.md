# 九切角 · 逐项检查清单

> **用法**：对每份文件逐个走完九个切角。走完一个打一个勾。
> **原则**：同一层同一个角度扫第三遍是浪费；**换角度扫第三遍、第四遍是应该的**。

---

## A · 正向

这个文件有什么功能？清单上记了吗？
- [ ] 所有 public / 导出方法已入账
- [ ] 所有命令 / API / 路由已入账
- [ ] 所有配置项已入账
- [ ] 所有 UI 入口已入账

## B · 反向

当前版有而原版没有的？（双向差集，别只查一个方向）
```bash
comm -23 <(sort old.txt) <(sort new.txt)   # 原版有、当前无
comm -13 <(sort old.txt) <(sort new.txt)   # 当前有、原版无 ← 别漏
```
- [ ] 改名 / 合并 / 拆分已定性（不是"缺了 9 个"，可能真缺只有 3 个）
- [ ] 当前多出的项已进**勿删清单**

**实证**：一直以为"缺 9 个 MCP 工具"，双向对照才发现被合并 2 个、等价改名 2 个、
当前多出 3 个，真缺失只有 3 个。由此暴露真实风险：
AI 客户端按原版 README 的工具名调用会**全部失败**。

## C · 边界

```
空集合 / 单元素 / 首尾元素 / 超长 / 超多 / 中文 / 空格 / 特殊字符 / 0 与负值 /
路径含空格 / 8.3 短名 / 高 DPI / 多缩放比
```
- [ ] 每个集合类操作都试过空与单元素
- [ ] 每个文本输入都试过超长与中文
- [ ] 每个路径操作都试过空格与中文路径

**实证**：8.3 短名不匹配（输入需先展开完整路径）；高 DPI 未处理 → 截图/取色错位。

## D · 异常 ⭐ 收益最高

```
中途取消 / 窗口失焦 / 进程被杀 / 磁盘满 / 文件被占用 / 权限不足 /
鼠标捕获丢失 / 双击 / 连点 / 重入 / 并发同发 / 断网 / 超时 / 异常退出
```
- [ ] try/catch 分支逐个看过（吞掉的异常往往掩盖真问题）
- [ ] 每个事务路径有 finally / RAII 恢复
- [ ] 每个长流程考虑中途取消与异常退出

**实证收益**：拖拽 35 个机制里，5 个直接产生 bug 的全从这里挖出：

| 缺失机制 | 后果 |
|---|---|
| 记录源页签 | 悬停切页签改了活动索引 → **卡片被移到错误页签** `[险]` |
| 用布局坐标而非视觉坐标 | 动画中途返回半路位置 → 插入条压在元素上 |
| 鼠标捕获丢失保护 | `MouseUp` 不触发 → 高亮/插入条**残留在屏幕上** |
| 向上以标题为基准 | 高个元素视觉中心受视口顶夹紧，**永远够不到贴顶矮邻框** |
| 先置空再处理 | 落点处理触发 UI 重排 → 重入 → 重复执行 |

## E · 横向一致性

同名功能在不同文件行为一致吗？
- [ ] 同类校验（如名称校验）在各处规则一致
- [ ] 同类错误文案一致
- [ ] 同类默认值一致

**实证**：名称校验 3 份实现，两份不一致 →
新建时被拒绝的名字（`..`、超长名）能通过改名写进去（真 bug）。

## F · 时序

先后顺序、延迟、防抖、定时器、谁先谁后？
```python
pat = {'防抖': r'防抖|debounce|Throttle',
       '定时器': r'DispatcherTimer|Timer\(',
       '抑制/暂停': r'Suppress|Suspend',
       '重入保护': r'重入|_running|_inProgress|_busy|IsRefreshing'}
```
- [ ] 每个防抖/节流的目的已记录（防振荡？匹配操作节奏？）
- [ ] 初始化顺序有依赖的地方已标注
- [ ] 临时摘锁/抑制窗口：状态是否在窗口**外**读？有没有 finally？可重入吗？

**实证**：监控 `Suppress`；连锁发送 400ms 防抖 —— 别当成冗余删掉。

## G · 权限与平台

平台 API、权限、编码、多进程？
- [ ] 平台专有 API 已列出（哪些在新平台不可用 / 有更好替代）
- [ ] 编码处理：按 BOM 判定还是"先试后回退"？（后者会静默产生乱码）
- [ ] 属性操作副作用（如 `+h` 会让文件夹被隐藏）
- [ ] 多进程写同一份数据？（`跨进程锁` 命中 = 架构信号）

## H · 数据往返

读 → 改 → 写 → 再读，一致吗？会被覆盖吗？
- [ ] 读不出来时会不会静默用默认值覆盖？（**必须区分"不存在"与"读不出来"**）
- [ ] 是唯一副本吗？有版本号迁移吗？
- [ ] 写入前有拦截吗？
- [ ] 整份覆盖写会吃掉哪些字段？

**实证**：前端 `saveConfig` 传整份 config，TS 多写的字段 Rust 不认识会被丢弃，
Rust 有的字段 TS 没写就传 undefined 覆盖 → **`chainActions` 丢失，用户连锁动作全没了**。

## I · 可见性

有 UI 入口吗？有文档吗？有 config 字段吗？

```
设置项无 + config 字段也无 → 正常缺口
设置项无 + config 字段有   → 类型 C（高优先级，用户只能手改 JSON）
设置项有 + config 字段无   → 硬编码，不可持久化
```

- [ ] 每个 config 字段都能在界面上找到开关（找不到 = 类型 C）
- [ ] 不在命令清单里的独立入口（Dialog / 小 Service）已扫到
- [ ] 被 `toast('请拖到...')` / `return false` 挡住的路径已检查是不是"其实是通路"
