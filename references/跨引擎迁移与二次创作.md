# 跨引擎迁移与二次创作（本 Skill 主场景）

> **本 Skill 的真实用途**：
> **自己的项目，在不同游戏引擎之间的搬迁、重制与二次创造。**

```bash
python3 scripts/engine_migration.py --ownership    # 项目性质与法律门禁开关
python3 scripts/engine_migration.py --axes        # 🔴 坐标系（最容易错）
python3 scripts/engine_migration.py --map         # 引擎概念映射
python3 scripts/engine_migration.py --recreate    # 二次创作四分类
python3 scripts/engine_migration.py --check ledger/engine_matrix.csv --gate
```

---

## 一、🔑 项目性质：法律门禁的开关

在 `ledger/project.yaml` 写：

```yaml
ownership: self        # 默认。文件不存在时也按 self
```

| `ownership` | 法律/许可门禁 |
|---|---|
| **`self`**（默认） | **不适用，自动跳过** |
| `third_party` | 才需要许可证据与授权确认 |

> **不要因为"许可未确认""反编译风险""DRM"这类顾虑
> 阻碍自有项目的重制与二次开发。**

`self` 时**自动跳过、不阻断、不降级、不报警**的项：

- G21 许可证据充分
- 字体/音效/图标的商用与再分发确认
- clean room / 反向工程合法性
- "遇加密/DRM/许可证校验停止并咨询法务"
- AGPL/GPL 工具的"法务确认"提示

> 即使是自有项目，若**引入第三方素材**（商城资源、外包音频、免费字体），
> 那部分素材仍需各自确认 —— **只影响该素材，不阻断整个项目**。

## 二、核心理念：先像素级记录，再有意识地偏离

> **先像素级记录原引擎上的表现，再有意识地偏离。**
> 偏离不是随意的 —— 每一处偏离都要有**分类、理由与证据**。

| 类别 | 含义 | 典型 |
|---|---|---|
| **`must-match`** | **必须等价**，偏离即 BUG | 输入响应延迟、跳跃高度与手感、移动速度与加速度、碰撞判定、无敌帧/判定帧、时序与节奏、关卡布局与可达性、数值与伤害、相机 FOV 与跟随、音频触发时机 |
| `may-evolve` | 可以有意识地演进 | 渲染画质、光照与阴影、特效粒子、模型精度、材质细节、UI 美化、字体、后处理强度 |
| `should-reinvent` | 应主动用新引擎特性重做 | Nanite / Lumen / GI / 体积光、新后处理栈、新物理特性、更优动画系统 |
| `explicit-new` | 明确的新增内容 | 新关卡、新机制、新美术方向、新剧情 |

规则：

- ⚠️ **`must-match` 项不许以"新引擎更好"为由擅自改动** —— 那是手感回归
- ⚠️ `should-reinvent` 项要单独记录**它是有意偏离**，否则验收时会被当成 BUG
  （对应 BUG 卡的「有意行为变更登记」）
- ✅ **二次创作的空间在 may-evolve / should-reinvent / explicit-new，不在 must-match**

这与 S2P 的四栏一脉相承：**可以不照搬，但必须知道搬前是什么样。**

## 三、🔴 坐标系与朝向：**最容易错，且错误会弥漫到全项目**

| 引擎 | 坐标系 | 前向 | 要点 |
|---|---|---|---|
| **Unity** | **左手系**, Y-up | +Z 前, +X 右, +Y 上 | FBX 导入默认转左手 |
| **Unreal** | **左手系**, Z-up | +X 前, +Y 右, +Z 上 | 🔴 **单位是厘米** |
| **Godot** | **右手系**, Y-up | **-Z 前**, +X 右, +Y 上 | 🔴 与 Unity 前向相反 |
| glTF/Blender | 规范右手 Y-up | — | 导出 `+Y up` 选项必须一致 |

陷阱：

- 🔴 **Unreal 用厘米**，Unity/Godot 用米 —— 速度、重力、阻尼直接搬**差 100 倍**
- 🔴 **Godot 是 -Z 前向**，Unity 是 +Z —— 模型/相机/AI 朝向**全反**
- 🔴 左手 vs 右手会翻转叉积、**winding order（背面剔除反了）**、法线方向
- 🔴 欧拉角顺序不同（Unity ZXY）—— 直接搬数值会得到错误朝向
- 🔴 负缩放会翻转法线并破坏物理凸包
- ⚠️ 骨骼轴向（Bone Roll）不同 → 重定向后手臂扭曲

> **迁移第一步就该锁定坐标系与单位** —— 否则后面全白做。

## 四、概念映射：**同名 ≠ 语义相同**

| 概念 | Unity | Unreal | Godot | ⚠️ |
|---|---|---|---|---|
| 场景对象 | GameObject | Actor | Node | **Node 是树，Actor 是平表+组件** |
| 可复用模板 | Prefab | Blueprint Class | PackedScene | 嵌套与变体机制完全不同 |
| 组件 | MonoBehaviour | Actor/SceneComponent | **Node 本身** | Godot 用子节点代替组件 |
| 协程 | Coroutine | Latent Action / Timeline | `await` / 信号 / Timer | **暂停/时间缩放下行为不同** |
| 资源引用 | GUID | 软/硬引用 | 路径 / UID | 迁移时**引用易断** |
| 数据资产 | ScriptableObject | DataAsset / DataTable | Resource | 需逐字段导出导入 |
| **时间步** | FixedUpdate | Tick Group + 子步 | `_physics_process` | 🔴 **不一致直接改变手感** |
| 输入 | Input System | Enhanced Input | InputMap | 死区/曲线/**缓冲窗口**要重录 |
| UI | UGUI / UI Toolkit | UMG / Slate | Control | 锚点/缩放/像素对齐语义不同 |
| 音频 | AudioSource / 混音器 | Sound Cue / MetaSound | AudioStreamPlayer | Wwise/FMOD 需单独迁 |

## 五、资产管线陷阱

- **🔴 法线贴图绿通道**：OpenGL(+Y) vs DirectX(-Y) —— **反了光照全错**
  （Unity/Unreal 默认 DirectX，Godot/Blender 默认 OpenGL）
- **色彩空间**：Linear vs Gamma —— sRGB 标记错误会全盘发灰/过亮
- **单位与缩放**：Unreal 厘米 vs 米，导入缩放因子未设 → 大 100 倍
- 切线空间（MikkTSpace）、骨骼轴向、**UV 通道语义**
- LOD Screen Size 阈值、纹理压缩（ASTC/BC/ETC）、**透明通道**
- 音频：压缩格式、采样率、**循环点**、空间化元数据
- 字体 SDF 参数不同 → 字重与描边不一致

---

## 六、着色器与渲染

- 翻译方向：HLSL ↔ GLSL ↔ MSL ↔ WGSL ↔ SPIR-V；**SPIRV-Cross** 作中间表示
- 可视化着色器（Shader Graph ↔ Material Editor ↔ VisualShader）
  **节点语义不完全等价**，需逐个验证输出
- ⚠️ 精度限定符（`half`/`mediump`）在移动端造成可见差异
- ⚠️ 矩阵**行主序 vs 列主序**、内置时间变量差异
- ⚠️ 后处理栈顺序（Bloom → Tonemap → LUT）不同 → 最终画面不同
- 🔑 **锁定色调映射（ACES/Reinhard/Filmic）、曝光、色彩空间、后处理顺序
  才能做视觉比对**

---

## 七、物理与动画（**must-match 的重灾区**）

**物理**：PhysX / Chaos / Bullet / Jolt / Godot 内置

- 🔴 **固定时间步必须与原引擎一致** —— 否则跳跃高度、摩擦、阻尼全变
- 碰撞形状近似方式不同 → 卡墙、穿透
- 物理材质组合模式（average/min/max）不同
- CCD 开法、求解器迭代次数、重力与阻尼公式
- ⚠️ **跨引擎不可能位级一致** —— 只保证「可玩等价」

**动画**：Mecanim ↔ AnimBlueprint ↔ AnimationTree

- 混合树参数与归一化语义不同
- 🔴 **骨骼重定向**：骨骼命名与轴向必须映射（否则手臂扭曲）
- 根运动提取方式不同 → 位移丢失
- IK 目标/极向量/权重、BlendShape 通道顺序
- 动画压缩误差不同 → 细微抖动
- 层与遮罩（Avatar Mask / bone filter）

## 八、验收

```bash
python3 scripts/engine_migration.py --check ledger/engine_matrix.csv --gate
```

脚本阻断三种情况：

1. 🚫 **`must-match` 却不等价** —— 手感/数值/碰撞/时序不许擅自改
2. 偏离未写理由或未分类 —— 四分类必填其一
3. 缺**原引擎表现**记录 —— **先记录，才有资格偏离**

配合本 Skill 已有的能力：

| 已有 | 用途 |
|---|---|
| `game_replay.py --desync` | 二分到帧、到子系统定位发散（首个发散帧 + 子系统） |
| `game_render.py` | GPU 帧图取证、基线污染检测 |
| `game_asset.py` | 资产 17 字段取证 |
| S2P 体验参数 | 手感数值（死区、缓冲窗口、加速度）逐条记录 |
| S2A 资产资源 | 美术/音效/图标整体归类 |
| BUG 卡 + 有意变更登记 | `should-reinvent` 的偏离要登记，否则被当 BUG |

## 九、一句话

> **记录是像素级的，迁移是可以主动演进的 ——
> 但每一处演进都要写清"原来是什么、现在是什么、为什么"。**
