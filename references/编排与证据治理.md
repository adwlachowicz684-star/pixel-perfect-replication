# 编排与证据治理（第七轮）

> **本轮判断**：最值得吸收的不是一个"大平台"，而是三条互相咬合的**薄层**——
> 能力契约 · 单一事实源 · 签字链。

---

## 一、先建能力契约，再谈上百个工具的编排

> **当前最大的工程缺口不是"没有工具"，而是没有机器可读的 capability contract。**

`which/where` 只能证明可执行文件存在，**不能证明它支持必需的输入、版本、
字体、GPU、屏幕捕获、容器运行时或许可证** —— 这会直接导致像素测试、反编译、
视频度量在下一台机器上**静默降级**。

### 已落地：`scripts/tools/registry.yaml` + `tool_run.py`

能力契约的核心字段：`id / required / capabilities / inputs / outputs /
probes / timeout / degradation`。**只写命令名是不够的。**

```bash
python3 scripts/tool_run.py --check-all --json ledger/capability.json --gate
```

探针输出含 `probe_version / content_hash / runtime_fingerprint /
observed_capabilities / failure_evidence`。
只有能力满足**或显式允许降级**时，流水线才调用工具 ——
把"工具没装"从**运行时报错前移为门禁决策**。

### 编排层：Taskfile 是外壳，Earthly 只接管需要干净容器的步骤

| 工具 | 定位 | 不该做什么 |
|---|---|---|
| **Taskfile** | 统一外壳；`preconditions` 可声明前置能力（Tauri 链、Playwright、字体库） | 用 `&&` 拼接不可观测长命令 |
| **Earthly** | 只接管**污染宿主**的步骤：Windows UI 采集、字体渲染、ICU/时区、视频编码 | 把全部脚本无差别容器化 |
| **mise** | 语言运行时（可读 `.tool-versions`，`mise.lock` 固化） | 锁定原生 GUI 工具链 |
| **devbox** | 宿主外工具与服务（Nix 友好包装） | 替代 Git 内源码证据库 |
| Nix | 二进制级深度可复现 | **不被 mise/devbox 替换** |

**Dagger 与 Bazel 是条件性升级，不是本轮默认** ——
Dagger 编排进程/容器，Bazel 把输入输出建模为可缓存构建图，
两者抽象边界不同。只有出现大量跨项目缓存、分布式构建或严格 hermetic 需求时才升级。

## 二、证据库只保留一个事实源，分析引擎只是派生层

> **SQLite + FTS5 是事实库，DuckDB 是查询/对账引擎 —— 不是两个真相源。**

| 操作 | 实现 | 验收 |
|---|---|---|
| 写入 | SQLite WAL + 事务 + 内容哈希 | 同一内容幂等，跨批可恢复 |
| 文本检索 | FTS5 外置内容表（BM25） | 结果可回链到证据主键 |
| 跨批对账 | DuckDB **只读**目录/快照 | SQL 可复跑，**不修改源文件** |
| 时间序列 | Parquet / SQLite 分区 | 可导出，**不依赖常驻服务** |

**已落地**：`scripts/tools/duckdb_evidence.py` ——
`--stats / --cross / --dup / --search / --sql`。
**纯 Python 兜底，不装 duckdb 也能跑**（实测通过对账与去重）。

### 防重复要两层，不是只保留最新文件

证据主键：`sha256(content) + source_type + normalized_scope`

- 先比**哈希**，哈希相同再比**结构化指纹**（截图特征、控件路径、属性集合、差异阈值）
- 文本用 **NFC 归一化** + 统一行尾 + 去 BOM
- **图像统一色彩管理、缩放、DPR 后再哈希**

每条证据记 `provenance`（工具、命令、参数、版本、输入哈希、时间）、
`confidence`、是否 `derived`、以及 `supersedes` 关系。
**重复不是被删除，而是被显式标记为同一事实的新观察。**

> **OpenLineage/Marquez、DataHub/Amundsen/Atlas 默认拒绝** ——
> 需要 Docker + PostgreSQL + 服务运维，对单机可复现审计是过度设计。
> 可把自家 event schema 设计成**兼容 OpenLineage 的子集**，未来可导出。
> **TimescaleDB / Prometheus / Redpanda 同理：与"可归档、可签名、可离线复跑"冲突。**

## 三、签字的本质是"谁在何时批准了哪个不可变摘要"

> **批准人签的是 manifest digest，不是"某个看起来相同的网页"。**

每次门禁先生成 `approval-manifest.json`：批准的证据 ID、哈希、规则版本、
批准人、角色、理由、环境、时间窗、报告产物 → 算 SHA-256 →
`cosign` 签名（或 keyless）→ 写入 **Rekor** 透明日志（含 inclusion proof）。

**manifest 中任一证据哈希变化，签名即失效。**

| 场景 | 方案 |
|---|---|
| 少量关键批准 | **cosign + Rekor + manifest** |
| 不能共用公网 Rekor / 不信任存储 | **immudb**（只增，带密码学证明） |
| 离线评审历史 | git-appraise（⚠️ 2021 年后无发布，accept 不防删除 —— **只作历史层**） |

**Gerrit / Graphite / Reviewable 不作为本地签字基础**（服务重 / 协作平台）。

### ⚠️ "决定不修"必须与"修复"同等级别证据

每次 `deferred` 必须填：
`defect_id · original_behavior_hash · target_behavior_hash ·
acceptance_rule · risk · owner · expiry · review_cycle · supersession_policy`

**禁止以聊天记录、口头同意、无哈希截图替代。**
签字证据与复刻证据分离存储但互相链接 —— 即使签名服务下线，
manifest、签名包与透明日志条目仍可离线验证。

## 四、差异报告服务于"逐功能收工"，不是追求界面炫目

- **结构化 diff**：`difftastic`（语法树比对，30+ 语言）—— 对反编译 C#、
  迁移后 Rust、配置 DSL 做结构化对照。**不替代像素/行为/契约 diff**
- **验收叙事**：`Allure`（step / timing / attachment / metadata → 静态 HTML）
  比自建 Markdown 更适合承载"逐控件、逐状态、逐视口"证据
- **报告站点**：`VitePress`（base 可设相对路径）或 `mdBook`。
  **大型交互站才用 Docusaurus**
- **报告与附件目录分离** —— 报告只引用**内容寻址附件**，
  **禁止把数 GB 截图重新编码进 HTML**

**报告门禁**：像素/布局/可访问性/行为四类均达阈值；未达标进 `blocked` 或
`deferred`；**任何 deferred 必须有签名批准**。
> **"看起来通过"不能成为关闭体验缺陷的理由。**

## 五、多模态与合成数据只能补充，不能倒置证据等级

### 证据等级排序（**不许倒置**）

```
源码/契约 > 可重复自动化观察 > 人工复核 > 多模态推断 > 合成数据
```

**若一条结论只由 OCR 和合成输入支持 → 标 `discuss`，不能标 `accepted`。**

| 手段 | 边界 |
|---|---|
| **rrweb** | 只录 Web（复刻后的 WebView）；**不能直接录 Win32/WPF**，原版仍靠 FlaUI |
| **OCR**（Tesseract/PaddleOCR/RapidOCR） | 只还原文案，**不能还原布局、状态、交互、动态文本**；须记模型/版本/置信度/人工校正 |
| 版面分析（LayoutParser/DocTr/marker） | 截图/文档版面提取，进 `multimodal_evidence` 分区，**不覆盖原始像素证据** |
| **Presidio** | 官方明确**不能保证找出全部 PII**；须"自动识别→人工复核→替换→签名" |
| Faker / Mimesis / SDV | 合成分布**不能证明**原版对边界值/历史脏数据/本地化格式的行为正确 |
| 伪本地化 | 须用**确定性**字符串包装与长度扩展；**不能用 LLM 改写替代原文证据** |

**要替换的是数据主体，不是界面语义** ——
真实坐标、颜色、时序和状态原则上不应替换为可能改变行为的假数据。

## 六、无障碍映射：补规范，不另造一棵树

已吸收的 axe/pa11y 回答"哪里不达标"；本轮补"**节点如何映射**"：
Chromium `aximize`、IAccessible2、AT-SPI、ARIA in HTML、UIA 规范、
W3C Accessibility Tree 文档 → 作为**映射词典**。

目标：把 WPF UIA 的 ControlType / Name / Role / Value / Pattern
映射到 Web AOM / ARIA role、name、state 与 focus order。

> **不要把 UI 坐标相似误当语义等价。**

新增脚本应是 `uia_to_aom_map.py`（输入 UIA 树 + 角色映射版本，
输出逐节点对照与**未映射项**），而不是直接改业务树。

## 八、第七轮不默认吸收（过度工程或服务化）

| 项 | 理由 |
|---|---|
| Dagger / Bazel | 过度工程，仅按需升级 |
| Marquez / DataHub / Amundsen / Atlas | 服务化数据血缘，需 Docker+PostgreSQL |
| TimescaleDB / Prometheus / Redpanda / Tinybird | 常驻基础设施，与"可归档可离线复跑"冲突 |
| ReportPortal | 服务化趋势平台 |
| Gerrit | Java 服务 + 专项运维 |
| Graphite / Reviewable | 协作平台，非本地签字基础 |
| Sentry Replay 与商业回放 | 托管、隐私、来源约束 |
| 多模型 OCR 黑箱 / LLM 伪本地化 | 不可解释，不能替代原文证据 |
| **自动快照更新 / flaky 自愈** | 会自动修正问题，与"不轻易收工"直接冲突 |

## 九、实施顺序

```
1. capability contract（registry.yaml + tool_run.py）  ← 已落地
2. Taskfile 外壳 + 证据库（duckdb_evidence.py）        ← 已落地
3. 签字 manifest（cosign + Rekor）
4. 有跨机器漂移时再上 mise / devbox / Earthly
5. Difftastic、OCR、回放、翻译、脱敏按实际缺口启用
```
