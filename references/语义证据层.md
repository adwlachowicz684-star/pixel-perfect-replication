# 语义证据层（第六轮）

> **本轮的核心判断**：问题不在工具数量（已有 26 个脚本），而在**证据粒度**。
>
> 现有脚本比较的是"**最终值**"，不足以回答：
> **中间调度是否等价、异常路径是否等价、协议格式是否等价**。
>
> 正确做法：把不可直接像素比较的语义，转成**可比较的序列化金标准**。

| 语义 | 金标准 |
|---|---|
| 文本 | `(code point, glyph_id, cluster, x/y advance, break opportunity, bidi level)` |
| 并发 | `(actor, logical time, event, before/after state, wall clock)` |
| 故障 | `(precondition, fault, observed error, recovery, postcondition, user-visible message)` |

---

## 一、文本排版：从字体度量推进到字形、断行、排序 ★★★

**前几轮只锁了 FreeType hinting，那只解决光栅化一层。**

WPF 的 DirectWrite/Uniscribe/ICU/Win32 locale 与浏览器 CSS 文本栈
**不共享同一语义**。只锁 hinting，仍可能在连字、字簇、双向重排、
换行点、排序键、日期格式上与原版不同。

### 两个独立合同（不许混）⭐

| 合同 | 内容 | 工具 |
|---|---|---|
| **L1 字形簇合同** | glyph ID / cluster 映射 / advance / offset | **HarfBuzz `hb-shape`** |
| **L2 最终像素合同** | 字体 fallback / hinting / subpixel / DPI / 合成 | 截图 |

> **只在 Chromium 里截图，不能判断差异来自文本布局、字体选择还是合成。**

HarfBuzz 的 Uniscribe/DirectWrite 后端可用于把**原版 Windows shaping 行为作金标准**，
再与新栈 shaper 对比。注意：HarfBuzz **自身不含 hinting**，
hinted rasterization 交给 FreeType 或 Skrifa（分工要写清）。

### 五维证据

| 维 | 金标准 | 工具 |
|---|---|---|
| `text_bytes` | 原字节哈希 + 探测编码 + 置信度 + **人工确认编码** | uchardet/chardet（**不作唯一解码源**） |
| `nfc_normalized` | NFC/NFKC 字节与序号比较结果 | ICU4X Normalizer |
| `canonical_bidi` | 逻辑序、视觉序、embedding level | UAX #9；FriBiDi/SheenBidi/Raqm |
| `break_opportunities` | 断点集合、字素边界 | UAX #14/#29；ICU4X Segmenter |
| `collation_order` | 排序键、日期/数字格式字符串 | ICU4X Collator（**须固定 data 版本**） |

### 实测出的两类坑（截图完全看不出来）

`scripts/text_layout.py` 实测抓到：

```
[t2] NFC 相等但原字节不同  → café 的组合/预组合序列差异
                             **影响排序与匹配**
[t3] NFKC 相等但 NFC 不同  → ＡＢＣ 全角/半角兼容字符
                             **显示可能相同但比较不同**
[t4] 文本不同且无 Bidi/断行/字形证据 → **无法判因**
```

**这两种在截图上完全一致，但排序、搜索、匹配行为全变了。**

### 权威层分工（不许两边都算）

| 范围 | 归谁 |
|---|---|
| 数据库/业务排序、文件顺序、搜索索引 | **Rust 固定 locale 与 data 版本** |
| 展示格式 | 前端按用户 locale（`Intl.*`） |
| 最终渲染 | Chromium / HarfBuzz |

### 字体资产：`fonttools/pyftsubset` 是门禁不是优化脚本

S2A 至少增加：`original_font_sha256` · `subset_tool_version` ·
`font_version/NAME table` · `included_unicodes` · `retained_OT_features` ·
`hinting` · `woff2/zopfli/br` · 许可与来源。

⚠️ **不要把 Web 字体 `unicode-range` 当成真正的子集化** ——
它只控制下载，**不删除字体内部字形**。

## 二、并发：异步迁移最大的风险是语义与取消模型 ★★★

WPF 的 `Dispatcher`、`DependencyProperty` 重入、UI 线程同步等待，
与 Tauri 的 Tokio、`spawn/await`、IPC 命令、前后端事件流**不是同构系统**。

**等价复刻的目标**：相同用户操作、并发任务和故障条件下，
**外部可见状态序列一致** —— 不是要求两个调度器"同时返回"。

### 工具分工

| 工具 | 干什么 | 边界 |
|---|---|---|
| **ThreadSanitizer** | 数据竞争检测 | **需几乎全量插桩**，否则误报漏报；开销数倍 |
| **Valgrind DRD/Helgrind** | mutex/rwlock 误用、递归锁、长持锁 | 仅 x86/x64 Linux，**不能用于 Windows/WPF** |
| **Loom / shuttle** | 受控调度、确定性重放（shuttle 可重放 schedule ID） | **不能证明正确性**，只是发现器 |
| **tokio-console** | 发现"活着但不前进"（self-wake、lost-waker、never-yielded） | 火焰图看不到的阻塞它能看到 |
| **rr --chaos** | 随机化调度暴露竞争 | Linux x86-64，**不能直接分析生产 WPF** |

> **没有找到能直接证明两版并发完全等价的现成工具** ——
> 搜索范围内不存在此类验证器。**不许宣称存在。**

### 可复刻的并发不变量（进 S3，不是只写进测试注释）

- 同一 command 不会被两个 actor 同时处理
- 事件不会丢失或重复应用
- 取消请求后**不会更新已废弃窗口状态**
- 任务链最终进入 success / error / cancelled 之一
- 并发导入不破坏单写者状态
- 资源关闭后没有 use-after-close

### 四条门禁

| 门禁 | 内容 |
|---|---|
| **阻塞预算** | 单次 command / event handler 禁止超过阈值 |
| **锁跨度** | 持有同步锁期间**禁止 await** |
| **取消一致性** | 所有长时间任务响应取消令牌 |
| **调度可回放** | 并发反例至少附 seed / record / trace |

## 三、故障注入：异常路径必须和正常路径一样穷尽 ★★★

**现有 `cross-end-check` 只覆盖 F1-F4（参数名/DTO/必传/注册），那只是参数层。**

原版在异常下的行为——部分写、断网、磁盘满、权限拒绝、重复启动、
剪贴板不可用——**一条都没采集**，而这些恰恰是用户真会遇到的。

> **"没有崩溃" ≠ "韧性等价"** —— 这是两条不同的门禁。
> 原版可能"也错了"，但新版应与原版**在同一前置条件下表现一致**，或明确改进并登记。

### 必覆盖故障目录（26 类，不止网络）

| 类 | 项 |
|---|---|
| 文件 | 打开失败 · 部分写入 · 磁盘满 · 权限拒绝 · 路径消失 · 并发替换 · 文件被占用 |
| 网络 | 连接超时 · 瞬间断网 · 慢网络 · 部分响应 · 重复响应 · 乱序响应 · TLS 失败 |
| 平台 | 重复启动 · 剪贴板不可用 · COM/OLE 繁忙 · 字体缺失 · 注册表不可写 · DPI 变化 · 多显示器切换 |
| 生命周期 | 卸载中途取消 · 升级中途断电 · 配置损坏 · 旧版本残留数据 · 首次运行无权限 |

### 每类故障必须六栏齐全

`precondition` · `fault` · `observed_error` · `recovery` ·
`postcondition` · `user_visible_message`

**外加 `old_behavior` 必须已采集** ——
**不许凭空生成新版韧性**（脚本会硬阻断留 TODO 的项）。

### 原版采集五步

1. **静态** — ILSpy/Cecil 找 catch / finally / transaction / retry
2. **动态** — FlaUI 驱动失败 UI
3. **故障** — Detours / libfiu / Toxiproxy
4. **结果** — 消息、日志、状态、磁盘文件、重试次数、遥测
5. **判定** — 契约验证**行为等价**，而非只是不崩溃

### 工具分工（互相不能替代）

| 工具 | 能 | 不能 |
|---|---|---|
| **Toxiproxy** | 传输层：latency/down/bandwidth/slow_close/timeout/reset_peer/slicer/limit_data | NTFS ACL、磁盘配额、独占锁、COM |
| **libfiu** | POSIX 层，`LD_PRELOAD` 注入 errno，`fiu-ctrl` 运行时启停 | Windows（需 Detours/shim 建等价层） |
| **Chaos Mesh** | 故障类型最全 | **K8s 原生，仅实验室**，不进桌面主链 |

**mitmproxy/WireMock 管内容层，Toxiproxy 管传输层** —— 不许互相替代。

## 四、安装与更新：桌面复刻最大的盲区之一 ★★

WPF 常见 MSI、ClickOnce、自定义 bootstrapper、注册表键、开始菜单、
桌面快捷方式、文件关联、URL 协议、服务、驱动、WebView 运行库、
每用户/每机器作用域。**Tauri 默认 MSI 不能自动复刻原版所有安装语义。**

> **平滑升级的核心不是"能下载新包"，而是残留数据迁移矩阵。**

### 残留数据 13 处，每处都要定 owner

`AppData\Roaming` · `AppData\Local` · `AppData\LocalLow` · `ProgramData` ·
`HKCU` · `HKLM` · SQLite/本地库 · 日志文件 · 缓存目录 · 锁文件 ·
自装字体 · 插件目录 · 用户文档目录

**所有权五选一**：只读快照 / 迁移 / 兼容 / 双写 / 废弃
**没有 owner 的数据在升级时一定会被漏掉。**

迁移脚本必须：事务或临时文件 · 版本上下界 · 校验和 · 回滚点 · 幂等键。

### 工具选择

| 工具 | 判定 |
|---|---|
| **WiX Toolset** | **安装契约源码**，不是临时打包脚本（Shortcut schema 可声明全部属性） |
| **Velopack** | 比 Omaha 更适合复刻 Windows 桌面应用；`--msi` 生成 WiX 5 MSI |
| **tauri-plugin-updater** | Tauri 2 内嵌更新（check / downloadAndInstall / relaunch） |
| Omaha | 成熟但重量级 C++/COM，**无硬约束不自建** |
| Sparkle / WinSparkle | 分别只适用 macOS / Win32 原版对照，**不能互换** |

⚠️ 开始菜单 shortcut 需 **Shortcut + RemoveFolder + KeyPath** 三者齐全，
否则**卸载时会残留**。

## 五、崩溃：统一"症状—调用栈—修复"语言 ★

| 工具 | 角色 |
|---|---|
| **Breakpad** | Windows client `ExceptionHandler` 生成 minidump（支持 out-of-process） |
| **Crashpad** | 独立 handler / 数据库 / 上传协议，保存 annotations |
| **rust-minidump** | `minidump-stackwalk` 本地分析；符号服务器 `srv*downstream*cache*URL` |

**⚠️ 不应以"调用栈相同"作为门禁** —— 跨语言没有相同函数。
应比较**归一化后的**：崩溃签名 · 崩溃阶段 · 用户输入 · 业务状态 · 恢复动作。

**Sentry 边界**：是聚合告警平台，**不应成为像素级差异验收源**。
可作为上报渠道（关掉自动面包屑噪声），建立
`crash_group → S2B BUG → 复刻决策` 映射。

## 六、图像资产转换管线 ★

`asset_conversion_graph`：
`source → detected format → transform chain → hash → target`

| 用途 | 工具 |
|---|---|
| SVG 确定性位图 | **resvg**（须记录版本、DPI、背景、CSS、shaping 后端） |
| 矢量 PDF 参考 | librsvg / rsvg-convert |
| 运行时多尺寸/压缩 | sharp（libvips）—— **有操作顺序依赖**，不能替代构建期基准 |
| ICO / ICNS | icotool、png2ico、png2icns |
| 优化层 | oxipng、pngquant、svgo |

**⚠️ 不得把"看起来差不多"的压缩产物直接发布** ——
有损量化须保留无损基准与失真预算。

## 七、剪贴板 / 拖放 / OLE ★★

**必须按"格式集合"验收，不是"文本粘贴成功"。**

Tauri clipboard-manager 只公开纯文本、图像、HTML。
**自定义 CF、CF_DIB/CF_DIBV5、CF_HDROP、OLE structured storage、
延迟渲染、嵌入对象、私有格式不能在默认 API 中直接复刻。**

| 维度 | 字段 |
|---|---|
| 提供端 | 所有 advertised formats、首选顺序、延迟渲染 |
| 消费端 | accepted formats、fallback、CF_HTML 片段头 |
| OLE | IDropSource / IDataObject / IEnumFORMATETC |
| 拖放 | DragImage、cursor feedback、copy/move/link effect |

**单实例/二次启动**：Tauri `single-instance` 插件可接收 args 与 cwd，
正好补上 WPF 单实例语义。`WM_COPYDATA` 适合轻量 IPC，不适合大块数据。

## 九、❌ 与理念冲突（不吸收）

| 做法 | 理由 |
|---|---|
| Sentry 作为唯一崩溃/差异源 | 聚合优先，不保证单用户证据完整 |
| Chaos Mesh 直接覆盖 Windows 桌面 | K8s/特权节点假设与单机桌面不符 |
| 只靠 `Intl` 默认 locale 复刻排序 | 实现、数据、版本均可能改变结果 |
| **用 Chromium 截图等同文本等价** | 不暴露 glyph/cluster/Bidi 根因 |
| **"概率通过"的随机并发测试** | 与"逐文件逐功能穷尽"冲突；只能作发现器 |
| 自动静默升级、无残留审计 | 用户状态和旧数据可能丢失 |
| 自动 font subset / unicode-range | 漏字符、漏 OT feature、运行时 fallback 差异 |
| **"能粘贴文本"等同剪贴板复刻** | 忽略 CF_HTML、CF_DIB、OLE、私有格式 |
| 只测 happy path | 原版异常行为未采集 |
