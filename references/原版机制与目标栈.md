# 原版机制与目标栈（第九轮）

> **本轮最值得吸收的不是又一个截图库，而是把四样东西变成一等对象**：
> **原版机制清单 · 原版取证动作 · 新栈能力矩阵 · 跨平台差异 · 行为门禁**

前八轮覆盖了视觉回归、AST、差分测试、运行时取证、崩溃、序列化、无障碍、
i18n、游戏复刻等宽范围。第九轮的短板不是工具总数，而是
"**原版有什么机制、怎样在运行中证明、怎样在目标栈复刻、何时算完成**"
没有形成机器可执行的字段。

---

## 一、判定口径：把"能跑"细化为机制、证据、门禁三层

每个原版机制至少包含：

```
id · layer · category · runtime_evidence · side_effect ·
new_stack_equivalence · visual_evidence · acceptance_criteria ·
tool · script · status
```

- `runtime_evidence` **只能接受可复现产物**：ETW/EventPipe、dump、日志、UIA 树、鼠标键盘录制
- `visual_evidence` 至少含：基准分辨率、DPI、缩放、动画帧、焦点状态、截图、diff
- `acceptance_criteria` 必须给**可判定布尔条件**，**不许写"尽量一致"**

> ⚠️ 脚本会拦截含糊表述：`尽量 / 差不多 / 基本一致 / 看着对`

## 二、A 区：WPF / .NET / Win32 机制（**最贴身的盲区**）

### 2.1 XAML 是五张清单，不是"控件和样式"

**属性系统 · 事件系统 · 模板系统 · 资源系统 · 树结构**

```bash
python3 scripts/wpf_mechanism.py --list           # 31 条机制
python3 scripts/wpf_mechanism.py --precedence     # 依赖属性值优先级
python3 scripts/wpf_mechanism.py --leak           # 四大泄漏根因
python3 scripts/wpf_mechanism.py --dpi            # DPI 基线矩阵
python3 scripts/wpf_mechanism.py --init ledger/wpf_mechanisms.csv
python3 scripts/wpf_mechanism.py --check ledger/wpf_mechanisms.csv --gate
```

### 2.2 🔑 依赖属性的真正难点是**值优先级链**

```
1  强制值 / coercion        ← 最高（除活动动画）
2  活动动画 / Animation     ← **覆盖局部值**
3  局部值 LocalValue        ← **通常高于样式 setter**
4  TemplateParent 模板属性
5  隐式样式 Implicit Style
6  样式触发器 Style Trigger
7  模板触发器 Template Trigger
8  样式 Setter
9  默认样式 / 主题
10 属性继承 Inherited
11 元数据默认值 Default
```

> ⚠️ **局部值通常高于样式 setter，但正在运行的动画是例外** ——
> 这条最容易在复刻时被颠倒。

> **改进发生在计算完成后，不是在测量前删除原版能力。**
> 除非证据表证明所有实际值路径只用到其中一两项，
> 否则**不应发明一个"统一状态对象"直接替代**。

### 2.3 绑定是一组**时间语义**，不是两个标签

| 机制 | 易漏点 |
|---|---|
| Mode | OneWay / TwoWay / **OneWayToSource** / OneTime |
| UpdateSourceTrigger | `PropertyChanged`（立即）vs `LostFocus`（延迟）vs Explicit；另有 **Delay** |
| ValidationRule | 异常 / IDataErrorInfo / 自定义规则；**红框与错误模板** |
| Converter / FallbackValue / TargetNullValue | 回退与空值格式化（**高置信待核**） |

绑定取证：同一输入框执行**快速连续键入 / 粘贴含格式化字符 / 清空 / 撤销 /
焦点切换 / 校验失败 / 文化切换 / 复值回显**，记录原值、展示值、内部值、
错误状态、回写时间戳。

### 2.4 路由事件必须**同时记隧道与冒泡**

```
冒泡：源 → 根
隧道：根 → 源（Preview）
直接：只在源
```

输入事件**通常先 Preview 再冒泡，且共享事件数据**。
需记 `event_path: [root..source]`、`handled_at`、`e.Handled` 副作用、
"同一事件数据是否跨隧道/冒泡延续"四字段。

> ⚠️ 不能因为 DOM `stopPropagation` 更简单就直接收敛为一次回调。

### 2.5 布局：约束传播探针（**不要立即改 CSS**）

若静态尺寸、字体、padding 都相同但 **resize 时**有像素差异：

```
固定尺寸 → 约束尺寸 → 内容增长 → 容器边界 → 滚动出现 → DPI 切换
```

每容器加 `layout_trace_id`，输出原始/期望 DesiredSize、final rect、
constraint、margin、基线、换行、容器滚动 offset。

### 2.6 WPF 四大泄漏根因（**不是泛化的"内存高"**）

1. 长期对象订阅静态/单例事件且未退订
2. Binding 中 Converter / ValidationRule / **Freezable** 未释放
3. 未注销的 `CompositionTarget.Rendering`、DispatcherTimer、弱事件失效
4. Dispose 缺失、finalizer 未终结、**WPF 内部保留的视觉树/事件 handler 引用链**

取证：`dotnet-counters` / `dotnet-trace` / `dotnet-dump` / `dotnet-gcdump`
（Windows 深度分析可用 PerfView —— ⚠️ **许可未核实，标来源不确定**）

### 2.7 Dispatcher 是**行为时间轴**

执行顺序：输入捕获 → 路由事件 → 绑定校验 → 布局无效化 → 渲染帧 → 动画 tick → 资源释放

> ⚠️ 新栈不应只测"最终画面"，应测**事件执行顺序**。
> `CompositionTarget.Rendering` **不用时必须解绑**，否则是持续工作源。

### 2.8 Win32 / .NET（体验细节的真正来源）

| 机制 | 关键 |
|---|---|
| **SendMessage vs PostMessage** | SendMessage **处理完才返回**；PostMessage 入队立即返回 |
| DPI Per-Monitor V2 | `WM_DPICHANGED`、**不再位图拉伸**、应用须自己重设尺寸 |
| COM STA / MTA | 原版依赖 STA 消息泵时，不得用任意 worker 线程操作 UI |
| DWM / 任务栏 / 托盘 / 文件关联 / UAC / 剪贴板 / OLE 拖放 | 都是**可见产品行为** |

**DPI 基线矩阵**：96/120/144/150/175/200 DPI · 至少两种显示器排列 ·
主屏/副屏启动 · 跨屏拖拽 · 恢复/最大化 · DWM 缩放 · 远程桌面 ·
**整数与非整数缩放**（取整差异最容易漏）

## 三、B 区：目标栈 Tauri + React + Rust（**新栈怎么做对**）

```bash
python3 scripts/target_stack.py --tauri      # Tauri 2 迁移事实
python3 scripts/target_stack.py --ipc        # invoke / 事件 / Channel
python3 scripts/target_stack.py --webview    # 三 WebView 差异基线
python3 scripts/target_stack.py --react      # React 确定性字段
python3 scripts/target_stack.py --rust       # Rust 工具链门禁
python3 scripts/target_stack.py --check ledger/capabilities.json --gate
```

### 3.1 ⚠️ Tauri 2 不是 Tauri 1 的升级

| 变更 | 内容 |
|---|---|
| 配置键 | `tauri` → `app`；`productName`/`version` 上移顶层 |
| 二进制名 | **不再自动匹配 productName** |
| SystemTray | **被移除** → tray-icon |
| 旧 Menu / `on_menu_event` | **被移除** |
| 更新器 | → `tauri-plugin-updater` |
| `@tauri-apps/api` | 只留 core/path/event/window，其余进插件 |
| **能力模型** | **capabilities / ACL = 默认拒绝的新边界** |

> 旧技能若仍以 Tauri 1 **allowlist** 思考，会**系统性漏掉现代能力模型**。

**能力矩阵字段**（13 项）：permission · identifier · platform · target ·
window_label · webview_label · scope · description · local · remote ·
requires · added_in_version · removed_in_version

```bash
# 实测：检出 wildcard scope 会阻断
🔴 **wildcard scope** 1 条 → 能力模型是默认拒绝，wildcard 等于绕过整个边界
```

⚠️ 官方插件聚合仓是**能力盘点起点，不是质量背书** —— 每个插件的版本、
许可证、维护状态须**重新读取仓库**，不因聚合页一次核验而冻结结论。

### 3.2 IPC 是三套语义，不是只有"函数调用"

| 类型 | 适用 |
|---|---|
| **invoke** | 一次请求/响应 |
| **event** | 跨窗口/后端广播 |
| **Channel** | **长流与逐帧增量** |

> 禁止把**大数组反复序列化往返** —— 连续像素数据、日志流、文件内容优先用 Channel 或临时文件句柄。
> 所有边界错误必须**可机读**，不应让前端只看到 `error: something failed`。

### 3.3 🔴 三 WebView 差异是像素级复刻的杀手

| 平台 | 引擎 | 差异 |
|---|---|---|
| Windows | WebView2 (Chromium) | 最接近 Chrome；注意 Evergreen 版本漂移 |
| Linux | **WebKitGTK** | **CSS、滚动、字体、缩放与 Chromium 有差异** |
| macOS | **WKWebView** | **滚动惯性、字体渲染、缩放与 Chromium 有差异** |

> **每个平台各自一套 golden，不许跨平台共用。**

多 WebView 是**复刻等价单元**，不是优化技巧。
双窗口共享状态时不能只测前端状态同步 —— 还要测首次挂载、失焦、
关闭一个 WebView、刷新、导航拦截、下载、协议升级、CSP、postmessage 来源。

### 3.4 React 确定性来自 key 语义、effect 清理、portal 顺序、焦点恢复

10 个必记字段：`list_key_strategy` · `key_stability` · `component_pure_render` ·
`effect_cleanup_present` · `focus_trap_owner` · `portal_root` ·
`return_focus_to` · `controlled_input_rehydration` · **`css_layer_order`** ·
`runtime_determinism`

> ⚠️ **StrictMode 故意双调用**是发现不纯渲染和缺失清理的有效机制，
> 但**双调用产生的 UI 不是基准** —— WPF 原版一次渲染的确定结果才是基准。
> 生产构建的探针仍必须**一次且仅一次**执行真实副作用。

**虚拟列表不能按"渲染了几千行"验收**，应按焦点和锚定验收：
滚动条比例、顶部/底部空白、**按像素锚定**、内容高度变化时的跳动、反向列表、
选择保留、编辑保留、键盘上下键、Home/End、分页加载、resize、字体变化、滚动恢复。

**CSS 门禁**（不规定只用某方案，规定确定性）：
相同输入生成相同样式 · 主题切换无 FOUC · z-index 层有稳定 owner ·
样式层顺序受锁文件固定 · 关键像素不依赖 CSS 变量未定义回退

> 应在每个交互后读 `getComputedStyle` 和盒模型做**字段级 diff**，
> **而非只比较截图**。

### 3.5 Rust 工具链串行门禁

`cargo-deny`（依赖/许可/公告）· `cargo-nextest` · `cargo-llvm-cov` ·
`cargo-geiger`（⚠️ **不直接判断安全**，应与 crev/safety-dance 结合）·
`cargo-audit` / `cargo-vet` · `cargo-careful` · `cargo-fuzz` · `cargo-msrv` ·
**`rust-lang/miri`** · `thiserror` / `anyhow` / `serde`

> ⚠️ **Miri 只能从 rust-lang/miri 吸收** ——
> crates.io 上的同名占位包是**抢注的 yanked dummy，绝不可作为依赖**。

职责边界：**serde** 管稳定契约 · **thiserror** 定义稳定错误 ·
**anyhow 只用于应用边界聚合**。

MSRV 是**固定策略**：`rust-toolchain.toml` 固定 + `cargo-msrv` 做版本提案，
**不在每次新稳定版发布时静默升版**。

## 四、C 区：数值 / 编码 / 序列化保真

```bash
python3 scripts/value_fidelity.py --float --old o.json --new n.json --gate
python3 scripts/value_fidelity.py --charsets
python3 scripts/value_fidelity.py --culture
python3 scripts/value_fidelity.py --canonical --file d.csv --out c.csv
```

### 4.1 🔑 三类"相同"必须分开

| 类型 | 适用 |
|---|---|
| **字节相同** | 保存文件 |
| **语义相同** | 跨进程契约 |
| **展示相同** | UI |

### 4.2 展示精度 ≠ 往返精度

> **不能默认 JSON 能无损保真** —— 必须记录
> `float_format = ryu | grisu | fixed | hex | raw_bits`

**Ryū**（Ulf Adams 算法，Rust 实现，有 PLDI'18 正确性证明，Apache-2.0/Boost；
f32 约 21ns、f64 约 31ns）用于最短往返表示。

逐字段做 `parse → serialize → parse`，比对
**bit pattern / 原始文本 / 规范化文本 / 平台格式**。

> ⚠️ 数字即使非金融值，也应记录**原始格式与显示格式** ——
> **不能因"值相等"删除格式信息**。

### 4.3 字符与时间坑

BOM · 字节序 · 编码检测（**只给概率，不能当事实**）·
**NFC/NFD/NFKC（相等但字节不同 → 影响排序与匹配）** ·
时区与夏令时 · 闰秒（chrono 能表示但**不完全支持**）· 历法

### 4.4 文化格式化差异要分类，不许说"格式不同"

`rounding` · `grouping separator` · `decimal separator` ·
`percent placement` · `currency code/symbol` · `negative sign` ·
`RTL shape` · `fallback`

> **不应以"英文通过"结案。**
> Rust 端固定 locale provider 与数据版本；React 端固定 `Intl` 数据回退。

### 4.5 规范化 diff，不是原始 diff

CSV 逐行规范 · JSON **stable key 排序 + 确定 NaN/inf 策略** ·
XML 规范化属性顺序与命名空间 · 二进制用 Kaitai

每项生成 `canonical.<ext>` + `checksum.sha256` + `field-report.json`。

> **Kaitai 定义「格式」，规范化器定义「逐字段等价」** —— 两者互补。

## 五、D 区：Web Vitals 只能作参考

> **直接把 200ms INP / 2.5s LCP / 0.1 CLS 当作"通过线"会误伤原生原版，
> 或放过真实掉帧。**

桌面没有统一 CDN、DOMContentLoaded 或首屏最大元素语义。
应分两层：`web_reference`（若同时有 Web 版）和 **`desktop_primary`**。

桌面层固定：输入延迟、首帧、首交互、空闲到稳态、连续滚动帧间隔、
动画掉帧、**IPC round-trip**、文件打开、搜索响应、窗口切换、DPI 切换、
内存稳定斜率、崩溃自由时长。

**INP 的启示是测"交互尾延迟"**（P50/P95/P99），不是只测平均点击响应。
CLS 可转为 `Cumulative Layout Shift Index`。

> ⚠️ 若原版某交互 P99 为 180ms、目标栈为 95ms，**不能自动收工** ——
> 仍需检查是否只是**删除了原动画/确认/反馈**。

## 六、E 区：文档考古

**changelog 工具只能提取提交事实，不能证明设计意图。**
`git-cliff` / `release-please` / `conventional-changelog` —— 只用于生成**候选证据**。

每条 feat/fix/perf 必须关联：commit、版本、代码位置、原版行为、测试证据、用户可见影响。
对 `BREAKING CHANGE` 自动建"旧契约—新契约—迁移—回归测试"四联表。

`document-archaeology.yaml` 字段：`doc_format` · `language` · `encoding` ·
`source_url` · `capture_date` · `version_range` · `claim_text` ·
`claim_type(intent|behavior|constraint|known_issue|marketing)` · `confidence` ·
`corroborating_evidence` · `contradicting_evidence`

> **"为什么当初这样设计"必须有至少两类证据。**
> 只有市场文案不能支撑行为；只有代码没有文档时标 `design_intent=inferred`。
> 旧 .NET Framework / XP/Vista 行为可作档案，**不应默认成为 Tauri 门禁**。

⚠️ CHM/HLP 提取应先隔离解析，**防止旧 ActiveX/脚本执行**；
KchmViewer 维护状态未核实，标来源不确定。

## 七、F 区：双轨运行

Branch by Abstraction 适合**内部逐步替换**；Strangler Fig 适合**外部入口替换**。
OpenRewrite 只提供"抽象层—开关—移除旧实现"的**工序参考**，
**不作为 WPF→Tauri 的直接转换器**（代码转换应由 tree-sitter/AST 工具链完成）。

**双轨对比必须有同一输入、同一时钟语义、同一输出 schema。**
`dual_track_replay.py` 录制原版输入事件/文件/网络/剪贴板/随机种子/时间起点，
重放到原版和目标版，两边输出 `state.json`、日志、屏幕事件、错误。

对账支持五类 comparator：exact · float epsilon · order-independent ·
semantic · visual —— **不能把所有字段强制字符串相等**。

不可逆副作用（打印、删除、发支付请求）用 test double，
外部 effect 写入 **effect journal**，比对顺序、参数和幂等键。

> 🔴 **与理念最冲突的是"先上线再观察"** ——
> 一旦用户状态被新实现永久改变，就无法保持原版作为唯一基准。

## 八、❌ 本轮新增冲突项

| 做法 | 为什么冲突 |
|---|---|
| 用统一 state 对象替代依赖属性优先级 | 在测量前删除了原版能力 |
| 只绑 onClick，漏掉隧道/冒泡 | 丢交互路径 |
| resize 有差异就改 CSS | 应先跑约束传播探针 |
| 把 StrictMode 双渲染结果当基准 | 那不是原版行为 |
| 虚拟列表按"渲染了几千行"验收 | 应按焦点和锚定 |
| 三 WebView 共用一套 golden | 差异是真实的，会被掩盖 |
| 保留 wildcard scope | 等于绕过默认拒绝的能力边界 |
| 默认 JSON 能无损保真浮点 | 必须记 `float_format` |
| 因"值相等"删除格式信息 | 显示格式是体验的一部分 |
| 照搬 Web Vitals 阈值到桌面 | 会误伤或放过 |
| 用 changelog 文本当设计意图 | 只是提交事实 |
| **"先上线再观察"** | 用户状态被永久改变后原版不再是基准 |
| `crates.io` 上的 miri 占位包 | 抢注的 yanked dummy |
| PerfView / KchmViewer 作强制门禁 | 许可或维护状态未核实 |
