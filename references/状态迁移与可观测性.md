# 状态迁移、IPC 与可观测性（第十轮）

> **第十轮真正仍未覆盖的不是"有没有迁移库"，而是缺少一套能把原版
> 所有状态、消息和痕迹转成可证伪契约的工具链。**

三份契约（**旧版录制 → 新版录制 → 差异阻断**）：
`migration-contract.yaml` · `ipc-contract.yaml` · `telemetry-contract.yaml`

> 若只写"用 Atlas 迁移""用 tracing 记录"，仍可能在 `clusters` 这类字段上
> **零报错地失败**。

## 一、A 类：持久化迁移（最高优先级）

### 1.1 已实证的教训

> 旧版配置/数据迁移时某个字段（`clusters`）被**静默丢弃**，
> 导致用户数据**永久丢失且无任何提示**。

```bash
python3 scripts/state_migration.py --silent       # 六类静默失败
python3 scripts/state_migration.py --unknown      # 未知字段策略
python3 scripts/state_migration.py --check ledger/migration_fields.csv --gate
python3 scripts/state_migration.py --fs           # 路径与文件系统陷阱
python3 scripts/state_migration.py --config       # 配置位置语义
```

### 1.2 🔑 schema 迁移工具 ≠ 迁移保真验证

> **DDL 完全相同不代表数据转换无损失。**

| 工具 | 角色 |
|---|---|
| **ariga/atlas** | 表达目标状态 + lint |
| **sqldef/sqldef** | 从旧库导出当前 DDL 后与目标比对；`--check` 漂移门禁 |
| **rust-db/refinery** | Rust 内嵌 SQL 迁移、版本与历史校验 |
| **amacneil/dbmate** | 单一二进制、事务迁移、schema dump |

**工作流**：
① 冻结旧版安装与数据库 → ② 生成 `old-schema.sql` + 脱敏 golden 数据 →
③ 手书 `expected-schema`（**每列来源、转换、未知键策略**）→
④ dry-run 得到计划 → ⑤ 临时库执行 + 写迁移历史 →
⑥ **四层对账** → ⑦ 写 `migration_run.json`

### 1.3 六类静默失败（**迁移返回成功，但数据语义已变**）

| 失败 | 为什么无报错 | 检测 | 处置 |
|---|---|---|---|
| ①反序列化忽略未知字段 | `serde(default)`、ORM 缺列 | 未知字段计数器 | 阻断 |
| ②列保留但写入空 | INSERT 漏字段 | **逐列原始值/摘要比对** | 阻断+报告业务键 |
| ③类型/文化转换 | `ToString()`、日期往返 | 十进制字符串快照 | 阻断+容差契约 |
| ④枚举未知值被默认替代 | 新模型只认已知分支 | 值域覆盖率 | **不许静默 `Other`** |
| ⑤外键/孤儿行 | 插入顺序、软删除 | 孤儿查询 | 阻断+保留源行 ID |
| ⑥写入成功但读取失败 | 锁、未 flush、缓存覆盖 | **开/关应用、崩溃后读回** | 阻断启动 |

### 1.4 🚫 未知字段策略**不允许 ignore**

| 策略 | 判定 |
|---|---|
| `passthrough` | ✅ 原样保留为版本化扩展字段 |
| `canonicalize` | ✅ 按批准的归一化规则（须有往返/业务样例测试） |
| `archive` | ✅ 脱离主表进只读审计（**须证明可检索**） |
| **`ignore`** | 🚫 **禁止** —— 这正是 `clusters` 事故的形式 |
| **`default`** | 🚫 **禁止** —— 等价于静默改写 |

**面向用户的文案不能暴露实现细节**：
- ✗ 「JSON 字段 clusters 未映射」
- ✓ 「旧版 X 中有 N 项集群设置未自动识别，可保留为高级数据并联系迁移支持；继续前这些设置不会生效」

技术细节进诊断包。用户选择丢弃也必须记录**明确同意、影响项、时间、操作者**，**不允许默认勾选**。

### 1.5 四层对账（**双向闭环，不是只校验"新库有没有数据"**）

1. **catalog** — 表、列、类型、可空、默认值、索引、唯一、外键、迁移历史
2. **cardinality** — COUNT(*)、重复键、空值数、最大/最小值
3. **content** — **按业务键 join**，比较规范化字段值；数值与日期用字符串往返快照
4. **behavior** — 打开同一文档、执行同一操作、关闭再打开，断言状态/MRU/窗口/词典/模板/许可证一致

最终把 `old_hash_by_key_range`、`new_hash_by_key_range`、差异业务键、修复动作落到 `migration_reconciliation` 表。

### 1.6 回滚 = 能证明回到可读旧状态

> **不是无条件反向执行 DDL。**
> 禁止在数据已按新语义写入后重跑旧的破坏性转换。

旧版快照保持只读 + 保留旧配置备份 + 记录已迁移最大业务版本 + 必要时从旧快照重建新库。
**新安装器启动时若发现状态不一致，应停止并进入修复向导，而不是重新初始化。**

### 1.7 迁移脚本最常见的失败**不是报错**

> 而是「**读取时已经看不到旧数据**」——先删旧库、先覆盖配置、
> 把旧路径重命名后再迁移、用新应用打开旧文件触发自动升级、
> WebView 缓存与用户 store 并发写。

修复：**取证—迁移—运行三段彻底隔离**。只读挂载或副本原版数据；
迁移器不可改变源；所有写先进 staging；启动前记录 source checksum；
完成后生成 `migration_receipt.json`。
**没有 receipt 时新应用不得把状态标为"最新"。**

### 1.8 配置迁移：先穷尽位置语义

`app.config` · `user.config`（ClickOnce/SettingsProvider）·
**AppData Roaming/Local/LocalLow** · ProgramData · HKCU/HKLM ·
INI/XML/JSON · **MRU** · 窗口状态（**须保留监视器布局快照**）·
自定义词典 · 模板 · 许可证/激活 · 缓存

⚠️ **Windows INI File Mapping** 会让部分 `GetPrivateProfile*` 调用**从注册表返回数据**
—— 只复制 `.ini` 会得到空配置。读取旧版时应**同时枚举文件与对应注册表映射**。

⚠️ 区分「**用户偏好**」（默认保留）与「**内部状态**」（可重建）。
许可证/激活受 **EULA 与机器绑定约束**，**不能直接复制哈希** ——
应进入"待用户确认/重新激活"状态并保留原文件。
MRU 失效路径**不应静默消失**，应标记不可用并允许逐项修复。

## 二、B 类：IPC 与系统集成面

```bash
python3 scripts/ipc_surface.py --list
python3 scripts/ipc_surface.py --single-instance
python3 scripts/ipc_surface.py --shell
python3 scripts/ipc_surface.py --check ledger/ipc_contract.csv --gate
```

### 2.1 每个消息要建模

`protocol_id, transport, encoding, framing, direction, caller_identity,
callee_security, request_fields, response_fields, timeout, retry, ordering,
side_effects, failure_mode`

> **Windows IPC 清点不能停在"有没有 Named Pipe"。**
> Named Pipe 既可以是字节流也可以是消息流 —— **消息模式把每次写入视为一个消息**，
> 部分读取返回 `ERROR_MORE_DATA`；字节模式不保留 write 边界。
> ⚠️ 消息模式改成字节流只追加长度前缀，**不能声称 IPC 对等**；反之亦然。

### 2.2 机制与验证重点

| 机制 | 验证重点 |
|---|---|
| Named Pipe | 字节流/消息模式、实例、权限、连接竞态 |
| Mailslot | 单向语义、消息尺寸、**丢失是否可接受** |
| WM_COPYDATA | 消息 ID、wparam/lparam、ANSI/Unicode、目标窗口 |
| 共享内存 + 同步对象 | 消息协议、**ownership abandoned**、**崩溃残留脏数据** |
| COM/RPC | 套间、STA/MTA、激活、接口 IID、权限 |
| Shell | 参数注入、动词、图标、per-user/machine、权限提升 |

⚠️ 跨平台 Rust 传输用 **kotauskas/interprocess**（Windows Named Pipe / Unix UDS）。
🚫 **不要用 servo/ipc-channel 做通用服务** —— 文档明确服务器**一次只接受一个客户端**。

### 2.3 单实例：**单位是会话身份，不是进程数**

身份维度：machine ID · install ID · user SID · session ID · window/profile ID
角色：**GUI 单实例 / CLI 并发 / 后台服务 / 安装器 / 渲染器进程**

⚠️ **必须传递第二个实例的命令行/工作目录**，而不仅是阻止启动。
⚠️ **不要用裸全局 mutex** —— `Global\` 与 `Local\`、Session 0、快速用户切换、远程桌面、不同权限。
⚠️ **abandoned mutex 不等于状态仍然有效**。
⚠️ 文件锁残留、管道实例耗尽、端口抢占都可能造成**假"已运行"**。
⚠️ **Session 0 服务不能无脑给交互用户显示 Toast 或打开文件对话框**。

会话测试矩阵：同用户双开 · 不同用户 · 同会话 · 服务调用 · UAC ·
**崩溃后重启** · 第二个实例带不同 cwd · 只读配置 · 网络路径

### 2.4 Shell 集成：**取证优先级高于重新设计**

- **URL protocol** —— 完整 URI 逐字符传递（引号、空格、`#`、Unicode、相对路径）；
  ⚠️ **命令行注入风险**意味着不能简单 `shell::open(uri)`
- **文件关联** —— `Open` / `Open with` / `Print` / `Drop` / `ShareTarget`；
  拖放格式（CF_HDROP、Shell IDList、FileGroupDescriptor）
- **上下文菜单** —— 进程外 COM/Explorer 宿主问题，**不是普通 Tauri command**
- **Toast** —— AUMID、tag/group、按钮、过期；**Windows 10/11 表现可能不同**

### 2.5 取证

**Process Monitor 4.1** 是本轮最重要的补件 —— v4.1 新增**命名管道和邮槽的 IPC event class**。
**ETW** 更底层但 ⚠️ **默认不是抓取任意管道明文** —— 必须知道 provider GUID/name、keyword、event template。

> **先以 ProcMon IPC 发现端点，再以目标 provider 细化 ETW。**

5 个 profile：①启动/退出 ②Named Pipe/Mailslot ③Shell/URL/文件关联 ④通知与托盘 ⑤崩溃
（⚠️ 不要无差别启用 boot logging，噪声会淹没真正的 IPC）

**录制判定标准是"请求—响应—副作用"三段，而不只是抓到字节。**
同一操作至少做**普通用户、管理员、Session 0/服务、远程桌面、受限用户**四组。

> 🔑 **IPC 的"功能通了"与"语义对等"之间至少隔三次重试、两个超时和一个权限上下文。**

## 三、C 类：日志、遥测、崩溃对等（**完全空白**）

```bash
python3 scripts/log_parity.py --drift      # 字段含义漂移
python3 scripts/log_parity.py --layers     # 三层断言
python3 scripts/log_parity.py --crash      # 崩溃五组字段
python3 scripts/log_parity.py --check ledger/telemetry_contract.csv --gate
```

### 3.1 🔑 最大的坑：字段名一致但含义漂移

| 字段 | 可能含义 |
|---|---|
| `user_id` | 本地 GUID / 微软账户 / 邮箱 / **匿名哈希** |
| `session_id` | **可能跨启动** |
| `duration_ms` | **可能含睡眠/挂起** |
| `error` | null / 空字符串 / 消息 / **类型** |
| `timestamp` | 本地时间 / UTC / 文件时间 / **单调时钟** |
| `count` | 累计 / 会话 / **去重后** |
| `version` | 应用 / schema / **协议**版本 |
| `level` | **级别映射 ≠ 语义相同** |

对策：OTel 语义规范字段复用 + 项目 `custom_attributes.md`，
每项标注**单位、基数、是否 PII、来源、缺失策略**。
⚠️ **动态值不得进事件名**（会破坏聚合）。

### 3.2 三层断言

| 层 | 内容 | 工具 |
|---|---|---|
| 1 事件断言 | 模板**出现/不出现/次数/字段** | `dbrgn/tracing-test` |
| 2 span 生命周期 | 断言 span 被**创建/进入/关闭**及次数（迁移事务、IPC 连接、文件写入是否真正关闭） | `tobz/tracing-fluent-assertions`（⚠️ 仅 dev-dep） |
| 3 结构化 diff | 同一 golden scenario，规范化后比对模板与属性 | ⚠️ **不得把相似度阈值当"通过"** |

旧版 .NET 侧：**捕获结构化 LogEvent，不是渲染文本** ——
`SerilogSinksInMemory`（模板/级别/次数/属性）+ `serilog-exceptions`（解构异常自定义属性）。
⚠️ 异常解构**不得无边界递归**或记录整个 `DbContext`（会把数据库结构/数据带进日志）。

> 目标**不是把旧日志永久引入新项目**，而是生成**可重放 event catalog**。

⚠️ Rust 侧用 tracing 作门面，但**不能让 OTLP 成为唯一 sink** ——
本地结构化 JSON、崩溃 breadcrumb、启动修复信息必须**可离线读取**。

### 3.3 崩溃上报：**按"可复现性"验收，不是按字段数量**

五组：①应用标识（含 **schema 版本**）②运行上下文（含 **DPI**、会话、权限）③崩溃现场（**exception chain**、breadcrumbs）④状态快照（**最后成功迁移阶段**、最后 IPC message）⑤环境健康（按需脱敏）

### 3.4 审计日志：append-only、可关联

`actor · process · session · operation · target · before_hash · after_hash ·
decision · evidence_id · result · reason`

每次迁移、配置导入、许可证变化、提权、外部文件打开、Shell 调用、插件加载、
远端/URL 打开都应产生结构化 audit event。
⚠️ **不可仅依赖 tracing filter**。
⚠️ 若原版没有审计，应标记为**复刻新增的安全强化**，而非原版对等功能。

### 3.5 遥测失败本身必须可观测

collector 未启动 / 队列接近上限 / 导出连续失败 / 磁盘写入被拒
→ 升级为 warning/error 并进入下次启动的 recovery report。
**不能把"没有异常"解释成"用户已上报"。**

⚠️ OTel Collector 的 file_storage WAL **只降低 collector 崩溃/重启的内存队列丢失**，
不能保证磁盘损坏、磁盘满或后端长期不可用 —— 关键事件仍需本地审计日志。

⚠️ **PII 必须在进入遥测前分类、哈希或删除**，不应依赖后端再脱敏。
**重放/崩溃/迁移失败/数据丢弃不得被采样掉。**

## 四、D 类：路径与文件系统（跨平台隐形杀手）

```bash
python3 scripts/state_migration.py --fs
```

| 项 | 要点 |
|---|---|
| 长路径 | `\\?\` **不是可选项，也不应无条件剥离**（部分旧 API/Shell 不接受 UNC） |
| 大小写 | NTFS 不敏感 / ext4 敏感 / APFS 默认不敏感 —— **不能在内存里无脑 `to_lowercase()`**（Turkish dotted i、Unicode 映射） |
| ADS | **移到 FAT32/exFAT、zip、邮件、Linux 时可能静默永久丢失** |
| 文件锁 | Windows **强制锁** vs Unix 建议锁 —— 被打开时 `rename`/`replace` 可能**失败**而非等待 |
| 原子写 | **临时文件 → fsync → rename**；⚠️ `tempfile` **不自动做最终替换** |
| 回收站 | 移动 vs 永久删除 —— **必须成为显式产品决策** |

**路径四层**：显示路径 / 系统路径 / 存储路径 / 审计路径 —— **不要混用**。
`normpath` 做词法清理（`canonicalize` 会做 I/O、解析符号链接并可能失败）；
`dunce::simplified` 处理 UNC（跨平台 no-op）。

## 五、E/F 类：插件、CLI、会话

**插件 API 对等以 ABI/能力清单为核心，不以"是否支持脚本"为核心。**
宿主 API、版本、类型、错误、生命周期、并发、取消、超时、内存/燃料、
文件系统范围、网络、剪贴板、UI、事件订阅。

已有 `wasmtime`；补充 **extism**（多语言 PDK/WASM 插件运行时，支持燃料限制与计时器）。
若原版是 Lua 而非 WASM，**extism 只能提供边界设计，不能声称脚本语言对等**。
⚠️ 没有原版 JS/Lua 接口证据时，**不应把脚本运行时包装成"像素级增强"**。

**CLI**：吸收 `clap`/`structopt`，维护 `cli-matrix.csv`
（参数、缩写、顺序、**退出码**、stdout/stderr 行、编码、彩色、`--json`、退出前 flush、超时、stdin 协议）。
**没有原版 CLI 就不应编造。**

## 六、实施顺序

1. **先冻结旧版证据**（ProcMon 4.1 / ETW / 旧 logging / dump），**再写新 schema**
2. CI 加四门：`schema-drift` · `migrator-unit` · `data-reconciliation` · `telemetry-log-parity`
3. Windows IPC 录制/重放：优先验 **Named Pipe 消息边界、单实例参数传递、Shell/Toast/拖放**
4. 路径层统一为 `normpath + dunce + 四层路径`，强制临时文件写、sync、原子 rename
5. **最后**才引入 Extism/脚本运行时，且必须先有原版插件 ABI 证据

## 七、❌ 本轮冲突项

| 做法 | 为什么冲突 |
|---|---|
| **迁移失败就重置用户数据** | 违反不可逆状态保真 |
| **未知字段忽略** | 正是 `clusters` 事故的直接形式 |
| **单实例一个全局 mutex** | 忽略会话与权限上下文 |
| 日志差不多就行 | 行为回归无法被测试 |
| **遥测先采再说** | 把 PII 处理推给后端 |
| **"没有异常"就代表迁移成功** | 绕过内容对账 |
| 本地缓存可任意删 | 破坏恢复 |
| 默认启用脚本运行时 | 扩大攻击面 |
| 相似度阈值当"通过" | 掩埋真实差异 |
| 相似度/DDL 相同即数据相同 | 转换可能已损失 |
| 无条件反向执行 DDL 回滚 | 新语义写入后重跑会破坏 |
| 动态值进事件名 | 破坏聚合 |
|Sentry 作唯一证据源 | 只能作可选导出器 |
