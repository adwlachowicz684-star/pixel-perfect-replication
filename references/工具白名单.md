# 工具白名单（每个工具的用途与禁用边界）

> **原则**：工具只产生证据，**不批准变更**。
> 任何工具的"通过"都不能替代人的审批，也不能替代台账清零。
>
> 引入任何工具前：读真实仓库与文档、确认许可与维护状态、小样本验证。
> **awesome 列表只是发现入口，不是可信依据。**

---

## 一、视觉层

| 工具 | 用途 | 在流程中的位置 | 禁用边界 |
|---|---|---|---|
| **Playwright** | 统一执行器：锁 viewport/DPR/缩放/字体/locale/timezone/theme/reduced-motion，语义等待后截图 | S7V 截图 | 不等固定时间；不用它"通过"来替代审批 |
| **pixelmatch** | 像素比较原语（抗锯齿检测、感知色差） | S7V diff 引擎 | 其 `threshold`/`includeAA` 是库参数，**不是项目阈值** |
| **Loki** | Storybook 组件级视觉回归 | S7V 组件隔离 | 不覆盖原生窗口、系统对话框、打印预览 |
| **reg-suit** | 历史报告与跨构建对比 | S7V 历史 | 不能替代逐张审批 |
| Argos / Chromatic / Happo | 多人审查、多浏览器、CI | 可选（SaaS） | 注意隐私、留存、上传范围治理；**"无差异"不等于跨平台证据** |
| Resemble.js | 图像分析 | 辅助 | — |

## 二、代码查询与改写层

| 工具 | 用途 | 位置 | 禁用边界 |
|---|---|---|---|
| **tree-sitter** | 通用解析，判断"机器能否读懂" | S2M L1 | 解析失败不许自动关闭 unknown |
| **ast-grep** | 精确 AST 查询（首选） | S2M L2 | 语言支持以官方清单为准，**不许假设 C# 支持** |
| **comby** | 跨语言结构搜索替换（兜底） | S2M L3 | 只算结构线索；**禁止裸 `-i` 全仓替换** |
| **jscodeshift / recast** | TS/TSX 保守批量重写 | S2M L4 | 白名单目录、dry-run、正反 fixture；**禁止 `**` 全仓** |
| Semgrep（CE） | 模式与 BUG 查询 | S2B/S5 辅助审计 | CE 无完整跨文件数据流，**不许声称完成全仓数据流分析** |
| CodeQL / Sourcegraph | 深层语义 / 跨仓搜索 | 可选 | 输出候选，最终仍要入台账 |

## 三、契约层

| 工具 | 用途 | 位置 | 禁用边界 |
|---|---|---|---|
| **Specmatic** | 用 OpenAPI 作契约测试，验证目标端 provider 符合性 | S4 契约门禁 | 不许从零编新 schema 当作原端契约 |
| **oasdiff** | API 变更的 breaking 判定（严重度/路径/行号/审查动作） | S4 兼容性 | PR 出现 breaking 必须显式 accept/reject |
| **Buf** | Protobuf breaking 检查（FILE/PACKAGE/WIRE_JSON/WIRE 四级） | S4（有 proto 时） | 没有 protobuf 就**不要为用它引入中间格式** |
| **Pact** | consumer-driven contract（前端录制期望 → provider 验证） | S4 | 与目标端自洽不是一回事 |
| OpenFeature / Unleash / Flagsmith / GrowthBook | feature flag 与灰度 | S6 回滚 | flag 必须关联功能卡、契约、回滚步骤、**过期日期与删除任务** |

## 四、等价性证据层

| 工具 | 用途 | 位置 | 禁用边界 |
|---|---|---|---|
| **insta**（Rust）/ **snapbox** / **ApprovalTests** | 快照与审批测试 | S7 golden | 禁止手编 golden；**禁止 bulk re-record** |
| **fast-check**（TS）/ **proptest**（Rust）/ **Hypothesis**（Py） | 属性测试（不变量） | S7 等价性 | 不许用"新旧必须完全相同"掩盖 S5 的择优决定 |
| **schemathesis** | 基于 OpenAPI 自动生成 API 测试 | S7 | — |
| StrykerJS / mutmut / cargo-mutants | mutation 审计（测试是否真能发现破坏） | S7 门禁质量审计 | **不把工具默认分数直接设成 G 门禁**；关键包存活数=0 |

## 五、考古权重层（只决定顺序，不决定完整性）

| 工具 | 用途 | 禁用边界 |
|---|---|---|
| CodeScene（行为代码分析） | 高频变更、跨团队修改、高缺陷倾向 → **决定挖掘顺序** | ⚠️ 只进 `考古权重`，**不进 `completeness`** |
| Code Maat / hercules / git-of-theseus | 变更耦合、代码年龄、留存分析 | **低热度旧模块不得自动判定"无需迁移"** |

> **旧功能不存在就是不存在，任何热度模型都救不回来。**

## 五·补：⚠️ 工具身份必须验证（实证陷阱）

**`which sg` 会命中 Unix 的 `sg`（set group ID）命令** ——
它可执行，但没有 `scan` 子命令，会让查询**永远 0 命中却显示"成功"**。

这是"假绿灯"的典型形态。**只检查"命令存在"是不够的**，必须验证工具身份：

```python
# ✅ 双重校验：--version 特征 + 子命令可用
blob = run([bin, "--version"]).stdout.lower()
if "ast-grep" not in blob:  return False      # 不是 ast-grep
if run([bin, "scan", "--help"]).returncode != 0: return False
```

本 Skill 的 `scripts/ast_query.py` 已实现该校验；
工具不可用时**如实降级并标 `confidence=low`**，绝不静默跳过。

## 六、明确不引入

| 工具/做法 | 理由 |
|---|---|
| 自动 approve baseline 的任何平台默认配置 | 把复刻目标改成"让新实现通过" |
| 随机快照测试 | 不稳定 = 人人都在重录 = 门禁失效 |
| 为使用某工具而引入中间格式（如强上 protobuf） | 为工具改架构，本末倒置 |
| OpenRewrite（本例 WPF→Tauri+React） | 其 recipe 体系面向 JVM；只在目标端恰为 Java/JVM 时借鉴其"配方组合"思想 |

## 七、引入新工具的检查清单

- [ ] 仓库真实存在且持续维护？
- [ ] 许可允许吸收？
- [ ] 小样本验证过（能复现其 README 主张）？
- [ ] 明确它在流程中的**证据角色**（不是"测试类别"）？
- [ ] 写清了**禁用边界**？
- [ ] 它的"通过"是否会被误当成审批？（是 → 加门禁约束）
