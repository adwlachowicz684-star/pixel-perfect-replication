# ⚠️ _inactive · 未启用区

本目录**当前不参与主流程**，内容是草案与预留位。

| 子目录 | 内容 | 状态 |
|---|---|---|
| `agents/` | 多 agent 分工的角色卡草案 | 草案，未启用 |
| `rules/` | 项目级硬规则草案（对应 AGENTS.md / CLAUDE.md / .cursorrules 分层） | 草案，未启用 |

## 为什么不放在主流程里

1. **主流程是单人也能跑通的**：`flow/S1-S7` 不依赖任何 agent 框架或规则文件注入。
2. **多 agent 不天然更准**：无边界的并行只会复制错误。
   只有隔离、结构化产物、锁、独立审查才提高可靠性——这些机制尚未在本项目验证。
3. **规则文件过长会失效**：超约 200 行会消耗更多上下文并可能降低遵守度；
   不同规则文件对同一行为给出冲突指令时，模型可能任意选择。

## 启用条件（满足后才从 _inactive 移出）

- [ ] 已确认所用工具链真的会加载这些文件（AGENTS.md / CLAUDE.md / .cursor/rules/*.mdc）
- [ ] 角色之间已完成**一次真实的文件交接**（manifest → evidence → contract → plan → verify → audit）
- [ ] 角色卡长期控制在 ~200 行以内，且与 `flow/` 阶段卡无冲突表述
- [ ] 规则文件互相之间做过冲突检查

## 通用原则（若启用）

- **交接物必须是文件**，不能把"总结"当真相。摘要适合给人看，不适合作为下一阶段唯一输入。
- **一次只有一个实现者**，释放锁后才写 handoff。
- **审查对象优先是 diff + 契约 + golden diff**，而不是"请检查实现质量"。
- **角色间传递明确问题集**，不是无限自由。
