# 01 · 穷尽挖掘：逐文件、逐功能、逐行

> **目标**：把旧实现里的**每一个可感知细节**都清出来，编号入账，一条不落。
>
> **立场**：本文件不讲"什么时候可以收工"。讲"**怎么保证没有遗漏**"。
> 挖掘的推进方式是 `文件 × 层 × 切角` 三重循环，任一维度没走完就继续走；
> 产出下降只是"这个切角榨干了"的信号，换一个切角继续。

---

# 第一部分 · 挖掘坐标系

## 一、六个信息层（纵向）

同样一份代码，从不同层次读，得到的信息完全不同。

| 层 | 载体 | 能挖到什么 | 本例产出 |
|---|---|---|---|
| **L1 声明层** | 命令注册表 / API 清单 / 路由表 / 事件表 | 模块级功能 | 68 |
| **L2 界面与资产层** | UI 文案、样式资源、图标/字体/颜色常量、动效时长、模板与触发器 | 交互入口 + 视觉像素 | +32 |
| **L3 逻辑层** | 方法体、`///` 文档注释 | 功能说明 | +30 |
| **L4 意图层** | **`//` 行内注释** | **真 bug 级细节、踩坑记录** | **+90** |
| **L5 实现层** | 系统调用 / 编码 / 序列化 / 第三方库用法 | **"到底生不生效"** | +51 |
| **L6 运行与环境层** | 构建脚本、部署约定、依赖版本、权限、注册表、环境变量 | 跑不起来就全白做 | （含在手法 11） |

## 二、五个横向维度（可单独整扫的一类）

不是层，是可以横跨所有文件单独扫的一整类：

| 维度 | 载体 | 为什么必须单独扫 |
|---|---|---|
| **数据层** | config 字段、真实数据文件 | **记不住的功能一定不存在**；读不出的字段迁移时会被静默丢弃 |
| **并发层** | 锁、去抖、重入、抑制、传输层 | 功能测试测不出的问题 |
| **文档层** | 修复记录、方案定稿、README、子目录 README | **原作者亲自记录的踩坑清单** |
| **整合层** | 重复实现、命名分歧、可统一的管理点 | 决定新版该怎么组织（见 02） |
| **时序与状态层** | 定时器、缓存失效、初始化顺序、状态机、退出兜底 | "顺序错了才出事"的那一类 bug |

## 三、九种切角（横向）⭐ 本 Skill 的核心机制

**同一层、同一批文件，换一个切角就能再挖出一批。** 这是"能深挖就深挖"的具体操作方式。

| # | 切角 | 每份文件都要问的问题 | 本例实证 |
|---|---|---|---|
| **A** | **正向** | 这里有什么功能？清单上记了吗？ | 基础产出 |
| **B** | **反向** | 当前版有而原版没有的？（对照着挖） | 12 项勿删增强项 |
| **C** | **边界** | 空值 / 超长 / 极端值 / 中文路径 / 路径含空格 / 单元素 / 首尾元素 会怎样？ | 高 DPI、8.3 短名 |
| **D** | **异常** | 失败 / 中断 / 重入 / 断电 / 鼠标捕获丢失 / 异常退出 会怎样？ | 退出无兜底落盘、高亮残留屏幕 |
| **E** | **横向一致性** | 同名功能在不同文件行为一致吗？ | 名称校验 3 处不一致 → 真 bug |
| **F** | **时序** | 先后顺序、延迟、防抖、定时器、谁先谁后？ | 连锁发送 400ms 防抖 |
| **G** | **权限与平台** | 平台 API、权限、编码、多进程？ | UTF-16 vs UTF-8、`+h` 让文件夹消失 |
| **H** | **数据往返** | 读 → 改 → 写 → 再读，一致吗？会被覆盖吗？ | `clusters` 静默丢弃并永久删除 |
| **I** | **可见性** | 这个功能有 UI 入口吗？有文档吗？有 config 字段吗？ | 三种"看不见的功能"（见下） |

## 四、挖掘循环

```text
for 文件档位 in [大文件, 中上, 中等, 小文件]:        # 每档都要走完，不许跳档
    for 文件 in 该档未清零文件:
        粗读 → 精读 → 复查（行级归类）
        for 层 in [L1..L6]:
            for 切角 in [A..I]:
                挖、编号入账、同步记性质判定（见 02）
        更新台账：产出项数 / 疑问行 / 状态
```

**卡住时的排查顺序**（不要停，往下走）：
1. 这个层还有哪个**切角**没走？→ 换切角
2. 这个文件的哪一层还没碰？→ 换层
3. 这个**档位**里还有哪个文件没精读？→ 换文件
4. 全部档位都走完了？→ 进入**复查轮**：逐行归类，把疑问清零
5. 疑问清零且复查产出为 0？→ 这一档才算干净

> **同层的第三遍、第四遍不是浪费** —— 前提是你换了切角。
> 真正浪费的是用同一个角度反复扫同一批文件。

# 第二部分 · 逐文件台账（穷尽的主判据）

## 一、为什么要建台账

"感觉挖得差不多了"是最不可靠的判据。台账把"挖过没有"变成可查询的事实。

**踩过的坑**：按行数倒序选文件（`sort -rn | head -50`），
结果所有 100-140 行的文件**从未被打开过**。后来专攻这一档，**单轮 +74 项**。

## 二、台账字段

每个文件一张卡：

```
路径 | 行数 | 档位 | 粗读 | 精读 | 复查 | 产出项数 | 疑问行 | 状态
```

**状态机**：`未读 → 粗读 → 精读 → 复查 → 清零`
只有 `清零` 才算完成，`精读` 不算。

## 三、档位划分（不许跳档）

```bash
find src -type f \( -name "*.cs" -o -name "*.xaml" \) | xargs wc -l | sort -rn
```

| 档位 | 行数 | 特点 | 注意事项 |
|---|---|---|---|
| 大文件 | > 500 | 大量样板（属性、事件绑定） | 第一遍扫，但别只扫它 |
| 中上 | 150-500 | 混合 | 容易漏 |
| **中等** | **60-150** | **几乎每行都是实质逻辑** | **最大盲区，必须整档走完** |
| 小文件 | ≤ 60 | 常量表 / 清单 / 枚举，密度极高 | 直接 `cat`，信息密度最高 |

**为什么中等文件最肥**：`FolderIconService` 565 行塞了 62 条行内注释；
而 100-140 行这一档，几乎每行都是实质逻辑，没有一行样板。

## 四、台账脚本

```bash
# 1. 全量入账
find src -type f | sort > all_files.txt
touch opened_files.txt

# 2. 每轮 diff：还没碰过的文件
comm -23 all_files.txt <(sort opened_files.txt)

# 3. 按档位列出未读文件（逐档清零，不许跳档）
while read -r n f; do
  [ "$n" -gt 60 ] && [ "$n" -le 150 ] && echo "$n $f"
done < <(xargs wc -l < <(comm -23 all_files.txt <(sort opened_files.txt)))
```

```python
# 台账状态统计：目标是 清零率 100%
import re, collections
rows = [l.split('|') for l in open('台账.md', encoding='utf-8') if l.strip().startswith('|')]
stat = collections.Counter(r[-2].strip() for r in rows if len(r) > 5)
print("总计:", sum(stat.values()), "| 清零:", stat.get('清零', 0))
print("未清零文件:", [r[1].strip() for r in rows if len(r) > 5 and r[-2].strip() != '清零'])
```

# 第三部分 · 行级归类（复查轮）

**精读一遍远远不够。** 复查轮要回答一个极端问题：
**这个文件的每一行，我都能解释它是干什么的吗？**

把每一行归到四类：

| 类别 | 含义 | 处理 |
|---|---|---|
| **功能** | 有实际行为，已编号入账 | 完成 |
| **样板** | 属性定义 / 事件绑定 / 样板代码 | 无需入账，但要能确认它确实是样板 |
| **死代码** | 定义了没引用 / 引用了没定义 | 记入清单（可能是忘接上的功能） |
| **疑问** | 看不懂 / 不确定作用 | **必须清零**：要么查清入账，要么立项跟踪 |

## 行级复查的实际做法

```python
# 1. 抽掉纯样板块后，看剩下的"实质行"是否都能对上清单条目
import re
lines = open('X.cs', encoding='utf-8', errors='replace').read().split('\n')
substantive = []
for i, l in enumerate(lines):
    s = l.strip()
    if not s or s.startswith('//') or s.startswith('///'): continue
    if re.match(r'^(public|private|internal)\s+(static\s+)?(readonly\s+)?\w+\s+\w+\s*\{\s*get;\s*set;\s*\}', s): continue
    if re.match(r'^(using|import)\s', s): continue
    if s in ('{', '}', '});', ');'): continue
    substantive.append((i + 1, s))
print(f"实质行 {len(substantive)} / 总行 {len(lines)}")
```

```text
2. 对每一条实质行问：清单里有对应条目吗？
   没有 → 是新功能（补编号）还是疑问（立项清零）
```

**本例实证**：交互系统原本只记了 8 个条目，行级复查 + 交互切角通读后，
发现它是 **35 个子机制**协同的一整套系统，单轮 +83 项。

# 第四部分 · 逐功能卡片（像素级的载体）

**每一个功能点都要填这张卡。** 字段没填满 = 这条没挖完。
这是"像素级"落到纸面上的地方，也是后面 03 写方案、04 做验收的唯一依据。

```text
【编号】#101
【名称】跨栏拖到空白 = 换栏移动
【位置】原版 ResolveLinkDrop() in DragService.cs
【触发】拖起卡片 → 拖到另一栏的空白区域 → 松手
【前置】源卡片非锁定；目标栏存在 activeTab
【正常流】命中卡片 = 建链；没命中 = 跨列移动
【边界】拖到自身位置 / 拖到栏内最后一个元素之后 / 目标栏为空
【异常】鼠标捕获丢失 → 高亮与插入条残留屏幕（需显式清理）
【视觉像素】插入条位置、高亮样式、动画时长
【文案像素】原版 toast 文案原文
【数据像素】涉及字段、写回时机、是否整份覆盖
【时序】落点处理是否触发 UI 重排 → 必须先置空再处理，否则重入
【并发】是否需要锁 / 防抖 / 重入保护
【平台依赖】无（纯逻辑）
【性质判定】设计意图 —— 必须补，照着语义做（见 02）
【新版方案】onCrossDrop 里 target 为 null 时调 moveCardAcross
【验证方式】tsc 0 错误；拖到空白后日志显示"已转为X"
【风险】换栏可能触发物理搬家，失败时后端整体中止
```

**关键字段说明**：

- **【性质判定】**：设计意图 / 技术权宜 / 平台限制 / 历史债 / 优秀实践 —— 决定新版是照做还是换掉（见 02 第二节）
- **【边界】【异常】**：最容易空着的两栏，也最容易出事
- **【验证方式】**：写不出验证方式 = 这条还没想清楚，不许进批次

# 第五部分 · 挖掘手法 1-16

> 前 14 个手法是实证过的产出路径，后 2 个是为"像素级"补的。
> 每个手法都给出"换切角继续深挖"的方向。

## 手法 1 · 声明层：命令 / API 清单差集

```python
re.findall(r'case\s+"(\w+)"', t)          # 命令分发（C#/TS）
re.findall(r'pub fn (\w+)', t)            # Rust 命令
re.findall(r'@tauri::command', t)
```

**局限**：清单上没有的功能会全漏。**继续深挖的方向**：
- 切角 B（反向）：两边双向差集，找改名 / 合并 / 拆分
- 切角 I（可见性）：清单上没有但真实存在的入口 → 独立 Dialog / 小 Service（类型 B 功能）

## 手法 2 · 界面与资产层：文案差集

界面上有的东西必然有文案，藏不住。

```python
re.findall(r'(Content|Text|Header|ToolTip|Watermark|Placeholder)="([^"]*[\u4e00-\u9fa5][^"]*)"', t)
```

**用子串双向匹配**（不是精确相等），否则漏掉一半：

```python
missing = [a for a in old_texts if not any(a in b or b in a for b in new_texts)]
```

**继续深挖的方向**：
- 切角 C：占位符 / 空状态 / 超长文案截断
- 切角 E：同一功能在不同页面的文案是否一致（不一致往往意味着两套实现）

## 手法 3 · 逻辑层：方法体精读（带前驱注释）

```python
for i, l in enumerate(lines):
    m = re.match(r'\s{4,}(?:private|public)\s+[\w<>\[\], ?\.]+\s+(\w+)\s*\(', l)
    if not m: continue
    zs = []
    j = i - 1
    while j >= 0 and j > i - 10:
        s = lines[j].strip()
        if s.startswith('///'): zs.insert(0, re.sub(r'^///\s*', '', s))
        elif s == '' or s.startswith('['): pass
        elif s.startswith('}'): break
        j -= 1
```

## 手法 4 · 意图层：行内注释全量提取 ⭐ 最高产

**`//` 比 `///` 值钱十倍**：

- `///` 回答：**"这个函数是干什么的"**
- `//` 回答：**"为什么必须这么写"** —— 踩过的坑、隐含约束、数据风险，全在这里

**本例实证**：把 `///` 全量提取换成 `//` 全量提取，**单轮从 +30 跳到 +90**。

```bash
python3 -c "
import re
lines = open('X.cs', encoding='utf-8', errors='replace').read().split('\n')
cur = None
for i, l in enumerate(lines):
    m = re.match(r'\s{4,}(?:private|public|internal)\s+(?:static\s+)?[\w<>\[\], ?\.]+\s+(\w+)\s*\(', l)
    if m: cur = m.group(1)
    if re.search(r'//\s*[\u4e00-\u9fa5]', l):
        print(f'L{i+1} [{cur}]', re.sub(r'^\s*//\s*', '', l.strip()))
"
```

**继续深挖的方向**：从负面教训词汇里挖机制
```
否则 | 会 | 可能 | 需 | 必须 | 绝不能 | 警惕 | 注意 | 坑 | 错 | 误
残留 | 丢失 | 死锁 | 振荡 | 黑屏 | 穿透 | 错位
```

## 手法 5 · 清单层：短清单文件

直接 `cat` 的短文件，信息密度极高：快捷键目录表（本例 22 条完整键位）、
使用说明 / TIPS 面板、参数 schema、数据模型定义。

**陷阱**：使用说明可能是**旧版遗留**，描述的功能当前版本根本没有。
**必须逐条 grep 代码验证再计入**（本例 TipsPanel 描述 3 个不存在的功能，已作废并记录理由）。

## 手法 6 · 实现层：样式资源 + 两边对照

```python
re.findall(r'x:Key="(\w+)"', t)     # 样式资源键，再往上回溯 <!-- 注释 -->
```

对照两边实现，问"**这个功能真的生效吗**"：
编码对不对（UTF-16LE vs UTF-8）、有没有通知系统（`SHChangeNotify`）、
边界处理（路径含空格、中文路径）。

**本例**：图标实现挖出 24 项，其中 3 项是真 bug 级——**改图标可能根本不生效**。

## 手法 7 · 反向层：双向 comm

**易犯的错**：默认"当前版是原版的子集"。实际常是**改名 / 合并 / 拆分**。

```bash
comm -23 <(sort old.txt) <(sort new.txt)   # 原版有、当前无
comm -13 <(sort old.txt) <(sort new.txt)   # 当前有、原版无 ← 别漏
```

**本例实证**：一直以为"缺 9 个 MCP 工具"，双向对照才发现：
- 被**合并**：`list_agents`+`list_skills` → `scan_content`
- **等价改名**：`lock_set`→`set_lock`、`backup_now`→`backup`
- 当前**多出**：`add_card`、`set_tag_color`、`read_file`
- 真缺失：只有 3 个

**由此暴露真实风险**：AI 客户端按原版 README 的工具名调用会**全部失败**。

## 手法 8 · 文档层：修复记录 = 踩坑清单 ⭐

`dev-notes/修复记录.md`、`方案定稿.md`、子目录 README 是**原作者亲自记录的踩坑清单**。
对复刻而言是**最高价值的一类信息**——告诉你哪些地方一定会出 bug。

```bash
find . -name "*.md" | xargs grep -l "修复\|方案\|记录\|ERRATA\|rules\|注意事项"
```

**本例**：A1-A9（P0 阻断级）、B1-B15（P1 严重）、C1-C17、D3-D9、V10。
对照后确认当前缺失 5 项：
- A2 图片未真正转 ICO → 改图标可能不生效
- B3 未处理高 DPI → 截图错位
- C12 退出无兜底落盘 → 异常退出丢改动 `[险]`
- C3/V3/D9 无异步刷新管线 + 无重入保护 → 卡片多时卡界面

## 手法 9 · 数据层：config 字段双向差集 + 真实数据文件 ⭐

**记不住的功能，一定不存在**（除非硬编码）。

```python
# 1. 原版：JsonPropertyName 映射（实际 JSON 键名）
names = re.findall(r'\[JsonPropertyName\("([^"]+)"\)\]', t)

# 2. 当前：按大括号配对截取结构体（⚠️ 不能用 grep 单行，会漏掉一半）
i = t.find('pub struct FpxConfig {')
depth, j = 0, i
while j < len(t):
    if t[j] == '{': depth += 1
    elif t[j] == '}':
        depth -= 1
        if depth == 0: break
    j += 1
fields = re.findall(r'pub\s+(\w+)\s*:', t[i:j])

# 3. 归一化命名后双向差集
def to_snake(s): return re.sub(r'(?<!^)(?=[A-Z])', '_', s).lower()
```

**踩过的坑**：用 `grep -oP "pub \w+"` 只抓到 25 个，**实际 39 个**
（带 `Option<...>` 的字段抓不全）。必须按大括号配对截取。

**语义合并检测**（比字段缺失更隐蔽）：
字段数对得上 ≠ 语义等价。本例原版有**两层**锁定
（`locked` 账面固定 / `folderLock.items[]` 系统 ACL），
当前合并成一层 `locks` → **"仅账面固定"这一档消失**。

### 手法 9b · 读真实数据文件（不是读代码）⭐

**代码只读它认识的部分。读不出的差异，代码里永远看不见。**

```bash
python3 -c "
import json
d = json.load(open('数据/link-record.json'))
print('顶层键:', list(d.keys()))
print('首条字段:', list(d['links'][0].keys()))
"
```

**本例实证**：原版真实数据有 `clusters` + 每条的 `cluster` 字段，
当前 `LinkRow` 完全没有，全库 grep 零命中 →
**用户拿原版数据迁移时，`clusters` 被静默丢弃、写回时永久删除**。

这个差异读原版代码看不出、读当前代码也看不出，**只有打开真实数据文件才会暴露**。

## 手法 10 · 并发层：模式全库扫描 ⭐

```python
pat = {
 'lock 语句':         r'\block\s*\(',
 'Monitor/Semaphore':  r'\b(Monitor|Semaphore\w*|Mutex|ReaderWriterLock)',
 '跨进程锁':           r'Global\\\\|@"Global|跨进程',
 'Interlocked':        r'Interlocked\.',
 'volatile':           r'\bvolatile\b',
 '重入保护':           r'重入|_running|_inProgress|_busy|IsRefreshing',
 '防抖':               r'防抖|debounce|Throttle',
 'Dispatcher 封送':    r'Dispatcher\.',
 'ConfigureAwait':     r'ConfigureAwait',
 'CancellationToken':  r'CancellationToken',
 '抑制/暂停':          r'Suppress|Suspend',
 '定时器':             r'DispatcherTimer|Timer\(',
 'try/finally 恢复':   r'finally',
}
```

**读法**：
- `跨进程锁` 命中 → **架构信号**：有多个进程写同一份数据
- `Interlocked`/`volatile` 零命中 → **负面信息也有价值**（别照搬成无锁实现）
- `try/finally` 命中 23 文件 → **"临时摘锁→执行→finally 恢复"是核心模式**

**临时摘锁 / 抑制模式，必须问三个问题**：
1. 状态是在窗口**外**读的吗？（窗口内读出来是假的）
2. 有没有 `finally`？（没有的话异常时锁摘不回来）
3. 可重入吗？（嵌套调用会不会提前把锁戴上）

**本例**：搬家前读 ACL 状态必须在摘锁窗口外读；
监控 `Suppress`；连锁发送 400ms 防抖。三处当前全缺。

**传输层对照**：不要假设两边进程模型相同。
本例原版 stdio、当前 HTTP over TCP → **不是缺功能，是架构选择**，
但后果很实际（原版文档的配置方式 100% 不可用）。

# 第八部分 · 编号与自检

编号固定（后续说"做第 N 项"即可，不怕对话丢失）。
**每轮交付前跑自检，口头声称的总数必须与脚本统计一致。**

```python
import re
t = open('清单.md', encoding='utf-8', errors='replace').read()
nums = [int(m.group(1)) for m in re.finditer(r'^\|\s*(\d{1,3})\s*\|', t, re.M)]
print("条目:", len(nums), "范围:", min(nums), "-", max(nums))
print("重复:", [n for n in set(nums) if nums.count(n) > 1])
print("缺号:", [n for n in range(1, max(nums)+1) if n not in nums])
```

**必须无重复、无缺号。**

**⚠️ 踩过的坑**：卷首索引里要写 `| 123 |` 而不是 `#123`，
否则编号统计脚本会把索引误当新条目（本例实测：说 662，统计出 666）。

# 第十部分 · 负面教训库（跨平台复刻必看）

这类陷阱**只在特定平台出现，但一旦出现就是致命的**。
照着功能清单做完，会发现"黑屏""点不动""错位"——**原因根本不在功能逻辑里**。

| 陷阱 | 平台 | 后果 |
|---|---|---|
| 逐像素 α 被当不透明 | Windows 分层窗口 | **渲染成整屏黑** |
| α=0 区域点击穿透 | Windows 分层窗口 | 覆盖层**完全收不到点击** |
| 模态 `Show()` 后降级 | WPF | `DialogResult` 抛异常 |
| 无边框最大化向内缩进 | WPF | 左/顶**露出一条桌面** |
| 无边框最大化盖住任务栏 | Windows | 需 `WM_GETMINMAXINFO` 钳制 |
| 高 DPI 未处理 | 全部 | 截图/取色**错位** |
| 管道缓冲区填满死锁 | 全部 | 需"先启动异步读再等退出" |
| 双端滚动同步振荡 | 全部 | 第二次 ScrollChanged 触发反向对齐 |
| 表格列信息不可靠 | Markdig | `ColumnIndex` 恒 -1 + 幻影列 → **首列丢失** |
| 8.3 短名不匹配 | Windows | 输入需先展开完整路径再匹配 |
| 无 BOM UTF-8 被读成乱码 | 全部 | Unicode 解码几乎不抛异常 → 回退永不触发 → **乱码写回成脏数据** |
| `+h` 会让文件夹被隐藏 | Windows | 设置图标只加 `+s` 不加 `+h` |
| 图片未真正转 ICO | 全部 | 改图标可能**根本不生效**（原版 A2） |

**原版实证注释（可直接作为检查项）**：
```
不设 Handled：普通单击仍走 Button Click
不能用 Hide()/Show()——模态对话框 Show 后会被降级（E006）
纯 Transparent（α=0）会整体点击穿透，故底刷用 α=1 近不可见黑
必须分层真透明——否则被当不透明渲染成整屏黑
EventSetter 会创建 code-behind 新实例，其 DataContext 为空（全树不可选中）
Markdig 表格 ColumnIndex 恒为 -1，还常含 1 列幻影——否则首列丢失
第二次 ScrollChanged 会逃逸触发反向对齐，两端来回微调成振荡
```

# 附录 · 十个陷阱清单（自检用）

1. **只扫命令清单** → 漏掉独立弹窗里的功能（类型 B）
2. **只按行数倒序选文件** → 漏掉中等文件整档（本例最大盲区）
3. **只提取 `///`** → 漏掉最有价值的踩坑记录（单轮相差 60 项）
4. **假设"当前是原版的子集"** → 漏掉改名 / 合并 / 反向差异
5. **只读代码不读数据** → 漏掉迁移时静默丢弃字段（类型 `[险]`）
6. **把使用说明当事实** → 可能描述旧版不存在的功能（本例 TipsPanel）
7. **grep 单行抓结构体字段** → 漏掉带泛型 / `Option` 的字段（本例 25 vs 39）
8. **复刻时对齐原版删掉增强项** → 必须维护反向清单
9. **只挖"有什么"，不挖"边界/异常"** → 功能在，但一用就出事
10. **跳过行级复查** → 交互系统这类"整套"被当成单个功能记一条
